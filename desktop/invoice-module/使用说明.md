# 自动开票台账 · 使用说明

把店铺订单整理成可直接导入开票系统的明细表。支持聚水潭 ERP、拼多多、淘宝天猫、京东、1688、抖音小店、钉钉 AI 表格的导出文件。

## 当前版本的完整操作流程（2026-10-10 更新）

1. 首次使用双击 `install.bat`，依赖安装到当前系统 Python；完成后双击 `run_gui.bat`。
2. 将同一日期范围的「订单明细 + 买家开票申请」放入 `订单投放`。正式处理前移走带“样例”的文件。
3. 在窗口点击「商品编码库」补齐真实的19位税收分类编码；点击「开票配置」确认销售方名称和实际适用税率。
4. 点击「开始处理」，打开本次「处理报告」。有异常的订单整单留在待修正明细中，不进入导入表；同批其他检查通过的订单可以导出。
5. 缺抬头税号：填写本次待补录清单的黄色列，点击「补录回写」选中该文件，再处理一次。回写按订单号保存，防止同一买家为不同单位开票时错套抬头。
6. 金额不符、缺编码、冲突申请：核实后修正源文件或映射库，再次处理。报告显示通过后，核对本次新福通申请单，在新福通导入并实际开票。
7. 实际开票成功后，准备含「平台订单号」「发票号码」两列的 Excel 或 CSV，点击「登记已开票」。合票可逐订单写同一发票号码；再次登记同一结果不会重复添加。
8. 再次处理，已登记订单应消失。对照库回写前会在 `数据/备份` 留存原文件。

程序只生成开票准备文件。真实开票系统的导入兼容性、实际开票结果需在新福通/税务局验证。默认1%来自现有配置，不代表程序已替你确认实际适用税率。

每次运行生成唯一文件名和 HTML/JSON 处理报告。`output` 中旧文件保留，务必只使用本次报告列出的文件。有异常或漏单时，即使勾选归档也保留源文件，方便修正。

环境检查：`python run.py --check`；自动任务运行：`python run.py --no-pause`。
退出码：0=处理完成且无待修正问题，2=完成检查但需要补充/修正数据，1=运行或生成失败。
回归验证：`python -m unittest discover -s tests -v`，测试使用临时目录，不修改真实开票记录。

## 零、先选一种工作模式

程序支持两条路子，处理逻辑完全一样，只是数据从哪来不同。改 `config.yaml` 里的 `mode` 一行即可切换：

```yaml
mode: auto      # 两种文件都收，自动识别（默认，先用这个）
mode: erp       # 只认聚水潭导出的数据
mode: platform  # 只认各平台后台导出的数据
```

### 模式一 · ERP 导出（推荐，最省事）

聚水潭是**聚合了你所有绑定店铺**的 ERP，所以一次导出就能覆盖全部店铺：

1. 聚水潭 → 发票管理 → **买家开票申请** → 点右上角「导出」
   → 拿到所有买家的**抬头、税号、邮箱、申请金额**
2. 聚水潭 → 销售单 → 按**同样的日期范围**导出
   → 拿到商品明细（订单号 → 商品、数量、金额）

两个文件一起丢进 `订单投放`，程序按订单号自动关联。

### 模式二 · 平台导出

不开 ERP、或部分平台没接 ERP 时：

1. 各平台后台 → 发票管理 → 点「**导出申请数据**」
   - 拼多多：订单开票 → 开票列表 → 导出
   - 京东：给买家开票 → 导出申请数据
2. 各平台 → 订单管理 → 导出订单（拿商品明细）

同样丢进 `订单投放`。

### 两种模式的区别

| | ERP 模式 | 平台模式 |
|---|---|---|
| 覆盖店铺 | **一次导出全部店铺** | 每个平台单独导 |
| 开票申请来源 | 聚水潭「买家开票申请」 | 各平台「导出申请数据」 |
| 商品明细来源 | 聚水潭销售单 | 平台订单导出 |
| 抬头税号完整度 | 高（买家申请时自己填的） | 平台之间字段有差异 |
| 文件数量 | 2 个 | 平台数 × 2 |

> 抬头和税号以**买家提交的开票申请**为准（买家自己填的最准），
> 申请单里没有的字段才回退到抬头库匹配。

## 一、窗口版（推荐日常用）· 双击 `run_gui.bat`

不想看黑框刷屏，就双击 **`run_gui.bat`**，会打开一个窗口：

![程序窗口](文档/images/程序窗口.png)

窗口上四块内容，从左到右、从上到下看：

| 位置 | 看什么 |
|---|---|
| 左上「处理步骤」 | 6 个步骤的实时状态：○ 待处理 / ◐ 进行中 / ● 已完成 / ✕ 失败 / ⊘ 已跳过，完成一条变绿 |
| 左下「本次生成」 | 这次生成了哪些文件，**点文件名就能直接打开** |
| 右侧「运行日志」 | 每一步干了什么，一行一行往下走；警告橙色、报错红色 |
| 底部 | 总进度条 + 百分比 + 用时；按钮：开始处理 / 打开输出文件夹 / 打开订单投放 / 生成测试订单 / 查看日志文件 |

**右上角可以现改**：

- **开票数据来源**：`自动识别` / `ERP 导出` / `平台导出` —— 选完**会自动写回 config.yaml**，下次打开还是这个
- **处理完归档原文件**：打勾后跑完把 `订单投放` 里的原始文件挪进 `归档/日期时间/`，适合每天固定跑一次的人

**6 个步骤分别是**：

| 步骤 | 干什么 | 出问题会怎样 |
|---|---|---|
| 1 加载配置与对照库 | 读 config.yaml、抬头库、税收编码库、已开票记录 | 库文件缺失会自动重建空表 |
| 2 扫描订单文件 | 扫 `订单投放` 里的 xlsx/xls/csv | 空文件夹会在这里失败并提示 |
| 3 解析订单与匹配抬头 | 识别来源 → 关联开票申请与订单明细 → 匹配抬头税号 | 单个文件读不了只标红，不影响其它文件 |
| 4 汇总发票 | 按「抬头 + 税号 + 店铺」分组，一组 = 一张发票 | — |
| 5 生成开票表格 | 写台账、新福通申请单、税务局表、预警表 | 某个格式生成失败只跳过它，其它照常 |
| 6 完成 | 归档原文件（如果勾了） | — |

> 每次运行都会写一份日志：`日志/运行日志_年月日_时分秒.log`
> 窗口关掉了也能从「查看日志文件」按钮或直接进 `日志` 文件夹翻。

## 二、命令行版 · 双击 `run.bat`

**第 1 步**：把平台后台或聚水潭导出的订单 Excel，丢进 `订单投放` 文件夹
（可以一次放多个文件、多个平台，程序会自动识别来源）

**第 2 步**：双击 `run.bat`

**第 3 步**：打开 `output` 文件夹里新生成的表

| 文件 | 用途 |
|---|---|
| **新福通开票申请单_*.xlsx** | ★ 贴好了官方模板，直接导入新福通统一开票 |
| `待开票台账_*.xlsx` | 主表，核对用 |
| `浙江电子税务局批量开票_*.xlsx` | 导税务局用 |
| `新福通清单导入_*.xlsx` | 备用通道（按清单导入） |
| `待补录清单_*.xlsx` | 缺抬头/税号的订单，需要你补一下 |
| `漏开票预警_*.xlsx` | **有买家申请了开票但找不到订单，会漏票，必须处理** |

**第 4 步**：开完票后，把含发票号码的结果表登记一次：
```
run.bat --mark-issued 你的开票结果表.xlsx
```
登记过的订单下次不会再出现在台账里。

### 新福通一键开票 · 具体操作

程序把检查通过的订单填入随项目保存的新福通模板（含「导入模板」「填写说明」页签和下拉校验）。真实系统版本是否接受，需先用一小批实际数据验证。操作流程：

1. 新福通 → 销项发票 → **开票申请单** → 点「**导入**」
2. 在弹窗第 1 步「选择要导入的开票申请单」里选好目标单据类型
3. 第 3 步「上传原始数据文件」→ 选择 `新福通开票申请单_日期.xlsx`
4. 点「确定」→ 数据进来后核对一遍 → **统一开票**

**分票规则**：同一个「开票单单据号」的明细会开在**同一张发票**上。
程序按「同一买家抬头 + 同一税号 + 同一店铺 + 同一发票类型」自动分组，单据号包含运行时间与流水，避免同一天多次处理重用单据号。

### 填进模板时的几个口径（已按官方说明处理好，供核对）

| 字段 | 程序的填法 | 依据 |
|---|---|---|
| 金额 | 含税金额 | 订单里的买家实付本来就是含税价 |
| 是否含税 | 全部填「是」 | 官方要求同一单据内必须一致 |
| 单价 | 含税单价 = 金额÷数量 | 输出按数量与含税金额重新计算单价 |
| 税率 | 文本，如 `1%` | 下拉只认 `0%,1%,1.5%,3%,5%,6%,9%,11%,13%,16%,17%` |
| 购买方是否为自然人 | 抬头类型含「个人」→「是」 | 自然人买家不需要税号 |
| 法人公司名称 | `config.yaml` 里的销售方名称 | **必须和新福通「法人公司」里维护的完全一致** |
| 优惠政策 | 「不使用优惠政策」 | 取下拉列表里的确切值 |
| 客户名称 | 留空 | 官方说明：不填则需填购买方信息（我们填了） |
| 开票备注 | 订单号（多个用逗号） | 方便事后对账 |

## 三、第一次使用必须先做的两件事

### 1. 填税收分类编码（不填导不进去）

打开 `数据/税收编码映射.xlsx`，给每个商品关键词填上真实的税收分类编码：

| 关键词 | 开票商品名称 | 税收分类编码 | 税率 | 单位 |
|---|---|---|---|---|
| 锁芯 | （留空=用原商品名）| **← 必填** | （留空）| 个 |
| 螺丝 | | **← 必填** | （留空）| 套 |

- 编码从哪来：新福通 → 商品管理 / 商品编码，查到本店商品对应的编码后复制过来
- **是 19 位**（税局规定的税收分类编码）。如果你系统里存的是短的（比如 `108041401`），
  按官方说明不足 19 位系统会自动补 0，也可以直接照抄
- **税率列留空即可**，留空就跟随 `config.yaml` 里的 `default_rate`；
  只有某个商品要单独用别的税率时才填
- **填一次永久生效**，以后全靠关键词自动匹配

### 2. 确认税率

`config.yaml` 里 `default_rate` 已经按你的情况设成 **`0.01`（1%）**（从官方模板的示例数据看出来的）。
如果你实际不是 1%，改成对应值，可填：
`0` / `0.01` / `0.015` / `0.03` / `0.05` / `0.06` / `0.09` / `0.11` / `0.13` / `0.16` / `0.17`

### 3. 核对销售方名称

`config.yaml` 里 `seller.name` 现在是「**诸暨五成电子商务商行（个体工商户）**」。
这必须和新福通里「法人公司」维护的名称**一字不差**，否则导入会报错。

## 四、抬头/税号不用每次都填

程序会按顺序自动匹配：平台订单号 → 买家账号 → 手机号 → 收货人。

匹配不到的会进 `待补录清单`，你在黄色列补填抬头和税号后：
```
run.bat --import-missing
```
补的内容写进 `数据/发票抬头库.xlsx`，按订单号匹配。未来订单优先使用买家新提交的申请信息；已有手工维护的买家账号映射仍可作为回退。

## 七、两条自动预警（很重要，别忽略）

### 1. 金额校验 —— 防止开错金额

买家的开票申请金额，和订单明细算出来的合计，程序会逐单比对：

- 一致 → 台账「金额校验」列显示 `一致`
- 不一致 → 显示 `申请30.00 / 明细19.90`，**该行整行标黄、「金额校验」列标红加粗**

对不上的常见原因：订单有优惠券、运费、部分退款、或者买家申请后又改了订单。
**这类必须人工确认按哪个金额开**，程序不会替你决定。

### 2. 漏开票预警 —— 防止漏票

买家明明提交了开票申请，但程序在订单明细里找不到对应订单，会单独出一张
`漏开票预警_*.xlsx`。原因通常是：

- 订单明细导出时**日期范围没覆盖到**
- 那个店铺的销售单**还没导出**
- 选了 ERP 模式，但部分订单不在 ERP 里

**看到预警表就要去补导订单明细**，否则这些票会被漏掉，买家会来催。

## 八、如果表里的字段对不上

各家导出的表头不一样，程序靠「字段名关键词」去认。如果你的导出里有列没被识别，
打开 `src/fieldmap.py`，在对应平台的别名列表里加一个词就行，不用改逻辑。

例：你的表头叫「实付款」，在 `COMMON_ALIASES["amount"]` 里加上 `"实付款"` 即可。

---

## 九、内置的开票规则（可在 config.yaml 改）

- 已取消 / 未付款 / 交易关闭的订单自动跳过
- 商品名含「赠品」「补差价」的行自动跳过
- 同一抬头 + 同一税号 + 同一店铺 + 同一发票类型的订单合并成一张票；关闭合票后按订单分票
- 同一订单同时出现在 ERP 和平台导出时，保留信息最完整的一份，不会重复开票
- 单张发票超过 100 行明细自动拆票
