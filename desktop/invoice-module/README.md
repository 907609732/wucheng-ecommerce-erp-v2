# 电商自动开票助手

Windows 本地开票工作台。只做申请采集、校验、模板准备、执行任务、结果登记与附件归档，不做 ERP、库存、物流。

## 运行

- 源码：安装 Python 3.12，在项目目录执行 `python -m pip install -r requirements.txt`，双击“启动新版开票助手.bat”。依赖安装在本机现有 Python，不建立项目虚拟环境。
- EXE：打开 release 下最新 pyinstaller 目录中的 InvoiceAssistant 文件夹，双击 InvoiceAssistant.exe。必须保留整个文件夹及 `_internal`，不能只复制 EXE。
- 隔离演示：`python assistant.py --demo`，或 `InvoiceAssistant.exe --demo`。自动建立临时数据目录、生成模拟单据并完成 MockProvider 流程；不会加入生产库、联网开票或登记真实发票号码。
- 环境检查：`python assistant.py --check`。本地 Chrome/Edge 启动下载通过不代表真实后台采集已通过。

## 正常业务

### 每日开票巡检（20:00）

- 窗口下方增加“运行日志”：每秒刷新连接、识别账号、查询两类申请和核对范围的阶段。失败会自动展开，并保留时间、错误码、任务编号及安全的代码位置；任务编号可用于串起同一次检查。关闭重开后仍可查阅，旧版历史记录保留但不补造旧版详细日志。
- 勾选“只看报错”或输入关键词筛选。点击“复制诊断日志”可粘贴给技术支持，“导出诊断日志”会生成独立 TXT（不覆盖旧文件，不自动上传）。界面显示最近 500 条，复制/导出最多最近 2000 条符合筛选的日志。本地日志数据库为巡检数据目录中的 `runtime-logs.sqlite3`，导出文件在 `diagnostics` 子目录。
- 日志只记录业务阶段、数量、范围、错误码、异常类型与代码位置；不记录原始页面、子进程输出、异常原文、密码、验证码、买家抬头和税号。历史检查表仍按原有规则保存结果，与诊断日志分开。

- 双击 `打开每日开票巡检.bat`，先在已登录千牛切到目标店铺，再“① 连接已登录千牛 → ② 立即检查”。连接从客户端可见控件自动读取当前账号 ID，不需要别名或密码，不打开独立浏览器。账号 ID 与店铺 ID、销售方税号不是一回事。
- 定时任务已改为程序内部 QTimer 调度，不依赖 Codex。界面可启用/暂停、修改时间并保存，默认每天 20:00（北京时间）。旧 Codex 任务 ID `20` 已暂停。
- 需要本程序保持运行、电脑开机联网、桌面解锁及千牛有效登录。千牛应停在已连接的目标账号，最好保持“给买家开票”页面打开；查询期间请勿切换账号或操作筛选。关闭巡检窗口会留在托盘；托盘“退出并停止定时任务”才结束。未添加开机启动或 Windows 计划任务，退出、关机期间不会检查；当天 20:00 后重新运行或从睡眠恢复会补查一次，不补造过去日期的数据。
- 程序单实例，后台子进程通过 pywinauto/UIA 读取千牛；手动检查和每日任务共用同一采集入口。只读取绑定账号；当前账号不同、控件不唯一、范围不一致或不能证明查询刷新时，整次检查失败，不自动读取其他账号。每日调度先持久化认领，重启不会重复触发同一天。失败后不会循环重试，可人工点“立即检查”。其他店铺或平台未验收。
- 后台窗口识别：先用 Win32 枚举进程归属已核实的“千牛工作台”，包括最小化/隐藏窗口，再通过同一窗口句柄连接 UIA。多个同名窗口只按可读取的账号身份与已绑定账号匹配，不按窗口大小、前后台或第一个候选猜选；登录窗口不会盖过已经存在的工作台。唯一目标可恢复显示；所有候选均不可读、目标重复或归属不明时停止。千牛进程在后台运行不等于工作台的账号控件仍可读取，此时需从任务栏/托盘打开已登录工作台一次，不要求重新登录。实现复用 [pywinauto 窗口发现参数](https://pywinauto.readthedocs.io/en/latest/code/pywinauto.findwindows.html)。
- 连接错误分为 `CLIENT_MISSING`（无工作台）、`CLIENT_MULTIPLE`（目标仍不唯一）、`CLIENT_LOGIN`（只有登录窗口）、`CLIENT_OWNER`（程序归属无法核实）和 `CLIENT_HIDDEN`（工作台无法恢复显示）。失败数量为未知；CLI 失败返回 2，成功返回 0。新版窗口“任务结束”日志直接标明连接/检查成功或失败，退出码不再作为业务成功证明。需退出托盘中的旧巡检程序后重开，加载新的界面日志逻辑；历史记录和定时设置保留。
- 只读查询“待处理申请”和“待录入开票”，不导出、不审批、不实际开票、不上传或回传。待录入可能已线下开具，显示为“待核对申请”。
- 记录实际日期范围。未证明覆盖平台完整可查询范围时，不显示“全部无申请”；登录或查询失败记为未知而不是零。
- 记录保存在 `%LOCALAPPDATA%/WuchengInvoiceAssistant/Monitoring/invoice-monitor.sqlite3`，不改写正式开票库。
- 财务导航修复：千牛停在打单或其他页时，程序先进入“财务”，等待“给买家开票”正式链接，再核实开票页及当前账号。原生侧栏没有 UIA 控件时，复用 MIT 开源 [WinOCR](https://github.com/GitHub30/winocr) 调用 Windows 中文 OCR，只在内存识别左侧导航，并核对交易/商品/财务的排列、窗口归属及遮挡；不使用固定坐标、不保存或上传截图。组件、语言或锚点不可用时停止，并提示在千牛点击“财务”后重试。程序依赖已加入 `requirements.txt`；本机 Python 已安装 WinOCR 0.0.15，Windows 中文 OCR 可用。
- 进入财务后的开票首页可能没有 `#/invoice/apply` 后缀；只在可信域名/路径且实际存在两类发票申请标签时接受首页，默认待处理列表还须核对标签选中状态。多页面、多入口、账号改变或未知跳转仍停止。

### 五步开票流程

主界面按钮按五步摆放，顶部显示当前步骤，底部用“上一步 / 下一步”切换；切换步骤本身不会执行采集、审核或开票。

1. **首次设置**：确认销售方，点击“登录并识别店铺”，只选择平台并扫码登录；打开后台店铺信息页后自动读取店铺名称和ID，不手填。最后确认官方模板。以后通常从第 2 步开始。
2. **获取数据**：先勾选店铺，再选择输出格式，最后点击“获取待开票数据”。登录或验证码由用户完成。已有批次可直接进入检查。
3. **检查资料**：逐项补资料、核对金额与外部已开票记录，再点击“确认并审核合格申请”。异常申请仍然拦截。
4. **准备文件**：点击生成或更新本批次文件，打开文件核对，查看导入说明，在新福通或税务局实际导入并开具。
5. **登记归档**：实际开具成功后，先登记含真实发票号码的结果，再归档附件。

实际淘宝后台路径目前尚未实测接通，不能当成已经实现一键采集。步骤编号只引导操作，不代表后台已经验收或已经完成真实开票。

店铺自动识别只读取可信平台页面可见的“店铺名称 / 店铺ID”等明确标签，连续两次一致才保存；昵称、税号不能冒充店铺ID。页面没有这些字段时，请在浏览器打开店铺信息页；仍无法识别会停止并提示，不猜填。真实各平台页面尚待验收。重复店铺不自动合并，登录到不同ID时不覆盖原绑定。商家法律主体和税务资料不从店铺名称自动推断；新账号的company字段仅作平台/店铺数据隔离命名空间。

聚水潭的申请历史无法证明尚未开票，入口已暂停。其销售 Excel 仍可用作订单商品明细，与电商后台申请按平台/店铺/订单号关联；单独销售表不能生成待开票申请。异常恢复入口可以同时选择申请和明细文件，但不是日常自动采集的替代品。

空状态、待审核、退款、缺资料、金额冲突、采集不完整均不会自动放行。淘宝“待录入开票”可能已线下开具，需要逐份核对外部记录。税率和商品编码必须由用户确认，不根据商品名自动猜测。

“资料设置 → 店铺 → 更多设置 → 字段映射”可选择申请/明细文件，仅预览表头，用下拉框覆盖有变化的对应列，保存后重新采集/恢复。不会改写原Excel或历史申请。“第3步 → 确认并审核合格申请”可批量记录当前版本审核，资料修改后需重新审核；这不启用正式自动开票。绑定路径和故障导入也收在“更多设置”。

## 执行与安全

“历史记录”中可选择批次；展开“高级工具：模拟执行测试”后，可建立模拟任务、运行模拟队列、暂停/恢复/取消未提交任务。模拟成功不等于已开票，凭证保存到独立“模拟凭证”目录。

提交超时/进程中断 → 结果未知 → 先核对原结果。未知任务不能恢复、取消或直接重试；只有原通道明确证明未提交，才允许人工恢复。暂停队列不会强行中断已开始的提交。真实发票结果含单据号和发票号码，按拆票关系登记。

新福通和税务局 Provider 目前只支持模板准备。**真实提交被锁定**，即使手工修改自动执行设置也无法绕过未验收的适配器。没有批准、真实授权、文档及界面证据，不启用 RPA、不点击实际开具、不自动回传平台。

历史记录支持给已登记真实发票关联 PDF/OFD/XML/图片附件，按 SHA-256 保存，不覆盖原件。附件没有自动验真；用户需核对发票与单据的真实对应关系。截图/错误证据接口的真实自动捕获尚待 RPA 验收，不宣称已经实现。

## 本地数据与凭据

默认数据在 `%LOCALAPPDATA%/WuchengInvoiceAssistant/Runtime`；SQLite、导出、日志、归档与程序分开。凭据封装只支持 Windows Credential Manager，不回退到明文；本期没有要求输入 API 授权或保存平台密码。独立 Chrome 首次扫码后复用，登录/验证码由人完成，不复制日常 Chrome 配置。

“备份数据”生成 SQLite 一致性备份。退出后可恢复备份数据库；同时保留导出与归档文件。不要删除旧版目录和“重构前完整备份.zip”。旧版启动脚本仍保留，但其聚水潭申请历史口径已过时，不建议用于正式待开票判定。

## 开发与验收

`python -m unittest discover -s tests -v`；`python build_windows.py` 使用 PyInstaller 打包。早期 `build_v2.py` 是保留的 Qt/Nuitka 旧构建入口，现用新入口。

源码没有复制所参考第三方项目代码，也没有把第三方发票云 API 设为必需组件。开源调查、正式能力边界和未验收项见 `文档/开源调查与能力清单.md`；各测试结果见 `文档/测试报告.md`。
