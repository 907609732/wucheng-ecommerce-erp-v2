# 采购数据采集（功能04）

Chrome启动时请求最大化，并使用Playwright的`viewport: null`取消固定1360×900网页视口，网页随实际窗口缩放。依据：[官方视口配置](https://playwright.dev/docs/api/class-browsertype#browser-type-launch-persistent-context-option-viewport)。账号识别使用随窗口调整的顶部范围，不再限制横坐标900px；支持非链接的span/strong等元素与开放Shadow DOM，并保持顶栏上下文检查，避免把供应商账号当成买家账号。日志会输出网页尺寸、控件/候选数量、顶栏/订单页/退出入口是否可见，不输出账号正文。明确的登录页/表单才归为未登录；已看到订单页或退出入口但识别失败归为需排查，安全验证单独提示，未知状态不擅自判定未登录。

采集页内提供与云仓一致风格的运行日志：时间、步骤、错误、等待心跳（每10秒）、复制日志和打开日志目录。点击按钮后的参数错误也立即显示。后端日志最近300条可回看，同时按天保存到workspace/purchase-auto/logs/purchase-YYYY-MM-DD.jsonl并汇入软件运行日志；重启恢复最近日志。不记录Cookie、订单正文或浏览器控制台内容，错误中的网址与常见凭据字段脱敏。日志只能定位有记录的操作，旧版本未记录的卡点无法追溯。

1688当前实现：选择起止日期，打开独立采集窗口完成登录，左上角账号ID自动回填到只读账号框，无需手填别名。点击“自动采集”后程序重新识别当前登录账号，填写下单时间，搜索并等待请求完成，核对日期，点击“导出当前条件”，接收Excel/CSV下载，再核对账号未变化，读取并生成入库预览。核对后点击确认入库。

默认调用本机安装的 Google Chrome，不再自动切换 Edge。每个平台使用独立、固定的自动账号会话目录（profiles/chrome下），无需事先知道账号ID。与原“平台+别名”会话分开，不占用日常Chrome资料，也不迁移旧登录信息；首次切换需重新登录。旧资料和旧别名下的采购记录保留，不自动改名或合并历史数据；新记录按平台+识别到的账号ID归集。更换账号请在采集窗口内退出并登录另一个账号，软件每3秒检查可见顶部登录身份；识别失败不导出、不入库，不用卖家昵称推测买家账号。验证码与登录由使用者完成。手动导入同样要求先识别当前账号，并在选择文件后再次核对。

支持跨月日期，按订单下单日期分别归入对应月份。原始文件保存在本机workspace/purchase-auto/incoming；预览另保留副本到purchase-exports。取消预览保留原始下载。没有有效文件、搜索尚未结束、日期不一致、关键字段缺失时不入库。停止采集会关闭本次采集窗口，台账不变更。

本次按截图实现“搜索→导出当前条件”。日期输入无法识别、只读控件不允许填写、导出后进入报表生成中心而没有直接下载等情况会提示人工处理。当前淘宝保留文件导入与后台入口，未声称具备经校准的自动导出能力。

选择器来源是用户提供的purchase-report/config/selectors.yaml，本程序复用其中平台地址与登录页识别信号。浏览器自动化复用现有Playwright及本机Chrome，无Python依赖。

验证：npm.cmd run test:purchase。覆盖本地网页的日期范围、先搜索后下载、即时下载接收、跨月归集、重复文件与行序改变去重、错误日期与登录阻断。所有浏览器测试仅访问127.0.0.1。

窗口专项验证：`node --test tests/purchase-window.test.mjs`。仅使用自己新建的Chrome测试资料与localhost页面，检查原生窗口最大化状态，再改变原生窗口大小并验证网页宽高同步变化。不会接管日常Chrome或访问1688。

真实1688页面访问被当前浏览器工具的站点安全策略阻断，尚未完成真实账号导出验收。截图不能证明实际DOM选择器可用，也不能证明导出后的弹窗流程。本实现未绕过该限制，需由使用者在程序中首次验证。
