## 已通过

- 实际安装包覆盖原安装位置，安装结果为 0.8.0；首页三个入口均可识别原模块。安装和关闭启动台前后，五个原后台服务进程均未被替换或终止。
- 切换前备份，原五个数据库逐表核对；415 项附件、配置、登录相关文件与基线一致。原数据目录和独立工作区保持可用，未用空账本替代原数据。
- 纯启动台包不包含云仓业务实现、账本、附件、订单或登录凭据；打包文件与源文件一致。五个业务包及两个运行环境经过允许列表、秘密扫描、ASAR 内容完整性检查。
- 模块管理 18 项自动测试覆盖签名、摘要、兼容性、安全解压、重复请求、取消、网络失败重试、磁盘不足、忙碌阻止、安装失败回滚、恢复日志、离线依赖、降级阻止及缓存损坏恢复。
- 五个真实构建模块在隔离账本上完成安装、服务健康检查、卸载、重装及数据保留。云仓升级到独立进程名，避免启动台覆盖安装误停云仓。
- 打包后的 CLI/MCP 能查询模块；缺失模块明确返回未安装，不隐式下载。主页三个“下载使用”入口、设置、合并帮助入口通过浏览器自动检查。
- 采购和销售嵌入页面可返回、切换并保留页面状态；附属模块首次使用出现下载确认。关闭启动台后后台继续运行。
- 采购导入的隔离测试覆盖五个平台合成数据、长订单号、多商品、多账号、重复、变更、未知退款、字段缺失、未完成范围、月份锁定、确认后变更、回滚及中断重试。19 项导入和集成测试通过。
- 打包后的采购页面实际完成两次确认；第一次确认前后账本不写入，第二次提交后金额与多商品明细一致，经营总览的支出增量一致。所有测试写入都使用隔离数据。
- 总览缺少来源时明确报告未接入；启动后再安装采购或销售，能动态识别注册表，无须重启总览。相关测试通过。
- 完整离线模块包在禁止网络请求的测试中完成官方签名、七包摘要、依赖完整性检查并启动共享运行环境。
- GitHub 七个单包的资产大小与 SHA-256 均和签名目录一致。无认证请求取得公开目录，并实际下载 Node.js 与总览包，完成安装、启动和业务接口查询。
- Windows CI 完成桌面、核心、模块、启动台、MCP、退役模块、仓库清理检查及生产依赖审计。`follow-redirects` 已升级至 1.16.1，生产依赖审计为零漏洞。

## 验收边界

- 全新 Windows Sandbox 首次进入桌面并生成安装快捷方式，但验收脚本收到“拒绝访问”；重试时 Windows 返回 `0x80070520`（登录会话不存在），远程窗口提示环境正在注销。因此全新系统在线/离线端到端验收未通过，保留自动验收脚本及错误证据，不能以本机隔离目录测试替代此结论。当前电脑的实际覆盖安装与隔离离线验收均已通过。
- 本次没有对五个平台重新登录或进行完整真实订单采集，也没有向原采购账本提交测试订单。合成测试和内部账本一致，不证明平台采集没有漏单。
- 模块清单使用 Ed25519 签名并包含每个包的 SHA-256；Windows 安装器未配置商业 Authenticode 代码签名证书。这是两类不同验证。
- 跨电脑共享账本、多人访问、公网部署与跨架构分发不在此次范围。
