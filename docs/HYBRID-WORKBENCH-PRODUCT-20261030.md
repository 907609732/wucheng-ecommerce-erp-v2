# 三合一业务工作台 + Harness：产品交接契约

依据：用户 2026-10-30 最新纠正；本契约取代“只保留聊天入口、以 Agent 结果取代全部业务界面”的解释。目标是保留人的核对与录单能力，减少采集、导入、整理中的人工步骤。以下为待实施契约，不能计作完成证据。

## 1. 保留什么，整合什么

| 工作面 | 必须保留的现有能力 | AI 承担的主要工作 |
| --- | --- | --- |
| 采购 | 月度看板、订单搜索与明细、人工新增/修改采购单、退款、商品/物流/附件、分类归属、供应商、核对任务、月结、审计和导出 | 平台采集、文件/OCR 识别、字段整理、查重、生成采购草稿与异常清单 |
| 销售 | 运营看板、销售/退款/收款/费用明细、应收与资金对账、原件、运费、资料覆盖、月报、月结与导出 | 下载账单、解析归属、对照数据、准备导入、生成差异与待复核结果 |
| 经营 | 整体收支、趋势与来源穿透、采购/销售汇总、费用、人力、付款登记、缺数提示、月报和历史快照 | 汇集已有台账、检查缺项和异常、解释来源、生成分析或待补事项 |

“三合一”指一个应用窗口、统一主导航和工作上下文，三类工作面可直接切换；第一批复用现有账本和领域服务，不以物理合库作为恢复功能的前置条件。采购、销售对经营的来源关系继续保留。云仓、订单导出、备份、定时任务仍属于软件能力范围。

**运费沿用用户先前决定**：面板右上保留“导入运费”，选择平台后呈现导入 Skill 和提示词；菜鸟可用，其余明确“待开通”。保留运费结果、原件、明细和核对，不借本次纠正恢复已明确删除的手工运费录入流程。

## 2. UX / UI 直接采用的信息结构

- 主导航：**业务工作台、AI 任务、任务历史、技能与提示词、设置**。业务工作台内固定 **经营 / 采购 / 销售** 三个入口；经营作为整体查看入口，采购与销售一键进入，不能藏在设置或要求先向 AI 发话。
- 业务工作面占主要空间，保留表格、筛选、图表、原件和人工操作。AI 为可展开的侧栏或独立任务工作面；业务页上“交给 AI”带入模块、当前筛选和来源范围，先展示带入范围。
- 查看结果可定位回实际业务明细；从明细返回时保留筛选、滚动和未提交表单。AI 完成后提示可刷新数据，不覆盖正在编辑的人工草稿。
- 三合一不是三个外部窗口或三个跳转卡片。第一批可在同壳内嵌真实旧工作面；随后收敛重复品牌、侧栏和跨模块链接。外层保留测试账本与当前连接标识。
- 人工保存沿用实际表单及领域校验；AI 生成的正式变更走结果复核。两种入口共用金额、去重、锁月、附件、审计和回执规则。全员真实登录后访问全部业务，不恢复权限管理。
- 所有加载仅使用既有通用进度条组件。原生内嵌视图须为外层导航、AI 侧栏和对话框留出真实布局区域，避免覆盖与焦点冲突。

## 3. Harness、Skill 和提示词的实际职责

Harness 统一接收目标及页面上下文，选择模型/引擎，组织会话、工具发现、执行、取消恢复、定时、用量和回执。Codex、Hermes 是可替换的执行适配；API 服务按兼容协议接入并显示实际支持状态，不把填写地址视为接入成功。MCP、CLI 与人工界面调用共同的业务执行层。

“技能与提示词”提供查看、创建、编辑、复制、导入导出、启停和版本历史。每个 Skill 保存名称、用途、平台/模块、所需输入、步骤、工具能力绑定、提示词及输出要求；每个版本有作者、时间和变更说明。内置 Skill 可复制后定制。新任务绑定具体版本，运行中编辑不会悄然改变该任务；新版本通过真实调用后标记可用，未开通平台继续占位。

提示词负责目标与步骤，登记的 MCP/CLI 能力执行实际操作。Skill 编辑不会改变真实身份、任务范围、来源证据或正式提交边界。正式入账、对外发送等结果仍绑定具体数据版本由人确认；可纠正格式自动处理，金额、归属和冲突交给人核对。

## 4. 现成入口、缺口与本轮批次

已核对：`desktop/local-desks.mjs` 的 `installDeskViews()` 已能同窗口切换三台；`preload.cjs` 已暴露 `open/hide/bounds/onNavigate`；`main.mjs` 的 `modules:open` 仍接真实服务。三模块 `public/index.html`、`public/app.js` 和采购 `order-form-view.js` 保留原工作面。当前 `agent-index.html` 仅新任务/历史/设置；`agent-workspace.mjs` 未接业务导航。`agent-host/launcher-policy.mjs` 还会拦截 `modules:open`，而 `local-desks.mjs` 直接注册的 `desks:open` 不经过该包装器。

最小接线：只开放采购/销售/经营的业务打开入口；把真实身份、连接状态与 Beta 注册表校验放到共同 `beforeOpen/ensure` 路径，使两种 IPC 同受约束。继续封住旧安装、迁移及维护操作。前端先隐藏内嵌视图再切 AI/设置，通过实测容器边界调用 `bounds`；监听 `onNavigate` 统一跨台导航。手工写入接口的登录/签名兼容由领域组逐项确认，不能用绕过校验的方式恢复表单。任务/复核层可复用；Skill 注册、版本绑定和页面上下文需新增。

1. **恢复可用工作面**：主壳加入真实三合一内嵌入口，接现有视图/服务；处理显示隐藏、尺寸、返回、跨模块链接、连接变化和未保存草稿。先保全所有原功能。
2. **接好人机协作**：业务页范围交给 AI，任务结果回到真实明细，完成状态及时同步；增加 Skill/提示词的持久化与版本绑定。保留当前真实 DeepSeek / Hermes 连接成果。
3. **统一体验与最终集中验收**：收敛重复导航和公共组件。完成后一次验证“人工采购单 → 销售/采购核对 → 经营来源穿透”及“AI 采集导入 → 差异复核 → 实际回读”。同时验证切页保留草稿、测试账本隔离与包体真实运行；失败范围定向修复，不反复全量测试。

交付边界：旧界面能打开不等于三合一体验已完成；AI 能回复不等于已调用业务能力；本契约不改变主干、正式数据和正式切换的既有保护。
