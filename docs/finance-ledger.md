# 店铺销售额采集（独立账本技术说明）

淘宝销售额人工下载以用户框选的「收入账单 → 月汇总 → 选择月份 → 查询 → 导出 Excel」为本次流程，见 [淘宝店铺销售额采集说明](taobao-sales-collection.md)。软件各功能右上角的「说明书 / 技术原理」使用本地统一内容源，见 [各功能说明书](feature-manual.md)。

以下保留原财务账本的扩展功能与历史验证记录；这些记录不代表本次已接通真实自动取账，也不要求仅采集销售额时同时下载支出及涉税账单。

运营看板是原来的经营数据功能；财务账版是新建的独立账本，不读取、复制或推算任何历史运营数据。每个店铺独立配置纳税主体、税号、主体类型、纳税人类型、申报周期和取账计划。

## 使用步骤

1. 主页选择「店铺销售额采集 → 添加店铺」，直接打开独立千牛登录窗口，不先填写大表。登录后读取店铺名、账号、店铺 ID，以及页面明确提供的主体信息；核对后「确认添加」。未显示店名时只补店名，未读取到账号或店铺 ID 时继续登录。税号、主体类型、纳税人类型、申报周期可稍后设置，新店定时任务默认关闭。取消或关闭登录窗口不创建占位店铺，取消清理临时会话。真实千牛身份自动读取尚未验收，不能保证后台返回全部资料。
2. 选择账期，点击「立即取账」或「更多 → 打开店铺后台」。在本店窗口完成登录，核对月份，分别导出收入、支出和涉税信息报送账单。下载完成后显示在「待核对文件」；ZIP 保存在财务资料目录，需要解压后导入。
3. 已有原始 Excel/CSV 可用「导入账单」。选择工作表、账单类型、月份、数据行范围及金额对应列。表头、合计行必须排除；不能把月汇总、日汇总、明细重复相加。自动收集的多文件可整批核对，只有完整批次才能入账；“全部”视图与具体子类型不得叠加。各分片字段不一致时需要分别映射，保留原始分类与来源文件备查。
4. 先点「预览核对」，确认金额和问题后再点「确认并入账」。相同文件和字段不重复入账。同店、同月、同类的更新完整替换当前版本，旧版本在「取账记录」中恢复。
5. 在「填表草稿」查看按月或按季汇集的来源。填写申报项目金额及来源/计算依据，保存草稿，再导出填表资料。空白是待确认，不是零。账单更新、恢复或店铺口径变化后，旧草稿会提示重新核对。
6. 「下载原文件」输出原始字节；「导出填表资料」输出使用说明、填表草稿、平台报送参考、当月账单明细、核对问题、期间来源清单、原值与公式。

## 每月 15 日计划与当前接通边界

- 每店单独启用，09:00 按北京时间取上月账单，不依赖电脑系统时区。15 日是用户指定取账日，不是统一纳税申报截止日。
- 电脑及软件需要运行。启用计划后关闭主窗口只隐藏，计划继续执行；退出进程、断电时不能运行。可在公共设置中自行开启登录 Windows 后启动。再次启动只补最近到期的一期，更早月份手动补取。
- 执行记录先持久化，再打开店铺窗口；同店同月不会因每分钟检查而重复启动。登录、验证码、无法核对账号、页面变化、空查询结果或异步导出中心转为待处理，手动重试。程序中断的记录重启标为已中断。
- **当前尚未通过真实千牛下载验收**：本次浏览器工具的安全策略阻止读取淘宝帮助页及千牛登录页面。因此未确认当前后台 DOM、全部收入子类型、支出与涉税账单切换、导出中心和真实文件字段。页面适配器采用严格检查：账号、月份和唯一导出入口匹配才尝试点击；其余需要人工在店铺窗口导出。新窗口首次打开不会自动完成全部分类取账。
- 收到 Electron `completed` 下载事件才记录收到文件；打开网页、点击导出、后台显示 0 项都不算已取到账。下载文件仍需预览并入账，不自动标记为完整账期或已申报。要完成无人值守取账，需要在可访问的真实千牛会话里联调并提供实际导出样本，完成全类型下载验收。
- 客户端模式明确提示在主服务器操作；财务数据尚未暴露给原远程经营数据 API。单机与主服务器均独立本地保存。

## 申报口径

输出是**人工核对的填表工作底稿**，不是电子税务局官方申报表，也没有实现税务局自动填入、正式提交、缴税。企业/个体、一般/小规模、税种、地域及适用政策不同，不能仅凭店铺到账额推算税款。此版不自动套用税率、减免或费用扣除。

平台涉税报送收入总额包含价款与增值税税额，不扣除实际补贴及平台佣金、服务费；退款、收入净额分别保留。平台报送数据用于核对，不直接当作商户不含税申报销售额。收支账单和涉税账单金额不同会提示查明口径，不覆盖原值。同税号多个店铺会提醒按纳税主体汇总，并补充平台外收入等资料。季报缺月不显示完整季度参考合计。

## 代码与存储

- `desktop/shared/finance-ledger.mjs`：金额整数分、SQLite、原始文件哈希、预览/版本/恢复、申报期间和 Excel 导出。
- `desktop/finance-worker.mjs` / `finance-jobs.mjs`：文件解析及查询在 worker 中执行，120 秒超时，原表上限 80 MB、解压 300 MB。
- `desktop/shared/finance-browser.mjs`：Electron 官方会话与下载组件、每店隔离、不复制外部浏览器 Cookie、下载完成后入待核对区。
- `desktop/main.mjs`：每分钟检查到期计划，财务 IPC 仅允许本应用主窗口、禁止客户端写本地影子账本。不会调用提交纳税申报或支付接口。
- `desktop/renderer/finance.js`：三个页签、Tabulator 查看/筛选/排序、店铺与字段映射对话框。
- 数据位于应用 userData 下 `workspace/finance/finance.sqlite`、`originals/`、`downloads/<shopId>/<month>/`。登录会话由 Electron 分区保存于该 userData。无真实文件、账单、税号、Cookie 打包进仓库或安装包。
- 原文件不可改写；记录保存源单元格、原公式及缓存值。缺少缓存、无效金额、跨月或重复行作为核对问题。明细按导入映射计算，人工确认才入账。

### 2026-10-10 外部 AI 改动复核

实际检查本机 Node 为 v24.18.0，与外部报告的 v22.23.2 不同。现有实现使用 Electron 独立店铺会话和页面脚本，不是控制已安装的原生千牛客户端；千牛登录状态不会自动共享。

已补充的账本修复：

- 同一财务目录的 worker 操作排队，等待 SQLite 连接关闭后再执行下一项，避免界面刷新和取账同时初始化数据库引起锁冲突。
- 旧账本已保存文件补建版本记录，保留生效状态及历史恢复；单文件不能被误判为完整多文件版本的重复导入。

- “全部”与具体子类型混合的批次拒绝直接相加；未完整批次、文件名明确标注类型与批次冲突的文件拒绝入账。原文件保留。这些检查不能证明未标明类型的文件一定正确，仍需人工核对。

## 本地账单交接接口（开发接入）

本接口只接收已经通过正常途径导出的文件，不登录平台、不下载账单、不验证导出完整性，也不自动提交入账或申报。千牛无人值守下载仍未接通。缺少的账单类型会明确列出，不认定为零或无数据。

复用现有财务 SQLite、原文件保存和待核对批次。支持 Excel/CSV；原件按 SHA-256 保存。清单里必须明确指定店铺、账期、账单类型及子类型，不根据文件名推测金额或店铺。相同店铺、账期、类型、子类型和文件内容的清单重复提交会返回原接收结果，重启后仍有效。清单中任何文件失败，整次数据库写入回滚；已复制的原件可能保留，但不产生生效账目。

目前为显式运行的本地 CLI 接口，尚未注册为影刀/八爪鱼应用、MCP 工具或后台定时服务。客户端模式不要使用；在保存财务数据的主机运行。为避免独立进程和正在处理的界面同时操作任务，请先退出 ERP 再接收，接收完成重新打开 ERP 核对。

将清单和账单放在同一目录，文件也可以在该目录的子目录中；不接受绝对路径或指向目录外的路径。示例 `receipt.json`：

```json
{
  "schemaVersion": 1,
  "shopId": "填写软件中已有财务店铺的ID",
  "month": "2026-09",
  "files": [
    { "path": "收入.xlsx", "kind": "income", "subtype": "货款收入" },
    { "path": "支出.xlsx", "kind": "expense", "subtype": "费用" },
    { "path": "涉税.xlsx", "kind": "tax", "subtype": "涉税信息报送" }
  ]
}
```

在项目目录执行（路径换成真实的本机路径；财务数据目录必须已包含 `finance.sqlite`）：

```powershell
npm.cmd run finance:receive-local -- "C:\实际应用数据目录\finance" "C:\正常导出的账单\receipt.json"
```

成功返回 `receiptId`、`jobId`、`batches`、`missingKinds`，状态固定为 `awaiting_review`，`platformDownloadVerified` 固定为 `false`。失败返回非零退出码。接收成功只表示清单内文件已保存，不能证明清单涵盖平台所有子类型或账单属于声明的店铺和月份。

随后在财务账版中选择对应店铺和账期，进入“待核对文件”，确认来源店铺、期间、字段映射、行范围和金额，再人工提交。服务不主动填写映射，也不会把文件接收当成报税完成。不同清单存在部分重叠时，应在预览时核对版本与重复数据，不能直接合并入账。

实现：`desktop/shared/finance-local-receipt.mjs`；调用入口：`scripts/finance-receive-local.mjs`。测试全部使用临时目录的合成账单，不使用真实经营数据。
