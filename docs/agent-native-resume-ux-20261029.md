# Agent 结果工作面 UX 续接约定

日期：2026-10-29。范围为续接清单 08–10，以及 12 的用户可见反馈。基于现有 `agent-workspace.mjs`、`agent-api.mjs`、`agent-index.html`、中央结果版本和下载链核对；本轮没有运行测试或平台操作。

## 共同规则

首页仍以目标输入框为中心。任务空间继续使用执行动态、结果工作面、来源与复核，不新增业务向导或独立人工录入页面。表格、原件和图表是核对目标结果的工具。

所有异步等待复用 `desktop/shared/loading-screen.mjs` 的进度条。现有右侧结果版本、来源、异常和正式提交回执保持可读，处理中不能显示“已完成”或“已入账”。历史结果只读。用户切换任务、结果版本或账户时，应清理未提交的临时预览资源，不把前一任务内容留在当前页面。

## 原件预览

### 入口与内容

在已有结果文件和来源条目中，对中央 artifact 提供“预览”和“下载”两个轻量操作。下载继续使用现有保存对话框。只在服务端允许且文件实际属于当前任务/当前访问者时显示可预览内容。

仅内嵌 PNG、JPEG、WebP 和 PDF。SVG、HTML、未知类型保持下载入口；不要尝试把领域 fileId、本地路径或任意 URL 当作预览源。UI 不从文件扩展名推断可信 MIME；以服务端实际核对后的类型为准。

预览显示在任务内的原件查看层，可用 `<dialog>`。标题包含文件名，辅助信息包含文件类型、大小与来源。图片可适应窗口，PDF 提供页内滚动或受控查看容器；窄屏仍保留可见的关闭和下载操作。打开后焦点进入查看层，关闭后回到原入口，Esc 关闭，Tab 不跑出查看层。

### 状态和文案

| 状态 | 内容与可用动作 |
| --- | --- |
| 读取中 | 共享进度条，“正在读取原件”；关闭始终可用 |
| 就绪 | 原件、文件信息；关闭、下载 |
| 文件过大或类型不支持 | “此原件暂不支持内嵌预览，可下载后查看。”；下载、关闭 |
| 权限失效或文件摘要变化 | “原件无法读取，请刷新任务后重试。”；关闭、刷新结果；不保留旧预览 |
| 读取失败 | 实际错误摘要；重试、下载、关闭。下载也必须重新鉴权 |

已有 `artifacts.open` 会在 launcher 主进程触发保存对话框，不能借用它伪装为内嵌预览。需要新增受控的 `artifacts.preview` 或等价只读私有入口，并经过现有 task/actor/hash 检查。临时对象 URL 应在关闭、任务切换和窗口销毁时 revoke；不持久化 base64 到任务补充内容。

## 草稿表格更正

### 可编辑的资格

默认表格只读。只有业务适配器明确返回稳定 `block.id`、唯一 `rowKey` 和 `editableFields`，并且服务端允许当前结果版本更正时，才显示“更正草稿”。用户须具有对应业务权限，当前任务不在 queued、running、committing、unknown 或 cancelled 状态；历史版本、来源原件和已入账事实不能原位改写。

字段编辑由声明决定；只允许简单文本、金额/数量、日期和枚举等适配器已定义值。业务行 ID、原件摘要、来源范围、人员真实 ID 和审批字段不能由表格自由修改。领域人员映射不明或重名时，回到必要问答让用户选择真实人员。

### 最小交互

1. 用户点击“更正草稿”，仅声明字段变为原位输入框。保持列名、行标识、原始值可核对，首个字段获焦。
2. 更正期间出现“提交更正”和“取消”；非编辑字段不变。未修改时禁用提交。输入框保留明确标签，金额显示来源单位，空值不自动转为 0。
3. 提交前在同一表格下展示逐项旧值→新值，提示“更正后将重新生成结果，需重新复核。”。这是重算的说明，不是正式入账确认。
4. 用户提交后，前端发送绑定当前结果的结构化更正。服务端校验旧结果版本、行/字段、旧值和权限；持久化为用户补充，再调用原业务 prepare/重算生成新结果。
5. 请求已接收时显示“更正已提交，正在重新生成结果”；结果生成后显示新版本、差异、来源和异常，正式提交仍用现有结果页复核。

建议提交数据为 `{taskId,resultId,resultVersion,corrections:[{blockId,rowKey,field,before,after}]}`。可作为 `tasks.input` 的受控扩展，或由独立 revision 操作实现，但必须服务端校验。当前纯文本 `tasks.input` 的成功返回不等于字段已被业务应用。若只是提交更正要求而无确定重算能力，必须保留“待重新生成/待核对”状态，不能把输入框的新值显示为已生效业务事实。

### 取消、陈旧和并发

| 情况 | 交互 |
| --- | --- |
| 取消编辑 | 丢弃本次本地改动，恢复服务器原值；不产生业务请求 |
| 结果在编辑中变化 | 停止提交，保留可复制的更正摘要；提示“结果已更新，请核对新版本后重新更正。”，不自动重放到新行 |
| 权限变化 | 退出编辑，刷新结果与权限；不沿用之前的提交资格 |
| 提交失败 | 本地改动保留，显示实际失败原因；不写成功提示，不自动重试未知请求 |
| 切任务或离开结果 | 有未提交改动时提醒保留在当前任务或放弃；只在用户选择后离开 |
| 新结果生成 | 清空旧复核勾选和 binding，必须重新核对；旧版本仍能从历史查看 |

## 图表

### 语义协议与展示

首轮只支持柱状图和折线图。适配器必须提供稳定 block id、维度字段/名称、指标字段/名称/单位、数据行、范围、来源，以及完整性状态。不得把任意对象自动猜成图表。

建议语义形状：`{id,type:'chart',chartType:'bar'|'line',dimension:{key,label},series:[{key,label,unit}],rows:[...],scope,sourceRefs,completeness:{state:'complete'|'partial'|'missing',message}}`，其中 `sourceRefs` 引用当前结果 evidence 中的稳定来源 ID。最终字段以策划/公共协议收敛为准，UI不得并行发明第二套协议。不同单位不得混用同一数轴；首轮可拆成相邻图表。金额保留 `fen`/`decimal` 等来源单位和币种，参考差额不标成利润。

图表标题下显示范围和完整性说明；指标图例以文字区分，不能只靠颜色。数据点可通过键盘或邻接明细读取具体值。每张图始终提供“查看数据”展开表格，供核查、窄屏和无图形能力时使用；未知图表协议显示可读结构化数据并注明“暂不支持此图表”，不能静默丢弃。

### 无数据与缺失

| 数据情况 | 展示 |
| --- | --- |
| 已完成查询且 rows 为空 | “此范围没有符合条件的记录。”；不画全零图 |
| 来源未取得/完整性 missing | “数据尚未齐全，暂不能生成此图表。”，列缺失范围/来源；不把缺数画成 0 |
| 部分数据 partial | 展示已有数据，明显标“数据未齐全”；缺失值保留缺口，不连成实测趋势 |
| 值为真实数值 0 | 按 0 绘制，与未知值可区分 |
| 非数值/非法单位 | 显示字段问题与可核对明细；不擅自解析或换算 |
| 日期或分类重复 | 由业务适配器先聚合/解释；UI不静默相加 |

## 运费跨模块交接反馈

用户仍只描述“整理/导入运费”。销售是菜鸟运费准备入账的唯一 owner；如果总览已经有原件，任务动态显示“复用已归档原件”，经中央 artifact/attachment 转交并核对摘要，不让用户重新下载上传。来源面板保留原归档出处与本次销售导入的关系。

无可用原件时才显示实际采集进度；原件缺范围或摘要变化时进入必要问答/异常。待开通平台保持“待开通”，不能出现虚构进度或成功状态。最终结果按统一版本复核入账。

## 集中验收时的 UX 边界

实现后一次性覆盖：预览关闭/Esc/焦点恢复与任务切换；390px 窄屏；版本变化时更正和复核失效；输入空值/真实0；partial/missing图表；未授权原件；所有等待仍为共享进度条。上述为待执行验收范围，本轮没有运行。
