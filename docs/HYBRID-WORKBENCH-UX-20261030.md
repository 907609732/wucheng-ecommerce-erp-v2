# 三合一业务工作台：UX 实施规格

交接依据：`HYBRID-WORKBENCH-PRODUCT-20261030.md`，用户最新纠正优先。本文件是待实施规格，不是完成证明；不修改业务规则、正式数据或现有 AI 密钥。此前实时同步补丁保持独立。

## 1. 入口与工作上下文（第 1 页）

主导航固定为「业务工作台 / AI 任务 / 任务历史 / 技能与提示词 / 设置」。首次进入业务工作台的「经营」，之后恢复上次工作台及筛选。工作台顶部直接切换「经营 / 采购 / 销售」，「更多业务」保留云仓、订单导出及当前支持的查看/操作入口；不可用时说明实际原因，不能删入口或当作已完成。

业务页为主要工作面，采购的「新增采购单」和原有编辑/核对操作直接可达，不要求先聊天。切台采用隐藏并复用同一模块视图，不刷新、不另开外部窗口。外层始终显示测试账本、连接状态和当前业务台；AI 任务和设置等整页打开前先隐藏原生业务视图，返回时恢复。

业务顶部「交给 AI」展开上下文助手，输入框上方显示可移除的范围条：模块、账本、期间、筛选、日期口径、选中记录数量。发送前冻结一份范围；后续手动筛选不暗改已运行任务。未选记录时明确“当前筛选范围”，禁止默认为全账本。只带已保存记录及已选原件标识；采购编辑草稿只有用户主动「把这份草稿交给 AI」才随任务传入，不能暗中正式保存。

实施修订：没有真实页面上下文桥时，显示“未读取页面筛选；仅按用户目标中的范围执行”，不显示虚构的当前筛选或记录数。目标是唯一必填项；独立范围框仅供可选补充，日期和对象已经写在目标中时不重复要求填写。缺少执行所需范围由 Agent 发起必要问答。业务侧发起任务后保留业务工作面与助手，由用户点击“展开任务空间”才进入完整复核页面；默认允许当前模块及公共事务，并列明所选 Skill 需要的额外模块。

上下文助手可输入目标、选 Skill、查看进度和当前结果；「展开任务空间」进入完整任务/复核页面并保留返回位置。AI 执行后显示数据已变化及「刷新看板」，不自动覆盖正在录入的采购单。真实 DeepSeek/Hermes 配置沿用，不能要求用户重填密钥。

## 2. 原生视图与对话框布局

必须给 WebContentsView 和 AI 分配真实、不重叠的窗口内容区域。以业务容器 `getBoundingClientRect()` 的可见矩形为依据，统一窗口内容坐标（DIP），主进程钳制 x/y/width/height；不能用 HTML z-index 遮盖原生页面。现有 bounds 接口只接收宽度、忽略高度，必须补齐高度后才能宣称布局完成。

| 情况 | 原生业务区域 | AI / 外层区域 |
| --- | --- | --- |
| AI 收起 | 业务容器全宽全高 | 顶部保留助手入口 |
| 窗口宽 ≥1360，且业务剩余宽 ≥760 | 内容左侧，实际减去 AI 宽及 16px 间距 | 右侧 AI 宽 360px；若调宽，不得挤破业务最小宽 |
| 空间不足 | 保留业务视图实例并隐藏 | 同一窗口切为完整 AI 工作面，明确「返回采购/销售/经营」；不用覆盖式窄浮层 |
| 外层原件预览、复核或 Skill 弹窗 | 弹窗打开前 await 隐藏原生视图 | 弹窗获得焦点；关闭后仅在同一账本/连接和当前业务页恢复原生视图 |

窗口 resize、缩放、侧栏变化及返回均重新测量；最小化/容器不可见时不设伪造的 100px 占位视图。切换/加载使用既有通用进度条；期间隐藏旧台，防止“采购标题下仍是销售内容”。原生业务内部弹窗在其自身视图中显示；外层弹窗须真实隐藏原生视图并恢复原焦点位置。

## 3. 草稿、返回与来源定位（第 2 页）

采购存在未保存内容时，台签显示「未保存」。单纯切台、展开助手或查看任务只隐藏视图，完整保留字段、附件、筛选和滚动，不弹多余确认。不允许以 `loadURL` 或销毁重建代替切台。刷新、重连、同台来源跳转、退出等确实会丢状态的动作，先执行草稿保护：可继续填写、保存本地草稿后继续、明确放弃后继续。保存草稿不入正式账、不绕过原表单校验；保存失败留在原处。草稿恢复按真实人员、账本、原记录版本核对，冲突提示人处理，不能静默覆盖。仅内存保留不等于已支持退出/崩溃后的草稿恢复，未实现时必须明确标记。

每台保留独立页面状态：路由、筛选/日期口径、排序、分页、滚动、选中记录及打开的明细；外层保存“从哪里来”。跨台来源使用受控结构 `{module, recordId/sourceId/batchId, period, basis}`，主机解析真实目标；结果文本、外部 URL 不作为任意导航地址。点击「在采购/销售/经营中查看」先检查同台草稿，再定位实际明细/高亮关联记录，并提供「返回 AI 结果」。返回恢复原筛选和滚动；记录已变更/不存在时展示实际状态与来源，不猜测替代记录。

经营 → 采购/销售来源穿透、AI → 实际明细、明细 → 原任务都通过同一外层导航。AI 正式提交后先取得回执并回读，再提供看板定位/刷新。人工录单保留现有真实保存和领域校验；AI 正式变更保留结果页人审。两者都不能解除锁月、去重、金额和审计要求。

## 4. Skill 与提示词：编辑到运行

列表显示用途、模块/平台、当前版本、启用状态及「内置/自定义/待开通/待验证/已验证」。打开详情可查看所需输入、步骤、绑定能力、提示词和输出要求。内置项「复制并定制」；自定义项编辑保存为新版本，记录作者、时间和变更说明，保留历史。运行中任务固定版本号及摘要，编辑不影响旧任务。

运行路径：选择 Skill → 填补必要输入并核对带入范围 →「开始任务」→进度/异常接管→结构化结果→必要的人审提交及回执。无版本时不能伪造“已保存”；未验证版本可明确试运行，只有真实能力调用和结果核对后标为已验证。启停影响后续新任务，不暗中改变进行中的任务；需要取消时走任务的暂停/停止操作。提示词编辑不能增添任意文件/shell工具或改变提交边界。

运费维持单一「导入运费」入口：选平台后显示对应 Skill 与提示词，菜鸟可用，其余待开通；保留原件/明细/结果核对，不恢复手填运费。全员真实登录后访问全部业务，不恢复权限管理。

## 5. UI / 开发交接与边界

阶段 1 先复用真实经营/采购/销售页面，保全人工操作和来源关系；云仓/导出入口说明当前支持方式。旧页面中的重复品牌、内侧栏和跨台旧导航属于已知未收敛项，后续统一；“旧页面能打开”不能称完整三合一体验完成。

UI 接手须画出：经营默认态、采购录单+助手、窄窗业务/AI切换、草稿保护、结果定位、Skill版本编辑/运行。开发按现成 `installDeskViews`、`open/hide/bounds/onNavigate` 接线，所有打开路径共用真实身份/连接/Beta校验。实施完成后集中验收：人工采购→来源穿透；AI准备→人审→回读；切台草稿/滚动；原生边界/弹窗；版本绑定。此阶段不运行测试，不以静态图替代实际运行证据。
