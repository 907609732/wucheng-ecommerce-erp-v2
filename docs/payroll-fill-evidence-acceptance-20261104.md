# 工资填充、0元及付款凭证开发版验收

分支 codex/payroll-fill-payment-evidence，源码开发版29430；本次未打包、未推送、未修改正式0.13.0程序及正式账本。

## 功能与原因

- 原表格未启用 Tabulator 原生 selectableRangeFill；现在开启右下角填充柄并处理rangeEdited草稿通知，复用6.6.1内置能力，不自研拖拽。
- 原工资解析与账单规范化均拒绝0；现在只有工资允许明确0，负数/空白仍拒绝，其他账单和真实付款仍须大于0。数值0不再被逻辑或转为空白，0元工资标为“零金额”，不表示发生付款。
- 付款/退款窗口新增可选图片上传，最多6张，每张10MB，PNG/JPEG/WebP；支持预览、移除选择。图片和付款在一次请求/事务内保存，失败清理本次原件；旧JSON付款兼容。
- 记录显示缩略图及原图链接；撤销保留历史凭证；新增已认证成员可读图片接口，写接口仍只允许UI。原件使用独立UUID存放，校验签名、大小、摘要，不接收客户端提供的文件路径。
- 支持完整备份和恢复中的付款凭证引用、大小及摘要核对。

## 验证

- 相关38项测试通过：工资零值、财务核心规则、付款图片原子保存/事务失败/无效图片/数量限制/路径拒绝、撤销保留、备份恢复和图片缺失拒绝、multipart API与原JSON API兼容。
- 独立合成服务30430：实际鼠标拖动3月姓名和0元工资到5月，保存后生成3月、4月、5月三笔0元工资，已付均0，月份未变。
- 同一合成账本浏览器：选择360×180测试凭证，预览尺寸正确；移除后文件数0；重选并保存10元测试付款，记录已付1000分、凭证1张4805字节，缩略图能从受保护的/apps/overview路径加载原图。
- 独立审查未发现重要问题；已检查库内range.setData调用editable守卫，因此只读月份/付款状态、复杂工资和保存中单元格不被填充覆盖。
- 最后已打开普通源码开发版29430人力支出，无测试草稿；合成服务停止。截图、脚本和测试图片位于工作区外 E:/WuchengERP/development。

图片当前校验文件签名而不做完整解码；损坏但签名正确的图片可能无法预览。UVCS独立功能合并时必须同时纳入新的付款凭证引用，不能只托管付款文字数据。正式版需要后续明确打包更新，当前正式0.13.0仍保持原行为。
