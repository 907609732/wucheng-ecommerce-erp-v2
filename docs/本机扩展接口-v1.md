# 本机业务扩展 v1

本版只交付当前电脑。主页为云仓同步、采购台、销售台；采购、销售、经营总览和买家订单导出台继续独立维护、独立保存数据。主程序使用 Electron WebContentsView，并保持 sandbox、contextIsolation 和 nodeIntegration=false。后台在主窗口退出后继续运行。

## 工作区与连接

默认工作区位于当前用户 `Documents/ChatGPT/采购`、`销售台`、`采购/采购台和销售额台聚合`、`复刻买家历史订单导出软件`。采购默认 17868，销售读取原 data/server.port，总览默认 17890。主程序不创建空业务账本。

如本机路径或采购端口与默认值不同，在 `%APPDATA%/LingtuIntegrations/registry.json` 中配置对应键 `purchase`、`sales`、`overview`、`exporter`。每项可包含 `root`、`dataDir`、`port`；导出台使用 `exe` 和 `dataDir`。当前电脑导出台复用 `%APPDATA%/买家订单导出台`，包含原订单任务和完整登录分区，不能改成一个空的新品牌目录。

服务身份包含 id、apiVersion、package version、root、dataDir、profile、pid、capabilities、busy。主程序检查身份、版本和实际数据目录。启动有进程内去重和跨进程启动锁；其他程序占用端口时拒绝继续。固定系统 Node.js 启动后台，日志位于各 data/integration-service.log。设置提供状态、路径、版本、日志和空闲时停止。采集、备份入账或其他保存请求进行时不能停止。

## HTTP 协议

基础地址：`http://127.0.0.1:<port>/api/integration/v1`。接口仅接受本机来源，拒绝跨站 Origin/Sec-Fetch-Site。密钥位于所属 data/.integration-key；调用方使用 Bearer，禁止写入日志或公共仓库。

| 方法 / 路径 | 适用服务 | 内容 |
| --- | --- | --- |
| GET /capabilities | 全部 | 本机身份、版本、目录、能力和忙碌状态 |
| GET /orders?q= | 采购 | 最多 1000 笔订单及商品明细 |
| GET /transfers | 采购 | 最近 100 批及结果 |
| POST /transfers | 采购 | 接收不可变快照，按摘要幂等 |
| GET /transfers/:id | 采购 | 来源、原值、拟入账值、问题、差异、金额和 revision |
| PUT /transfers/:id | 采购 | `{revision,decisions:{account,rows}}`，改变后两次确认失效 |
| POST /transfers/:id/review | 采购 / 仅核对页面 | 第一次逐单确认 |
| POST /transfers/:id/confirm | 采购 / 仅核对页面 | 第二次整批确认，产生短期 receipt |
| POST /transfers/:id/commit | 采购 / 仅核对页面 | `{receipt}`；备份、再次检查、事务写入、逐单比较 |
| GET /transfers/:id/verification | 采购 | 比较当前订单与该批确认内容 |
| POST /transfers/:id/rollback | 采购 / 仅核对页面 | `{reason}`；仅撤销本批变更，后续编辑冲突时拒绝覆盖 |
| POST /exporter/open | 采购 | 打开原独立导出台 |
| GET /report | 销售 | 原 report 查询参数与统计口径 |
| GET /ledger?month=YYYY-MM | 销售 | 月度销售流水，金额字段 amount 为整数分 |
| POST /overview/open | 销售 | 启动总览，返回本机地址 |
| GET /overview?month=YYYY-MM | 总览 | 读取源账本及锁定月快照 |
| GET /dashboard | 总览 | 原 dashboard 查询参数 |
| GET /bills | 总览 | 自有费用账单与付款 |
| GET /tasks | 导出台 | 脱敏任务列表 |
| GET /tasks/:id/orders | 导出台 | order-transfer/v1 快照 |
| POST /tasks/:id/transfer | 导出台 | 创建采购核对批次并打开页面，不直接入账 |
| GET/POST /edits | 三个台账 | 查询 / 创建修改草稿 |
| GET /edits/:id | 三个台账 | 修改前后内容与 revision |
| POST /edits/:id/commit | 三个台账 / 仅核对页面 | 本次界面确认后写入，校验失败事务撤销 |
| POST /stop | 全部 | `{confirm:true}`，仅空闲时执行 |

核对页面从同源 `/review-session` 建立短期 Cookie + nonce 会话。Bearer 调用不能执行界面确认端点。CLI/MCP 不公开 review、confirm、commit 或 rollback 代理；不存在绕过两次确认的参数。本机管理员或能修改源代码/数据库的进程不在此隔离边界内。

修改草稿请求：`{type,target,patch,reason}`。采购 type=order，销售 type=ledger，总览 type=bill。只允许白名单字段；不提供删除、任意 SQL、任意路径或付款操作。销售 patch 使用 amountCents（整数分），适配原服务的元输入。已导入的销售流水仍需原批次撤销流程，已有匹配、锁定月份、账单付款限制继续生效。

## order-transfer/v1

```json
{
  "schema": "order-transfer/v1",
  "task": {
    "id": "原任务编号",
    "platform": "taobao",
    "account": "原显示名",
    "accountKey": "可靠身份的 SHA-256；未知为空",
    "from": "2026-10-01",
    "to": "2026-10-20",
    "status": "completed",
    "listOutcome": "complete",
    "count": 1,
    "updatedAt": "来源更新时间",
    "plan": null
  },
  "orders": [{
    "id": "999999999999999999999",
    "platform": "taobao",
    "account": "原显示名",
    "createdAt": "2026-10-05",
    "paidAt": "2026-10-05",
    "status": "交易成功",
    "shop": "供应商",
    "paidFen": 12345,
    "refundFen": null,
    "freightFen": null,
    "items": [{"id":"1","title":"商品","quantity":2,"unitPriceFen":null}]
  }],
  "digest": "规范化 task 和 orders 的 SHA-256"
}
```

平台值：taobao（包含天猫）、alibaba、pdd、jd、xianyu。其他平台原采集和导出保留，但不能进入本版采购转入流程。未知金额为 null，不能替换为 0。规范化按对象键排序、数组顺序保留，再 JSON.stringify 和 SHA-256；凭据、Cookie 不进入任务元信息。

整批对应完整任务，禁止通过选择部分订单绕过范围问题。旧任务没有 listOutcome 或完整性依据时阻止入账。退款未知须在 rows[订单号] 内填写 refundCents 与 refundEvidence。首次对应真实采购账号；只有 64 位十六进制 accountKey 才记忆映射。占位账号不作为去重身份。

orders 的全部原字段存为不可变来源；采购保留全商品行，整单实付只加一次。物流、地址、图片等未获取会提示；未知独立运费沿用采购“实付已含运费”口径，不另加运费，原件保留未知状态。已有空缺不覆盖原值，备注默认保留，商品运单、分类、附件继续经过原业务校验。

## 事务、备份与恢复

追加 integration_* 表，既有表结构、业务 ID、原件和历史记录不迁移。提交前 SQLite 在线备份，原始快照保存到 originals/order-transfer-<批次>.json。批次写入与来源关联、原业务审计、结果在同一事务内；读取逐单核对后才提交，提交后再次读取。失败保留快照和错误事件。

相同快照重发、提交重试返回原批次；进程中断后已提交的批次不会重复入账。事务前/内失败可以重新核对再试。已经撤销的批次保留不可变历史，再次导入需要新采集任务。撤销不还原整个数据库；后续人工编辑存在时列出冲突订单并阻止覆盖。总览继续按原口径读取源账本，差额不等同于利润。

## CLI 和 MCP

沿用现有 `inventory_extension_list`、`inventory_extension_call` 和官方 SDK。随主程序安装的扩展 ID 为 `lingtu.desks`，actions 为 status、query、start、stop、prepare。查询 kind 包括 orders、ledger、report、overview、dashboard、bills、tasks、transfers、transfer、verification、edits、edit。prepare 仅保存草稿，仍需页面确认。

```powershell
# 查看扩展
& '.\云仓库存同步.exe' --cli extensions
# 查看服务状态
& '.\云仓库存同步.exe' --cli extension-call --id=lingtu.desks --action=status
# 参数使用 base64url JSON；不在命令中写入密钥
$params = '{"desk":"purchase","kind":"orders"}'
$encoded = [Convert]::ToBase64String([Text.Encoding]::UTF8.GetBytes($params)).TrimEnd('=').Replace('+','-').Replace('/','_')
& '.\云仓库存同步.exe' --cli extension-call --id=lingtu.desks --action=query "--params-base64=$encoded"
```

start、stop、prepare 还须遵循原扩展框架 `--confirm-side-effect`，它只确认启动/停止/草稿操作，不能代替订单导入的两次页面确认。导出台还提供 `--integration-cli`（任务查询）与 `--integration-cli --task=<id>`（只读快照）；原独立 UI 启动方式不变。

参考：[Electron WebContentsView](https://www.electronjs.org/docs/latest/api/web-contents-view)、[MCP TypeScript SDK](https://ts.sdk.modelcontextprotocol.io/v2/)。
