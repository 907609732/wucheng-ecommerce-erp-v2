# 五成电子商务工作台 0.11.0

工作台完整安装器包含云仓、采购、销售、经营总览、历史订单导出台以及固定 Node、浏览器、网关和私网组件。普通用户无需源码、npm 或手动导入业务包。产品以一份签名套装清单统一激活；各业务进程和账本保持隔离。

## 统一工程与数据

外部业务源码集中在 `apps/purchase`、`apps/sales`、`apps/overview`、`apps/exporter`；云仓沿用 `core` 与桌面核心。各组件保留锁文件，完整构建使用 `npm.cmd run workbench:build`，不会发布到公网。

固定 Node.js 与浏览器 vendor ZIP 随当前签名套装负载保留。后续构建优先读取 `dist/suite-payload-current.json` 指向的受保护 payload，核对签名、版本兼容、文件大小及 SHA-256；仅当 current 指针不存在时才使用旧 `dist/modules` 引导缓存。存在但损坏、越界或包含链接的 current 缓存会阻止构建，不回退。可运行 `node scripts/build-suite-payload.mjs --verify-vendors` 只读检查缓存选择；此命令不读取签名私钥、不重建组件或改变当前候选。

正式业务资料位于当前用户文档的 `LingtuWorkbench/Data/<模块>`。旧用户必须先执行受控迁移，不得指向空目录初始化。原服务器及各账本身份、记录 ID、金额、锁月和审计保留。浏览器认证、Windows DPAPI 与内置 Tailscale profile 保留原物理路径，注册表通过 `authProfileDir` 登记兼容位置。

同机迁移工具：

```powershell
node scripts/move-local-workbench-data.mjs preview <完整数据目录> <工程外私有备份目录>
node scripts/move-local-workbench-data.mjs apply <完整数据目录> <工程外私有备份目录>
```

apply 正常停止业务、形成全量文件及 SQLite 一致性备份、复制校验后切换五项注册路径；不复制旧 PID、启动锁或运行地址。新工作台在套装维护锁内复核数据，全部健康通过才开放业务。失败保留 journal、原资料和候选，不自动删除或覆盖。开放业务后禁止整库回退。

来源目录保留迁移维护标记，旧入口迁到工作台；不能继续直接用旧源码启动第二套账本。旧业务资料封存，认证目录不参与冗余清理。

## 启动与日常使用

“登录 Windows 后启动”位于设置中。新用户默认关闭，旧用户继承原云仓选择；后台启动只恢复网关及已启用的云仓计划，其余功能按需启动。关闭窗口进入托盘，退出界面不停止业务服务。服务停止和更新继续执行活动任务检查。

客户端沿用 Tailscale 和服务器账本，不因为安装器带有业务代码而初始化本地正式数据。登录、验证码仍在主服务器处理。未登录 Windows、休眠、关机和主机离线不属于后台可用状态。

MCP、CLI 的配置与调用示例见 `workbench-agent-interface.md`。历史订单正式入账仍需两次页面确认，智能体不能用确认参数绕过。

## 验证与清理

隔离测试、干净 Windows 离线安装、实际主机迁移及真实平台验证分开记录。检查启动项或隐藏启动参数，不等于完成真实 Windows 重新登录验收；实际验证范围以交付报告为准。

清理工具先生成明确候选，只在安装摘要与数据核对通过后删除工程内旧构建。真实月表和历史核对资料先复制到私有归档并逐文件核对；仅删除有可核对备份且已迁入新工程的旧源码文件。认证目录、正式资料、版本历史及其他独立软件保留。
