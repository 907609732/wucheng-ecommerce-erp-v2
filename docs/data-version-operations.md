# 正式业务数据版本托管

本功能使用独立、需认证的 Unity Version Control 数据仓库。源码仓库与 GitHub Actions 只处理程序和合成测试，不携带正式账本、附件或凭据。启用前核对目标组织、仓库 ACL、容量、实际运行身份及恢复结果。

## 行为

一次成功业务事务生成一个事件；批量导入的整体事务只生成一条。预览、无变化与回滚不生成业务版本。主业务记录数量用于中文说明，审计和内部辅助行不重复计数。初次启用建立基线。

事务 COMMIT 前同步导出经过白名单过滤的业务表、恢复 schema 和所引用的原件/附件，并将事件写进同一业务事务。快照失败则业务事务回滚，不显示“已保存”。正式库仍是原有 SQLite；云端存储可恢复的业务逻辑快照，授权、会话、运行状态和历史备份不在导出范围。

附件通过摘要校验和不可变本地副本保留，重复版本使用内容寻址与硬链接节省空间。网络上传在保存后排队进行。只有查询或提交得到真实 changeset，软件才显示“已托管”和 `cs:N`。断网保留待提交事件，后台退避重试；失败队首先处理，避免旧快照后来覆盖新版本。

每个模块独立保证事务一致性；跨模块操作产生各自记录，不宣称三个 SQLite 是同一个原子事务。支持的浏览器、手机和后台入口通过模块存储捕获；任意外部 SQL、未安装保护的旧脚本会被保护触发器拒绝。独立脚本应通过受支持接口，或显式使用相同模块存储及版本目录；新增业务 schema 后调用 `refresh()` 并更新白名单。

## 配置与运行身份

在主机现有正式配置中增加（示例路径，实际以维护配置为准）：

```json
{
  "dataVersion": {
    "enabled": true,
    "dir": "E:/WuchengERP/data-version",
    "workspace": "E:/WuchengERP/data-version/workspace",
    "repository": "专用数据仓库@组织@cloud.cn",
    "cmPath": "C:/Program Files/PlasticSCM5/client/cm.exe",
    "uploadMode": "user-agent",
    "localHistoryCount": 10
  }
}
```

`dir` 不得包含或位于活动业务数据目录，`workspace` 必须为其内独立子目录。开发配置只允许使用其隔离 stateDir 内的版本目录。默认不启用，不自动连接正式账本。`localHistoryCount` 为每模块保留的最近已确认本地快照数，允许 1–1000，缺省 10；待提交或失败快照不清理。远端历史和本地事件元数据继续保留。共享附件 blob 暂不自动回收；监控磁盘余量，不手动删除待提交数据。

`host` 模式由 ERP 宿主上传，必须在实际宿主账户下验证 cm。LocalSystem 不会自动获得当前桌面用户的登录。

本机采用 `user-agent`：正式服务负责保存快照，已登录的 Windows 用户运行上传代理，复用该用户正常配置的官方 cm。用户退出登录或代理未启动时仍保留本地版本，云端提交等待下次代理运行；没有配置无人登录时的独立云端身份，不能宣称退出登录后仍上传。

```powershell
node server/data-version/agent.mjs --config E:/WuchengERP/config.json
```

运维启动入口应从稳定配置读取当前 releaseRoot，再运行该版本的 agent.mjs。可配置当前用户登录后自动隐藏启动，不复制凭据文件，不在启动脚本中保存密码。代理使用 OS 锁避免重复运行，上传器另有串行锁、命令租约及提交暂存清单。强制结束后，未结束的 cm 命令会阻止新命令重叠；无法确认旧命令退出时报告异常，先核实进程与清单，不直接删锁文件。

## 软件内查看

顶部选择“数据版本”。列表支持时间、模块、操作人和状态筛选；详情显示业务摘要、增改删数量、附件摘要、事件 ID、提交时间和真实版本号。首版提供业务操作摘要，不展示数据库整行或字段级前后对照。失败时可重试托管，不重复保存业务。

用户代理不运行时记录为等待托管；远端未确认不能视作机器外备份成功。原有维护备份继续保留。

## 从云端恢复到隔离目录

先在另一个专用 UVCS 工作区切到所需 changeset，下载该版本模块目录，例如 `purchase/`。不要对正在上传的生产 workspace 执行切换、回滚或手工编辑。

使用 Node.js 24.18 或更新版本运行恢复命令，目标必须不存在：

```powershell
node server/data-version/cli.mjs restore --event-dir E:/DataVersionRecovery/checkout/purchase --target E:/DataVersionRecovery/restored-purchase
```

恢复核验清单和文件 SHA-256、业务白名单、外键和序列；只写新目录，禁止附加外部数据库。业务路径保持模块所使用的数据相对路径，原件和附件随目录恢复。登录授权需按原运维流程重新配置。恢复后先在副本上打开模块并核对汇总，再另行执行正式恢复维护；软件页面不提供覆盖正式账本按钮。

## 停用与程序回退

保护触发器持久存在，直接运行不含该功能的旧程序会拒绝写入。回退必须先停止 ERP 和上传代理，备份当前账本与待提交版本，再使用当前版本执行：

```powershell
node server/data-version/cli.mjs disable --config E:/WuchengERP/config.json
```

该命令检查模块停止，移除本功能自己的保护触发器并关闭配置，保留历史。它明确记录“停用期间未逐次保护”；重新启用时建立新基线，不补造缺失期间的逐次版本。随后才切回旧程序。新版本配置关闭时会通过显式维护模式执行同样停用；未声明停用的外部脚本仍不会获得绕过保护的能力。

## 接入核对

1. 程序与正式账本分离；保留一致性维护备份与旧 releaseRoot。
2. 白名单与库内秘密审查；在正式副本上验证关键记录、汇总、附件恢复及保存耗时。
3. 目标私有仓库、授权成员和容量核验；在实际上传身份下用合成数据完成真实提交、查询、断点重试和远端恢复。
4. 源码推送，GitHub 检查及构建，下载并校验候选；不以本地测试替代云端构建。
5. 在管理员维护窗口更新正式服务并启用，启动全部模块建立三个正式基线；启动用户上传代理并配置登录自动启动。
6. 页面与 UVCS 核对实际基线及后续真实业务提交。没有新业务保存时，不伪造业务数据证明效果。

故障导致快照生成失败时不接受新的未保护业务写入。磁盘空间、云端容量或认证异常应及时处理，不能用清空待提交队列恢复表面正常。
