# 采购功能04：采集与可编辑表格

采购模块包含「采购采集」和「数据查看 / 表格」两个独立子页面。采集、日期选择、账号状态、预览入库与采集日志保持在采集页；数据页延迟加载本地 Univer 中文电子表格。

## 使用

1. 在采集页采集并确认入库。
2. 切换到数据页，首次载入会将原始采购明细加入工作簿，点击「保存表格」。
3. 双击单元格编辑；工具栏支持字体、颜色、数字格式、合并、排序、撤销/重做等基础操作。支持多工作表及公式，分析表预置实付款汇总公式。
4. 后续采集入库后，无未保存编辑时自动显示；采集页切回表格也会自动检查。若有未保存编辑，先保留草稿，点击「保存表格」后自动补入。仍可用「补入新采集 / 重新载入」手动刷新。新增来源按明细唯一键追加，不覆盖原来的编辑或手工补充行。
5. 「导出 Excel」包含当前内容（含未保存修改）、公式及基础格式。导出不等于保存工作簿。

请保留采购明细工作表，以及其第1行的16个来源字段名称。可以移动字段列；自动追加时按字段名称定位。改名、删除或重复表头会阻止新增数据追加，提示人工恢复，不猜测列位置。

## 数据与安全边界

- 编辑内容保存在同一 SQLite 中独立的 `purchase_workbook` 表，不修改 `purchase_lines` 和原始导出文件。两处金额可能因人工编辑而不同；采集页摘要始终反映原始记录，分析表汇总反映编辑后的工作簿。
- 显式保存；页面切换保留内存草稿，离开模块及关闭/刷新提供未保存提醒。不要通过强制结束进程代替正常关闭。
- 保存使用事务和版本号检查；其他窗口保存后，旧版本不会覆盖新版本。每次后续保存将前一版本保存在 `purchase_workbook_history`，目前未提供版本恢复界面。
- 客户端只读，服务器/单机可保存。无协同编辑或云端同步能力。
- 当前保护上限：最多20000条来源记录、12个工作表、每表50000行/200列、24MB工作簿 JSON。超过限制报错，不静默截断来源记录。
- 开源组件为 Univer 1.0.4 的 Core + Filter presets（Apache-2.0），没有接入 Pro 或付费服务。不是完整 WPS；不承诺宏、打印排版、透视表、图表或复杂 Excel 文件的完整往返兼容。导出器基于项目已有 ExcelJS。
- 所有表格 JS/CSS 打包在本机，无 CDN。iframe 隔离组件样式；只有该可信本地文档允许内联样式，禁止网络连接、子页面和外部对象。ERP 主页面保持原有严格 CSP。
- npm 安全检查未发现此次新增 Univer 依赖的已知告警；项目现有工具链仍有原有依赖告警，不在此变更内进行跨模块升级。

安装依赖后执行 `npm.cmd run build:purchase-sheet`。`npm.cmd run desktop`、`desktop:pack`、`desktop:build` 和 `desktop:publish` 的 npm 前置脚本都会重新构建表格资源。直接运行 Electron 前需手动构建一次。

- `npm.cmd run test:purchase-sheet-ui`：隔离测试资料中的 Electron 本地界面检查，不访问真实平台，不使用真实账号。
- `npm.cmd run test:desktop`：桌面基础回归。

### 采集后表格未刷新的修复

原因：已打开的 iframe 保留采集前的空工作簿，入库通知原先只提示手动补入，没有刷新工作簿。原始采购记录并未丢失。

入库通知及切回数据页现在会自动检查；没有手工编辑时刷新来源，有未保存编辑时保留草稿并在保存后自动补入。使用通知版本和编辑代数保护处理刷新中的重复通知及新编辑。加载追加数据后通过 Univer 的公共公式接口重算，不沿用旧汇总缓存。

源码及实际打包 EXE 的隔离窗口回归通过：空表采集后显示、可见表自动刷新、重复通知去重、未保存编辑保留、保存后补入、读取期间编辑保护，以及原有表格编辑/公式/筛选/保存/退出保护。采购10项、桌面35项基础回归通过。
