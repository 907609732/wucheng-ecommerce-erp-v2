# 三合一工作台：UI 实施规格

依据已交付产品契约与 UX 规格。本文件为实施设计，不是完成或验收证明；现有业务页、账本、真实 DeepSeek 配置和通用 Loading 保留。

## 第 1 页：统一外壳与六种状态

沿用 `agent-workspace.css` 的白色界面、蓝色主操作、细边框及现有图标。色值：正文 `#18334a`、背景 `#f4f7fb`、主色 `#177dc0`、次要文字 `#637c90`、边框 `#dbe5ef`、选中导航 `#e7f2fc`。只保留原生业务自己的数据视觉，不额外制作假数据指标。

顶栏继续显示品牌、测试账本、真实登录人和连接状态。主导航为「业务工作台 / AI 任务 / 任务历史 / 技能与提示词 / 设置」。沿用 176px 侧栏；业务模式主区域取消 1600px 居中上限，内边距 16px，工作面尽量占满。小标题 17px、正文 14px、辅助 12px；按钮高 38px、圆角 8px。品牌副标题改为「业务与 AI，在同一个工作台」。

| 状态 | 可见布局与操作 |
| --- | --- |
| ① 经营默认态 | 主导航选中业务工作台；上方 48px 工具栏含「经营 / 采购 / 销售」台签、「更多业务」、「交给 AI」。下方真实经营页面占主要空间。台签当前态使用浅蓝底及蓝色下沿，不能只靠颜色区分；云仓、订单导出保留在更多业务。 |
| ② 采购录单 + AI | 左侧真实采购表单完整可操作；顶部采购台签可带「未保存」文字。满足宽度条件时，右侧 360px AI 栏，与业务区间距 16px。AI 栏依次为范围条、目标输入、Skill 选择、任务动态、结果摘要及「展开任务空间」。不另造外层「新增采购单」按钮，复用原采购操作。 |
| ③ 窄窗切换 | 宽度不足容纳业务 760px + AI 360px 时，不挤压采购单；隐藏业务原生视图并显示完整 AI 页面。顶部始终提供「← 返回采购」，返回复用原视图与表单。≤640px 主导航可横向滚动，文字不省略；业务台签允许横向滚动。桌面最小窗口仍按现有设置，窄屏仅作为响应式布局支持，不虚称已修改最小窗口。 |
| ④ 草稿保护 | 普通切台不弹窗。刷新、重连或会改变同台路由时，先隐藏原生视图，再显示草稿对话框：标题「采购单尚未保存」，说明即将发生的动作；主操作「继续填写」，次操作「保存本地草稿并继续」，危险操作「放弃草稿并继续」。未接草稿保存时不显示可点击的假按钮，只提供继续填写和明确放弃；不把浏览器内存状态称为持久草稿。 |
| ⑤ 结果定位 | AI 结果中每条受控来源显示「在采购中查看」等文字操作，并显示期间、口径和真实编号。进入来源后外层有细条「来自 AI 任务 · 返回结果」，不遮盖表头。来源不存在/版本变化以原位状态说明，不能指向猜测记录。已回读的新数据用「数据已更新，可刷新看板」提示，不自动刷新采购表单。 |
| ⑥ Skill 版本编辑 / 运行 | 左侧用途列表，右侧详情或编辑。列表显示名称、模块/平台、版本、内置/自定义及可用状态。详情含用途、所需输入、步骤、工具绑定、提示词和输出要求；「复制并定制」「试运行」为主操作。编辑在明确标题下保存「新版本」，附变更说明；版本历史列作者、时间和说明。运行页先显示范围与固定版本，再开始任务。 |

## 第 2 页：组件、真实布局与实施约定

业务容器 `#business-surface` 只作为 WebContentsView 的测量区域，不使用 iframe 或外窗。业务模式保持外壳固定，下方容器独立占据余下高度；使用实际 `getBoundingClientRect()` 的 x/y/width/height，不写死顶栏偏移。≥1360px 且实际业务剩余宽≥760px 才显示 360px AI 栏，其余切完整 AI 页。窗口、缩放、导航及侧栏变化后重测；0 尺寸先隐藏，不能用 100px 最小占位盖住外层。

切台开始隐藏旧视图，工具栏保留目标台签并用现有 `loadingMarkup()` 显示加载进度；实际新页面就绪后再显现。失败保留当前目标和真实错误，提供「重试」及「返回上一工作台」，不退回假成功页。切换 AI、设置、技能页前必须等待 `hide()`；外层对话框同样先隐藏原生视图，关闭后校验仍为同一账本、连接、模块才恢复。外层浮层不依靠 z-index 盖原生页面。

AI 范围条用可展开的文本块，不铺满胶囊：例如「采购 · 2026-10 · 当前筛选 · 12 条已保存记录」。无法取得真实筛选或记录数时显示「范围未确认」并要求补齐，不能假写「全部」。草稿只能在用户主动操作后传入。Skill 选择只列启用版本，运行任务展示名称、版本和摘要；禁用、待开通及缺少绑定能力均明确原因。未验证版本用「待验证 / 试运行」，不能仅由模型回复将状态改为已验证。

技能页使用现有表单控件、`.settings-card` 与结构化结果组件：≥1100px 列表宽 280px、详情其余；较窄时改为列表→详情的同页返回，不压缩提示词编辑区。长提示词用等宽可选文本区，高度至少 240px；保存只经真实持久化 API。只有持久化成功才显示版本与「已保存」；失败保留编辑内容并显示错误。导入先显示文件校验与差异，导出使用真实保存能力；后台契约未接时明确待接入，不用 localStorage 冒充公司技能库。

所有台签、更多业务、版本列表及返回操作支持键盘和可见焦点；台签使用 `tablist/tab/tabpanel` 与 `aria-selected`，可用方向键切换但不自动丢弃输入。加载区使用通用进度条和状态文案，禁止新增转圈。错误可读、可关闭，不能闪退；变更成功使用非阻塞状态提示。先不改旧业务页内侧栏和品牌，作为阶段 1 的已知重复；后续统一不能误删原功能。

开发边界：UI 负责新外壳与入口、真实 bounds 和隐藏恢复、技能/提示词页面；主机组负责打开入口共同身份/连接/Beta 校验及 4 维 bounds；领域组负责草稿状态/保存、真实页面上下文、受控来源定位和人工写审计。实时同步补丁先由总控集成，再给 UI 新基线。完成所有接线后集中核对六态、人工录单、AI 回读、切台草稿和包体原生边界；设计文档与静态 DOM 不能替代这些证据。
