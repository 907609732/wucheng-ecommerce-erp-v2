# 验收规则

## 分层入口

| 命令 | 用途 | 可复用的结果 |
|---|---|---|
| `verify:quick` | 按改动影响运行 Node 单元与接口测试；共享宿主变动覆盖全部组 | 仅明确输入相同的本地测试任务 |
| `verify:integration` | 全量本地测试，再串行执行现有真实源码桌面夹具 | 不缓存界面和运行集成结果 |
| `verify:release` | 冻结安装器摘要检查、全量测试与安装/升级/恢复/界面/CLI/MCP证据核对 | 不缓存发版结论 |

本地合成账本、真实平台、真实安装、发布可达性分别记录。某项缺少证据、失败或跳过时不能变成“全部通过”。界面验收不能只等待窗口或空白外壳，必须等待对应模块内容和就绪状态。

每轮报告包含源码身份、开始时间、每阶段耗时、退出码、缓存摘要、失败原因和证据路径。源码或安装器摘要变化后旧候选报告失效。运行记录存 `.codex-artifacts/engineering`，不再每轮新增一篇 docs 文档。

## 性能对比

同机同输入至少三轮取中位数，分别记录冷构建、缓存构建、快速验收、首次准备和已准备模块的正常重启。增量构建、快速验收和正常重启目标各降低至少 50%；首次网络下载单独列出，不混入启动提速。达不到时报告实际结果与瓶颈，不能减少必要覆盖或跳过路径、签名和摘要保护。

基线以实际测量为准。历史“跳过激活后的首屏”不能当正常启动基线。预览测试必须使用临时 LOCALAPPDATA 和合成账本；不得修改正式预览账本或正式业务目录。

## 必测故障

断网、中断续传、取消重试、忽略 Range 的服务器、异常 Content-Range、损坏归档、错误签名、版本不兼容、路径重定向、磁盘不足、激活失败及回滚。已有可用版本与账本必须保留。文档改动不重建业务，单模块改动只使相关任务失效；共享依赖变动使全部受影响任务失效。

发版还需同一候选完成全新安装、升级和恢复检查、五模块真实界面、合成账本读写、MCP握手/CLI查询及 GitHub 资产可达性。未发布的新下载地址不能伪称已验收；本轮不自动发布。
