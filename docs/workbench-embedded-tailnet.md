# 工作台内置私网连接

## 使用方式

0.10.0 候选版在客户端设置中新增“内置私网连接”。填写主服务器原有的 Tailscale HTTPS 8443 地址，点击“登录私网”，在 Tailscale 官方页面完成自己的账号授权。授权完成后工作台核对设备状态、主服务器身份、成员权限和账本身份。后续启动使用同一登录状态自动连接。

原有“现有 Tailscale 客户端”连接方式继续保留。主服务器仍使用系统 Tailscale Serve，原采购手机端 HTTPS 443 及现有 8443 入口保留。此版本不改 FlClash 的系统代理、DNS、TUN 或公网节点。网络不通时不能推断账本为空，也不自动切换到本机账本或公网。

内置连接会登记一台新的 Tailscale 设备。现网已按明确设备收紧 TCP 8443，新设备必须经过管理员核对后获得相应权限。已有系统 Tailscale 设备的授权不会自动复制给新设备。独立成员身份及应用内模块角色仍需分别配置；同账号的多台设备不能替代独立成员验收。

## 实现边界

0.10.1 增加首页及设置页的常驻连接状态，每 10 秒自动检查并显示最近检查时间。主服务器分别核对本机网关及私网 HTTPS 的原账本身份；客户端复用专用会话进行带身份的只读请求。该状态不以选择的模式或缓存的登录标记代替实际检查。检查不会修改 Serve、授权或系统代理，不会在暂停后自动登录。当前本机系统 Tailscale 为 NoState 时，界面已实机显示“主服务器未就绪”；历史 CQH 连通记录不能代替当前主机可用性。

- 使用 [Tailscale 官方 tsnet](https://tailscale.com/docs/features/tsnet) 1.104.2，Windows x64 Go 辅助进程，客户端无需安装 Go 或 Node 开发环境。系统 Go 1.27.3 仅用于构建。
- GUI、CLI、MCP 复用相同物理配置目录中的一个后台代理。父工作台退出后代理可继续运行。代理凭据通过 Windows 当前用户安全存储加密，进程之间通过经挑战验证的本机接口复用，凭据不进入命令行或渲染页面。
- 业务页面保持原 HTTPS 地址、证书验证、Secure/HttpOnly Cookie、CSRF、真实操作人和账本 UUID 绑定。Electron 专用 Session 使用经过认证的回环 CONNECT 代理；代理只允许所配置的完整主机名及 8443 端口，不提供通用转发或公网回退。
- 用户态域名解析使用 Tailnet 节点信息及官方 DNS 查询接口，只接受 Tailscale 私网地址，不回退到操作系统 DNS。
- 首次授权只打开经过完整校验的 Tailscale 官方登录地址，授权、验证码和管理员确认由用户完成。不内置共享密钥、不自动填写登录凭据。
- 配置、账号或账本变化时丢弃过期响应，禁止将旧 Cookie 发送到新服务器。退出账号先持久暂停自动连接，关闭业务视图、清除会话 Cookie 并锁定离线快照；账号注销尚未确认时明确报错，不宣称已注销。退出失败后，重启或状态轮询都不能自动恢复访问，须明确重新连接或完成退出。模块账本变化只在重新核对原模块身份后解除对应缓存锁。
- 自动更新安装前检查本机请求与业务写入，关闭专用会话并停止可验证的本配置连接进程，释放安装文件。身份不明的进程阻止更新；不按端口猜测进程或结束其他软件。主服务器独立业务后台继续运行。

## 构建与验证

Go 源码位于 `network/tailnet/`。构建资源在 `dist/tailnet-runtime/`，仅包含 EXE、固定版本清单、NOTICE 和生产依赖许可证。构建与打包均校验字节长度、SHA-256、平台及协议；不分发设备状态、DPAPI 文件、登录地址、账本或个人配置。

分层验证包括 Go 单元测试和 Windows DPAPI/独占锁、实际 Go 进程的惰性 init/status/EOF、跨父进程复用、Electron 请求绑定代理认证、页面/请求/下载共用会话、配置竞态和缓存隔离。隔离 HTTPS 测试使用专用测试证书和仅测试进程的证书开关，正式工作台不增加证书例外。

惰性测试不调用 Start/login，不注册真实设备；它们不能证明真实 Tailnet 已登录或 CQH 已连接。真实登录、新设备权限差异、双机读写、独立成员、原手机端、平台采集及正式迁移另记验收结果，不能以隔离测试代替。

## CQH 实机连接补记（2026-10-25）

用户完成官方登录及本次设备/权限确认后，内置节点已批准。保存并重新读取的现网规则与审核拟稿一致；主机实际双栈过滤仅向该新节点开放 TCP 8443，原 443 手机入口、既有规则和 Serve 目标未改，无 Funnel。旧 CQH 系统节点的较宽既有权限仍保留，不能把新节点边界描述为整台电脑的权限范围。

CQH 的 0.10.0 安装版已实际使用“内置私网连接”通过身份检查，并打开五个模块读取主机原有数据。关闭工作台、从原桌面快捷方式重开后自动恢复连接，无需再次登录。主机及五模块账本身份与原基准一致。本轮未采集、发送、导入、迁移或写入测试业务记录；独立成员与真实写入验收仍待完成。见 [CQH 内置连接记录](../dist/module-verification/workbench-cqh-embedded-0.10.0.json) 和 [实际生效权限记录](../dist/module-verification/workbench-embedded-network-effective-2026-10-25.json)。
