# 人力支出年度表与看板实施计划

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 人力支出默认当年，左侧固定1—12月；模块顶部切换工资表和人力看板。

**Architecture:** 复用 Tabulator、Chart.js、现有工资与付款数据。年度工资在一次事务中跨月保存，保留请求幂等、版本冲突和审计；不创建付款。

**Tech Stack:** 原生 JavaScript、Node、SQLite、Tabulator、Chart.js；无新增依赖。

**Spec:** 用户2026-11-04本轮要求及下述边界。

## 边界

- 只改源码开发版，不打包、不切换正式服务，保留当前未提交工作。
- 每月默认一行、至少两组人员栏；同人同月多笔保留额外行，不合并账单。
- 年度新录工资日期默认对应月末；已有工资保留原日期和账期。空月份不产生工资。
- 看板按账期统计应付（包含公司承担），按实际付款日期统计净付款；待付为所选年度账单当前余额。缺失月份标为未录入。
- 顶部切换和切年受草稿/保存状态保护；退出视图销毁图表与表格。

## 实施和验证

- [x] 年度模型测试：12月固定行、闰年、历史日期、重复姓名/月份、无空工资；实现模型。
- [x] 保存测试：跨月同事务、越年拒绝、回执重试、旧版本冲突、月度兼容；实现年度接口输入。
- [x] 看板模型测试：应付/实际支付分属不同期间、退款/作废、跨年付款、复杂工资不重复；实现看板和顶部切换。
- [x] 源码开发浏览器验证：默认当年、全年录入、加人保留草稿、切换保护、保存/刷新、看板、窄屏和往返切换。
- [x] 针对性检查、独立代码审查、更新验收文档；打开开发页面交付。

## Review Focus

- 跨年付款不得误算为账期实付。
- 修改年度工资不得迁移原有账期和日期。
- 一笔版本冲突必须回滚整个年度请求。
- 月份占位行不能造成未保存提示或新增空账单。
- 看板切换、切年与重新进入均不丢草稿、不重复绑定事件。
