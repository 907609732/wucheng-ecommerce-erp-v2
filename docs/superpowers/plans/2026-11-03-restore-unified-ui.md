# 恢复浏览器三台统一 UI 与期间选择器

恢复来源：归档分支 codex/business-runtime-slimming 的 f8aaae6，以及 refs/stash e0cc5e7 的已跟踪改动。当前浏览器版本未合入共享 ui 层，造成样式和期间控件不一致。本次恢复既有设计，不重新设计业务页面。

1. 先恢复旧版期间工具测试并确认当前缺失共享组件导致失败。
2. 从共同基线 a995314 到归档 stash 提取三个 public 目录、ui 层及 UI 同步脚本的差异，用三方应用保留浏览器化的独立改动；逐项处理冲突。不得恢复 Electron、导出器或后台采集自动启动。
3. 将共享同步目标限制为采购、销售、经营总览，加入统一检查命令和发布源码清单，加载资源的唯一来源仍保留 shared/ui。
4. 运行期间校验、共享资源一致性及相关模块回归。在仓库外使用已有运行依赖和复制账本建立浏览器预览，避免给刚清理的源代码工作区重新填入依赖、数据和截图。
5. 用本地浏览器检查三台期间选择、跨年切换、单次触发、键盘和弹层布局，验证业务查询未改变。完成独立审查后再准备正式版本切换；程序更新不回退账本。

验收范围为三个业务台的统计期间、筛选、任务月份和确认月份。业务单据上的实际发生日期保留日期语义；独立云仓和订单导出不在本次范围。
