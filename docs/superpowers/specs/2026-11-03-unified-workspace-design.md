# 三个业务台的结构与时间交互统一（已确认）

## 目标

采购、销售、经营总览使用同一页面骨架和内容边界。统计时间采用用户截图的「日 / 月 / 年」分段交互，复用现有共享期间选择器。保持账本、业务规则与正式服务独立，先在隔离环境验收。

## 当前问题

- 共享 components.css 重复定义骨架，写死的 222px 侧栏、74px 页头覆盖响应式变量。
- 销售运营/设置页为主区域额外加宽度与 padding，与共享正文 padding 叠加。
- 经营总览 main 另有 1640px 和 34px/38px padding，时间组件放在页头；销售在正文上方，采购又在内容内。
- 期间组件虽共享代码，但快捷月份条、粒度隐藏规则、位置与大小不一致。

## 建议方案

直接归一现有 HTML/CSS 与共享组件；不重写业务、不换框架、不新增运行依赖。相比只叠加 CSS，此方案清理冲突来源，避免后续页面再次漂移；相比重建全站，变更集中在现有布局契约。

1. 侧栏宽度、页头高度统一引用 tokens，保留当前 222/180/74px 的响应式侧栏与 74/60px 页头。
2. 主内容区域使用全部可用宽度、统一响应式左右留白（桌面 40px、中屏 24px、小屏 16px）；标题、筛选、卡片、表格与页脚共用同一边界，去除模块额外套的 max-width/padding。
3. 三个模块统一「侧栏 + 页头标题 + 筛选行 + 业务正文」。统计时间位于筛选行左侧，店铺/类别跟随，刷新等操作位于右侧；窄屏自然换行。
4. 时间交互统一为「日 / 月 / 年」分段按钮 + 上一期/期间按钮/下一期。点期间按钮打开同款选择弹层；选择一次仅触发一次查询；去掉额外的全年/12个月快捷条。
5. 用户已确认：只支持月度的业务显示日/月/年并禁用不支持项、标注原因。不增加后端不支持的统计粒度。
6. 实际发生日期、付款日期、任务截止日等录入字段保持日期输入语义，不把它们改成统计粒度选择器。起止范围保留范围语义。

## 验收

- 在相同窗口尺寸逐模块对比侧栏、页头、筛选与正文的实际边界；检查 1920、1440、1024、375px。
- 页面主体不横向溢出；宽表格在自身容器横向滚动。
- 所有统计期间入口使用同款分段/期间弹层；不支持粒度不能触发无效请求。
- 键盘、焦点、清空、跨年、期间记忆、未保存草稿保护不退化。
- 连续切换业务台、菜单与期间，检查加载完成、错误与请求次数；此前卡顿报告仍作为待复现问题，不以样式统一宣称已经修复。
- 合成/复制数据验收后才准备正式候选版本；运行证据与依赖留在工作区外。

## 已确认

- 用户于2026-11-03确认按推荐方式统一，月度页面显示禁用的日/年。
- 保留原有后端支持粒度与数据规则。
