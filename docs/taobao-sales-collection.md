# 淘宝店铺销售额采集：下载流程与技术原理

本文由 desktop/renderer/feature-help-content.js 生成，与软件右上角的说明书 / 技术原理共用内容源。维护时修改该文件，再运行 npm run docs:features。平台步骤来自用户截图，实现说明来自当前源码；不代表真实平台自动下载已经验收。

## 店铺销售额采集

本次淘宝取数按用户截图中的收入账单 → 月汇总 → 导出 Excel 执行。先保存本店本月原表，再核对收入、退款和净额；不要求为了采集销售额先下载支出或涉税账单。

### 说明书

#### 添加店铺：先登录，再读取信息

1. 点击「添加店铺」直接打开独立千牛登录窗口，不先填写主体、税号或申报设置。请本人扫码或输入账号完成登录；程序不代填密码或绕过验证码。
2. 登录后只读当前店铺身份区域明确提供的店铺名称、账号、店铺 ID、主体或税号。同页订单卡片、网格及交易对方资料不回填；来源无法确认时保持未知，不为补齐资料调用未知接口或点击设置。
3. 核对小窗口中的店铺与账号，点击「确认添加」。后台未显示店名时只需补充店铺名称；未读取到账号或店铺 ID 时不能确认，继续登录或点击重新读取。
4. 未读取到的主体、税号、纳税类型保持待确认，可在店铺设置稍后补充，不阻碍销售额文件归集。默认不开启定时任务，添加不会下载账单或提交申报。
5. 取消添加或关闭登录窗口不保存占位店铺，读取时关窗不会自动重开。取消清理临时登录会话，清理失败提示重试而不虚报完成；保存期间账号 / 店铺变化停止添加，重复店铺选择原记录，不覆盖旧设置。

#### 淘宝销售额下载流程（按框选位置）

1. 登录自己的千牛 / 淘宝商家后台，核对当前店铺名称与账号。多店铺要逐店操作，不以浏览器标签昵称代替店铺确认。
2. 左侧进入「财务 → 对账管理 → 收支账单」。
3. 顶部选择「收入账单」，再选「月汇总」；本流程不是日汇总、收入明细或涉税信息报送账单。
4. 选择「月份」起止范围；单月采集时起始月份和结束月份设为同一个目标月份。
5. 账单类型选择截图所示「货款收入」，业务大类先用「全部」。这是本流程的默认范围；积分奖励及其他收入如需采集，要另行确认并单独留档，不偷偷混入货款收入。
6. 点击「查询」，等待本月结果加载，核对月份、币种、业务大类、收入金额合计及退款金额合计。查询失败或账单未生成不能记为零。
7. 点击你框出的「导出 Excel」下载月汇总表，不使用「导出 PDF」或行内「下载全量明细」替代本流程。
8. 如果平台转到生成任务，进入「历史下载记录」，核对店铺、查询范围、账单类型和生成状态，待成功后下载。只有实际文件落地且可打开才算下载完成。
9. 保持原表内容不变，可将文件另存命名为「店铺名_YYYY-MM_收入账单_月汇总.xlsx」，按店铺 / 月份归档；记录下载时间与查询条件。

#### 下载后在 ERP 中归集

1. 进入「店铺销售额采集 → 添加店铺」，先登录再读取信息，核对后确认添加；店铺设置改为后续可选步骤。选择与导出文件一致的账期。
2. 点击「导入账单」选择原始 Excel；账单类型选「收入账单」，选择实际工作表、首末数据行。排除表头及整表合计行；不要把月汇总与日汇总 / 明细叠加。
3. 按真实列名映射账期、收入总额、退款金额和收入净额。截图只证明页面字段，Excel 列名和日期格式需拿到真实原表后核对；不要猜列号。
4. 点击「预览核对」，将本月收入与退款分别同后台查询结果对比。缺失字段、无法识别月份或金额差异先处理，未核对完不要确认。
5. 范围和金额确认后勾选完整账单确认，再「确认并入账」。保留原文件和旧版本，不把点击下载当成自动入账。

#### 金额口径与去重

> 注意：以下边界必须在操作前核对。

- 本功能把月汇总的货款收入用作店铺账单收入统计，不能直接当成下单成交额、支付成交额、利润或不含税申报销售额。
- 收入总额、退款金额分别保留。没有净额列且两者齐全时，现有账本计算净额 = 收入总额 − 退款金额；缺失值不是零。
- 同一月份同一业务的月汇总、日汇总和明细只选一种计入金额。具体业务分片可以核对后合并，但「全部」不能再与它包含的子类型叠加。
- 支出、平台费用与涉税报送有其他口径，销售额采集不默认扣费或套税率。填表草稿是另一个可选流程，不代表正式申报。

#### 常见问题与当前边界

- 截图公告写有每月 8 日生成上月账单、单次导出 50,000 条限制；这是截图所示说明，当前平台实际限制以页面为准。失败时缩小查询范围，并确认拆分文件不重复、不遗漏。
- 在已安装的千牛中下载的文件不会自动传给 ERP，请使用导入账单。ERP 独立窗口也不自动复用原生千牛的登录态；首次需要本人登录。确认添加后保留该店铺独立分区，按平台允许的期限持久保存登录态，不修改 Cookie 有效期；过期后仍需本人登录。
- 立即取账 / 定时取账仍是现有多类型账单编排，本次没有把它改成已验收的“只取货款收入月汇总”自动流程。真实千牛自动下载尚未完成验证，当前可靠路径是人工导出后导入核对。
- 登录失效、验证码、店铺不符、月份不符、下载报错、文件损坏时停止并人工处理。不能绕过验证、自动认定零销售额或自动申报。

### 技术原理

#### 登录优先添加店铺

- 主进程 FinanceShopOnboarding 创建临时 UUID 和独立 Electron 会话分区，打开千牛账单地址；renderer 周期调用受主窗口权限保护的只读身份 IPC，不启动取账任务。
- finance-identity 只接受可靠当前店铺身份区域的明确字段或可信账号昵称 Cookie；不接受交易对方、普通页面标签、订单卡片、商品名、标题或登录表单输入。不同来源冲突时停止确认，不能用账号昵称猜店名。
- 确认时重新读取身份，保存阶段持续保护身份版本；导航、账号变化、关窗或主体 / 税号变化需重新核对，不绑定已变化的会话。店铺 ID 沿用临时分区 UUID；失败仅处理本次未完成的新记录，不删除既存店铺。取消清理失败可重试。
- 未提供的主体、税号、主体类型、纳税人类型及申报周期保留待确认。新店计划默认关闭，身份识别的本地仿真测试不替代真实千牛页面验收。

#### 数据链路与页面来源

- 平台查询条件 → 千牛生成原始 Excel → 本地保存 → ERP 导入 / 待核对 → 字段映射与预览 → 人工确认 → 独立账本及版本记录。平台原表是数据源，不用截图数字填账。
- 入口地址与用户截图及现有 FINANCE_URL 一致：https://qn.taobao.com/home.htm/whale-accountant/bill/summary?billDirection=income&billType=month
- 文档中的按钮路径来自用户提供的截图，不代表已经读取真实后台 DOM 或验证真实导出文件结构。

#### 文件解析、金额与追溯

- renderer 的 inventoryApp 调用主进程财务 IPC；finance-worker / finance-jobs 执行解析、预览和查询，FinanceLedger 管理 SQLite。金额转成整数分保存，展示 / 导出时转回元，避免浮点累加误差。
- 原文件通过 SHA-256 哈希留档，源单元格、原公式和缓存值保留；同店同月同类完整版本更新时保留旧版本，可在取账记录恢复。
- 导入先预览再确认，不自动猜测真实列名和账期；公式缺缓存、跨月、无法识别金额和净额差异作为核对事项，缺值不补零。
- 文件和数据库在应用 userData/workspace/finance 下：finance.sqlite、originals，以及下载 / 待处理目录。本模块不读取或复制运营看板的 business_* 历史金额。

#### 下载与自动化原理

- 现有自动化使用 Electron BrowserWindow 与每店独立会话分区，通过页面快照和语义匹配识别账号、月份、账单分类及导出入口，不靠固定截图坐标。
- Electron 下载 completed 事件后还要检查文件头、大小、来源任务关联；收到文件只表示下载落地，不等于账期完整、已入账或已申报。
- 计划按每店设置在北京时间每月 15 日 09:00 检查到期；依赖电脑和进程运行。登录、验证码或页面不匹配转人工，不能承诺关机后执行。

#### 本次已做 / 尚未做

> 注意：以下边界必须在操作前核对。
