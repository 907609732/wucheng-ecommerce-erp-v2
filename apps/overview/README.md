# 灵兔经营收支总览

双击 **启动灵兔经营收支总览.cmd**，打开 <http://127.0.0.1:17890>。首次安装运行 `npm.cmd ci`；环境要求 Node.js 24 或更新版本。当前电脑已安装。

销售台、采购台继续在各自入口维护。本应用只读两个源账本，独立保存费用、付款和月报；不运行源应用的初始化、迁移或写入逻辑。不会上传财务数据或启用公开访问。

## 日常使用

1. **经营看板**：右上角切换年度 / 月度，选择年份或月份。年度显示 1—12 月收支折线、月份覆盖状态；月度显示每日折线。另有支出分类、店铺入账对比和期间数据表。点击月份进入月度看板，点击日期查看当天参考差额明细；分类柱、店铺柱及主卡片可追溯来源。图例可开关曲线。未录入项目显示“待补”，缺失日期保持断线。
2. **运费账单 / 其他费用**：两个独立入口。运费按月份和店铺登记，支持进货运输、销售发货、退货运输、云仓及多家物流公司；其他费用用于软件、房租、报销等。均支持表格导入和手工登记。
3. **人力支出**：登记外部已经算好的工资表，不自动算薪。每人保留应发、个人代扣、实发及公司承担。应付合计 = 应发 + 公司承担；实发 = 应发 − 代扣。可分别登记实发、代扣缴付和公司承担的付款。
4. **付款 / 退款**：账单登记不会自动变成付款。点击账单登记日期、金额、唯一流水号；支持分次付款及退款，错误付款可填写原因撤销。退款不能早于足额付款或超过已付金额。退款冲减净实付并重新增加待付；如整笔费用已取消，完成退款后作废账单。
5. **待补数据**：补日期、核对未知流水用途、填写月度完整性依据。明确核对当月没有某类费用后才标为零。确认后数据变化，标为“待复核”。
6. **月报快照**：保存当时的数字、来源版本和缺项；后续变化不会覆盖历史，旧快照可下载 Excel。存在缺项时仍可保存带缺项的快照，不代表正式财务结账。
7. **备份与记录**：下载完整 ZIP，或将 ZIP 恢复为独立副本；最近 200 条操作可在界面查看，数据库保留全部审计。

## 运费的表格维护

1. 进入“运费账单”，在店铺表上方选择月份。未录店铺点“填写”，默认只需输入物流公司和运费金额；店铺、月份自动带入，默认销售发货，账单日期默认所选月末，账单号自动生成。用途、日期、账单号、备注和关联来源可展开“更多信息”修改；有账单的店铺点“查看账单”就地展开，再点账单查看详情、付款或更正，点“再添加一张”可录同店铺另一张账单。
2. 批量填写时，在右上“导出 Excel”中选择“下载空白填写表”：自动预填月份、账单编号及销售台的店铺，公司共用单列；选定店铺时只下载该店铺。
3. 在 Excel 填写物流公司、用途和应付金额。一个月同一店铺可有多张账单；新增另一张请使用不同账单编号。未填写物流公司和金额的空白模板行自动略过。
4. 维护已有账单时，展开“筛选”选择店铺、关键词或所有月份，再用“导出 Excel → 导出已有账单”。修改蓝色可编辑列，保留记录 ID 和记录版本，填写更正原因。多条明细共用同一个记录 ID；汇总金额须与明细合计一致。
5. 使用“导入 Excel”，选择文件后“预览表格”。默认第一张表、第一行表头，其他设置可展开调整；字段映射默认收起，可展开核对。预览新增、更正、重复和冲突，更正展示金额、字段及明细变化；旧版本或重复身份冲突须核对后重新导出。确认后保存原件、来源行号和前后记录。删除表格中的账单行不会作废系统账单；要复制为新账单，请清空记录 ID / 版本并使用新的账单编号。
6. 表格中的累计实付和待付为只读参考，修改它们不会登记付款。账单导入后仍需单独登记实际付款 / 退款。运费列表的累计实付包含该账单所有付款日期，经营看板按实际付款日期归月，二者用途不同。

未录账单的店铺显示“待录”；明确确认当月没有运费，仍在“待补数据”中登记依据。

## 导入与避免重复

- 支持 XLSX、UTF-8/GB18030 CSV，25 MB、20,000 行以内。可选择工作表、表头行、备用账期并调整字段映射；旧 XLS 请先另存为 XLSX。
- `选择文件 → 字段映射 → 预览及核对 → 确认入账`。预览只保存在进程内，过期或关闭后释放；确认后保存原始文件字节、源行号、导入批次与审计。
- 运费使用“所属月份 + 店铺 + 物流公司 + 账单编号”识别一张账单，其他类型使用“类型 + 收款单位/人员 + 账单编号”。明细用不同编号；汇总行填“汇总”，运单/人员行填“明细”。汇总与明细并存时只计明细，合计不符阻止入库。完全相同账单跳过；普通新增导入遇到内容冲突时阻止保存，运费更正通过带记录 ID / 版本的维护表明确回导，不静默覆盖。
- 一张工资表可用公司薪资部门作收款单位，每个员工占一个明细；也可每员工单独一张账单。分明细追踪逐人付款时使用后者。付款目前关联账单，不做员工逐笔核销。
- 付款流水号全局唯一。同一银行转账付多张账单时，使用“真实流水号/账单编号”作为各分配付款的唯一编号，并在备注说明分配；各金额须自行核对到真实转账总额。
- 采购实付已含订单运费，额外物流才新增一张费用账单。平台费用已经进入平台流水的，用“关联已有支出”搜索并关联；关联付款保留展示，不再扣差额。
- 报销关联采购单，同一来源只能关联一张费用账单。关联被源台账排除后会出现待核对，不自动切换统计规则。
- 通过单笔新增和编辑可调整明细、归属及备注；所有更正保留原因和前后值。账单有有效付款时不能更改类型或关联来源。

## 统计口径

- **参考差额**：已识别的平台业务入账、退款与费用的带符号合计，加采购和额外实付的带符号合计。销售按账单发生日期，采购优先付款日，额外支出按实际付款日；未付账单另外列示，不混入实付。
- **年 / 月看板**：年度金额按日历年的发生日期汇总，等于各月已录金额合计；待付款取所选年 12 月末余额，不将每月余额相加。月度保持按月末余额。当前年度也展示完整 12 个月，未来无数据月份显示“未到期”，不预测收入费用。已录的未来日期记录仍按原日期显示。
- **图表与导出**：折线包含已录业务入账、已录支出净额、已录参考差额。支出净额包含交易退款、平台费用、采购及额外实付，并冲减已归期的费用退款；正值为净支出、负值为净退款。资金往来不参与。店铺对比是平台业务入账，不代表银行到账或利润。日趋势只有对应类别已确认录全且日期已到，才将无流水日显示为零。导出包含相同期间的趋势表、汇总、明细与缺项；明细筛选保留日期、店铺及搜索条件。快照仍按月保存。
- 囤货采购全部进入这一版支出参考，未做已售成本、库存或资产折旧，不能据此判断完整经营利润。
- 提现、营销账户转账、保证金划转单列；营销实际消耗须有账单，不把充值当费用。未识别代码、没有明确含义的净结算留待核对。
- 采购沿用“已完成 / 待发货 / 待收货 + 未手动排除”的规则。分类拆分只分配整单金额。缺付款日期时显示暂估数量和金额；累计退款没有日期时不倒扣到原采购月份，在总览补充实际退款日后再归月。
- 源销售台的锁定月使用其锁定快照。来源整月覆盖、实际到账缺口与总览中的人工完整性确认分别显示，不互相替代。
- 当前只合计人民币。外币保留原值进入待核对，不猜测汇率。店铺/公司归属仅作直接归集，不自动分摊共用费用。
- 源库缺失或读取错误时总览明确报错，汇总金额留空，并阻止月报导出/快照；不会创建空源库。来源重新可用后刷新恢复。

## 数据、环境与恢复

新增数据位于 `data/overview.sqlite`；`data/originals/` 为费用导入原件，`data/backups/` 为完整备份。源账本及原件继续由原应用保管，需分别备份。

环境变量均可选：

| 变量 | 默认值 |
|---|---|
| `OVERVIEW_PORT` | `17890`，仅监听 `127.0.0.1` |
| `OVERVIEW_DATA_DIR` | 本项目 `data` 目录 |
| `OVERVIEW_PURCHASE_DB` | 上一级采购台 `data/purchases.sqlite` |
| `OVERVIEW_SALES_DB` | 同级销售台 `data/sales.sqlite` |

备份通过 SQLite 在线备份接口生成，包含被数据库引用的原件、SHA-256 和字节清单。恢复先校验文件、路径和 SQLite 完整性，仅写入新的 `restored-UUID` 目录，不覆盖当前数据。备份包含私有业务数据，请妥善保存。

命令行恢复：`npm.cmd run restore -- "备份ZIP绝对路径"`。若需切换，先停止当前总览服务，设置 `$env:OVERVIEW_DATA_DIR='恢复副本绝对路径'` 后执行 `npm.cmd start`。不要在服务运行时直接覆盖数据库文件或混用 WAL/SHM。

## 验证

- `npm.cmd run check`：JavaScript 语法检查。
- `npm.cmd test`：独立临时源账本与费用库，涵盖付款/退款、去重、归月、分类、关联、只读、导出和备份恢复。
- `npm.cmd run verify:live`：只读核对真实九月账本，独立 SQL 复核采购金额、逐项核对明细与汇总、验证导出及来源逻辑校验值；输出在已忽略的 `test-output`，不新增真实费用。
- `npm.cmd run verify:dashboard -- 2026`：只读三个真实账本，验证全年合计、各月 / 每日趋势、日期下钻和年度 Excel 一致；输出 `test-output/dashboard-verification.json` 和年度核对 Excel。
- `node scripts/ui-fixture.mjs`：隔离界面验收环境，端口 17891，Ctrl+C 后清理隔离数据。不要把它当正式账本使用。

现有 ExcelJS、csv-parse、Chart.js、Tabulator 负责文件与界面；Express 和 Node SQLite 负责本机服务。上传组件使用经审计后的 Multer 2.4.0。参考 [Node SQLite](https://nodejs.org/docs/latest-v24.x/api/sqlite.html)、[ExcelJS](https://github.com/exceljs/exceljs)、[CSV Parse](https://csv.js.org/parse/)。

看板沿用 [Chart.js 折线图](https://www.chartjs.org/docs/latest/charts/line.html)，通过空值和 `spanGaps: false` 保留缺失日期，不新增第三方图表服务或上传数据。

## 菜鸟云仓账单下载（1.3.0）

在「运费账单 → 下载云仓账单」中，先连接日常 Chrome，再选择月份开始。首次请安装 [微软官方 Playwright 扩展](https://chromewebstore.google.com/detail/playwright-extension/mmlmfjhmonkocbjadbfplnigmagldckm)，在 Chrome 打开的扩展页面确认连接并选择已经登录菜鸟金掌柜的标签页。如果扩展新建空白标签页，程序会打开固定的金掌柜首页并检查登录；其他网站的标签页不会被改动。扩展连接的实现参考 [官方说明](https://github.com/microsoft/playwright/tree/main/packages/extension)。不需要 Codex 或 AI 服务；Node.js 后台通过固定流程调用 Playwright MCP。没有安装扩展时，连接会超时，请安装后重试。

- 按「业务时间」自然月下载交易明细、货品信息、计费明细、全部费用项汇总以及可获取的仓储货品明细。费用项跨页全选，保留零金额和赔付。平台目前将交易导出和费用导出都命名为“交易明细账单”，程序使用提交前后任务编号和文件表头共同核对。
- 只下载整理，不新建费用、付款或完整性确认。交易汇总与费用汇总是同一批业务的不同视角，不能再次相加。当前月显示“截至下载时”。默认先核验 2026 年 9 月，三类下载通过后开放多月。
- 历史中的“继续”补齐失败、待生成或中断的项目，不重复提交结果不明确的任务。“重新下载”用于平台有更新时，保留旧版本；同月、同类型、内容相同的文件按 SHA-256 复用。已成功下载月份默认复用本地文件。
- 下载原件和每月清单位于 `data/downloads/cainiao/<账户哈希>/<YYYY-MM>/<批次UUID>/`。文件采用 UUID 存储以避免路径冲突，原始文件名保存在清单和数据库中，网页下载时恢复原名。ZIP 保留原封包，包括仓储的嵌套 ZIP、GB18030 CSV。文件不展开写入磁盘。未识别的表头或金额不一致会保留原件并显示“待核验”。
- 浏览器需要保持开启。验证码、登录、扩展授权或其他自动化占用需手动处理。程序不付款、开票、确认账单或配置邮件。运行时请不要切换账户或编辑下载标签页；可在其他标签页正常工作。
- 平台任务等待 10 分钟仍未完成会保留任务编号。取消仅停止本地后续步骤，不删除平台任务或原件。应用重启后显示可继续的任务；未设置记住授权时，Chrome 连接需重新确认。
- 新备份格式为 v2，包含下载任务记录、原件和月度清单，兼容恢复旧 v1 备份。未压缩总大小上限 300 MB、压缩后上传恢复上限 100 MB；超限明确拒绝，不遗漏文件。登录凭据、浏览器资料、临时下载目录不进入备份。

可选「记住浏览器授权」：在 Chrome 的 Playwright 扩展中复制 `PLAYWRIGHT_MCP_EXTENSION_TOKEN` 的值，在系统内粘贴并勾选自动连接后保存。此令牌允许持有者连接该 Chrome；不要发送到聊天或共享文件。使用官方令牌机制，后续打开下载窗口时自动连接。菜鸟登录失效、验证码、扩展令牌更换或 Chrome 配置被清除仍需处理，不能保证网站永久登录。

授权通过 Windows DPAPI 按当前 Windows 用户加密，保存在 `data/.cainiao-authorization.dpapi`；只通过匿名管道处理明文，仅传给下载器的子进程环境，不设置全局环境变量，不写入 SQLite、日志、下载清单或备份。恢复备份或更换 Windows 用户后需要重新设置。在窗口中「取消记住并断开」会删除本机保存的授权并关闭连接；如需使其他持有者的令牌也失效，应在扩展中更换令牌。页面适配代码使用固定本地文件 `lib/cainiao-page.mjs`，更新适配时保留已有浏览器连接。

接口均为本机接口：`/api/cainiao/connection` 查询或连接；`/api/cainiao/authorization` 明确同意后保存或移除本机授权（不返回令牌）；`/api/cainiao/download-jobs` 创建、列出任务；`/:id/resume`、`/:id/cancel`、`/:id/open-folder` 处理现有任务；`/api/cainiao/files/:id` 读取校验后的原件。所有写操作沿用 `X-Overview-Token` 和同源校验，不接受自定义网址、脚本或磁盘路径。

开发验证：`node --test tests/cainiao.test.mjs` 使用隔离数据库及模拟浏览器，覆盖负数/零金额、嵌套 ZIP、任务混淆、部分失败、恢复、去重、备份、接口权限与金额不变。`test-output/cainiao-source-verification.json` 是网站实际下载样本的解析核对，不能替代扩展连接后的独立程序端到端验收。
