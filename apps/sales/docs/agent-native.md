# 销售台 Agent 原生业务接口

本接口让中央任务使用销售台现有业务规则完成查询、准备、人工复核和入账。销售台负责真实业务数据、原件、权限与回读；中央任务负责可信人员上下文、任务附件、结果展示和人工审批。能力目录不是对网页按钮的模拟，也不把生成的一段文字当作执行回执。

本轮模块内部声明 **75 项能力：44 项查询、24 项需人审准备、7 项免审准备**。逐项输入与实际测试证据见 [能力与证据表](agent-native-evidence.md)。真实契约由 [agent-schemas.mjs](../lib/agent-schemas.mjs) 声明，适配器由 [agent-adapter.mjs](../lib/agent-adapter.mjs) 导出。每项都有中文标题、描述及具体 JSON Schema，根对象禁止额外字段；日期、月份、币种、数据集、分页、原件和版本有独立约束，业务域仍进行日历、范围及账本校验。

## 内部目录与中央公开目录

内部能力 `sales.file-stage` 接受可信传输的原件 `{file:{filename,dataBase64,sha256}}`，保留最多 25MiB 的兼容入口。**中央公开目录将这一项替换为 `sales.files.stage {attachmentId}`，总数仍为 75**；中央其他能力的 `file` / `files[]` 只接受暂存返回的 `{id}`。模型不提交 Base64、主机路径、凭据或任意 URL。

中央主机通过当前任务的可信 `resolveAttachment` 读取真实附件，检查文件大小、任务归属及 SHA-256，再通过销售台签名上传接口分片传输：

| 内部传输接口 | 作用 |
| --- | --- |
| `POST /api/integration/v1/agent/files/upload/start` | 绑定人员、任务、原名、大小、完整 SHA 和稳定上传键，返回已有分片 |
| `POST /api/integration/v1/agent/files/upload/part` | 校验 1MiB 分片索引、字节数及分片 SHA；重复同片只确认一次 |
| `POST /api/integration/v1/agent/files/upload/finish` | 校验连续完整分片及原件 SHA，登记同人员同任务 source ID |

分片协议的原件上限为 **50MiB**，与旧内部 inline 入口的 25MiB 上限不同。共享协议测试覆盖 50MiB、重启续传、人员/任务隔离及摘要篡改；销售台另有真实附件 ID→分片 HTTP→人审导入 4250 分→中央任务导出登记的执行测试，见证据 H7、X。模块原件下载成功不单独证明中央任务文件已经登记。

## 查询与提交流程

可信适配器只访问 `/api/integration/v1/agent/` 下的接口。它使用宿主提供的 `transport`，不从模型输入取地址、签名或身份，也不导入桌面启动器。

| 接口 | 行为 |
| --- | --- |
| `GET binding` | 返回当前 `dataSetId` 和 `revision` |
| `GET query?capabilityId&input&taskId` | 按具体能力 Schema、真实身份和业务权限读取；暂存原件解析保持当前任务范围 |
| `POST prepare` | 接收 `taskId/capabilityId/input`，返回 summary、scope、blocks、evidence、changes、issues；需人审能力另返回仅含 preparation ID 的公开 commitData |
| `POST commit` | 只接受已准备的结果及可信审批头，验证当前账本、内容和身份后原子提交 |
| `GET receipts/:idempotencyKey` | 查询当前人员的持久回执；不明状态返回 unknown，不推测已成功 |
| `GET files/:id` | 检查文件归属、原授权与 SHA 后下载真实文件 |

需人审的准备阶段使用隔离 SQLite 副本及原件副本运行原有领域函数。正式业务数据在准备后必须保持原修订；真正提交时重验绑定、先备份，再执行领域写入、业务回读和回执保存。存在阻断项的结果不能提交。运费、导入、锁月、匹配等沿用原有规则，不添加绕过领域校验的写表入口。

7 项免审准备是原件暂存、一致性备份及菜鸟的连接、断开、开始下载、停止、恢复。它们可以保存原件、下载任务、备份或辅助元数据，但不得改变正式财务业务表；服务对业务表快照进行前后核对。菜鸟下载完成不直接生成运费记录，入账仍需 `sales.cainiao-posting` 人审。

## 身份、审批与并发

Agent 接口要求经过工作台验签的真实 actor，且 `modules` 包含 sales、目标 `module` 为 sales。普通 Bearer、模型的 `role` 或本地存储不能建立这种身份。viewer 或 `canRunTasks=false` 不能准备、提交。资金月报、对账、资金流水、匹配、锁月、汇率、备份恢复等由服务端老板权限控制；员工只在真实允许范围内准备经营资料、手工业务和费用，员工覆盖确认只允许 `operations/expense`，资料交接要求实际 editor。权限在查询、准备、提交和文件取回时分别检查。

中央人工确认后生成短时 HMAC-SHA256 审批证明，域标识为 `erp-agent-review-v1:`，有效期不超过 60 秒。签名绑定 `actorId/module/capabilityId/taskId/resultId/resultVersion/dataSetId/revision/changeDigest/idempotencyKey`。`changeDigest` 来自规范 JSON 的能力、业务输入、服务端准备标识和变更列表。模型不能填写 `approval/confirmed/trustedUi/role/commitData` 等内部信任字段。

提交不仅校验签名，也与服务端保存的草稿逐项比较。跨人员草稿、改动后的输入、过期账本修订、复用到不同内容的幂等键均拒绝。同一人员、同一内容、同一幂等键重放返回已保存回执，不重复入账；重启后仍可查原回执。回执记录人员、任务、能力、数据集、前后修订、业务结果、回读验证及备份。

SQLite 的 Agent 提交拥有异步事务所有权。提交期间其他人员、后台任务、保留的 prepared statement 及 raw DB 写入不能插入该事务；失败回滚，提交后的分离异步回调不能继续借用过期所有权。具体隔离测试见证据表 T1–T3。

## 金额与业务状态

| 字段或结果 | 业务口径 |
| --- | --- |
| `ledger-create/update.amount`、匹配的 `left_amount/right_amount`、运费各费用 | **原币元的十进制字符串**，最多两位小数；领域精确转换为安全整数分，禁止浮点或科学计数法替代 |
| `currency` | `CNY/RUB/USD/EUR`，保留真实原币；不同币种不擅自按参考汇率认作实际到账 |
| `pdd-reference` 收入、支出、期初和期末余额 | **整数分**；收入非负、支出非正；没有取得的数据用 null，不补 0 |
| 已存流水、平台月表、运费分类中的金额 | 领域整数分；展示或 Excel 可格式化成元，不能把格式化结果再当分提交 |
| 汇率 | 保存日期、实际生效日期、官方来源及 SHA；固定精度 scale=100000000，不作为实际收款确认 |
| 笔数、件数 | 整数；未取得可为 null。运单号、订单号及外部编号保持字符串，避免丢失前导零和长编号精度 |

账单存在仅表示已经取得该原件，不代表整月完整、资金已经人工核对或月报已经批准。平台参考金额对上不自动产生匹配。员工 `staff-handoff` 使用当前 `staffRevision`，只表示资料就绪并等待老板；不把 settlement/receipt 覆盖置 full，不锁月。员工资料变化需重新提交，老板正常匹配不应让员工准备资料失效。月报任务的 `needs_action` 是真实缺口状态，不包装为已完成月结。

运费独立于平台已经扣除的费用。`warehouse` 的费用按 shipping/packing/materials/storage/other 分类；赔付抵扣以有依据的负 `other` 保留，不把补偿抹掉。数据缺失、未知费用、金额精度错误、币种不支持、净额不平及来源被修改时阻断入账。

## 原件与下载

source ID 绑定真实人员与任务，读入前检查原字节 SHA。文件名保留官方口径：淘宝仍要求同月 `交易货款_YYYYMM_YYYYMM.csv`，拼多多为真实官方 ZIP。文件映射只接受明确列号、目标店铺、月份、数据集及口径；不从汇总或截图反造原件。撤销导入保留原件与审计。

模块下载返回受控 artifact，不向模型暴露本机数据目录或绝对路径。中央主机应通过可信 `transport.download` 流式取得原件，核对声明的大小及 SHA，将字节保存到当前中央任务并调用 artifact 登记；展示使用登记后的任务文件 ID。只拿到模块临时 URL 或 JSON 元数据不算中央下载交付完成。原件、运费附件、工作簿导出、月报、模板和备份都走同一归属及摘要校验要求。

备份创建后验证数据库与原件完整性；`restore-copy {name}` 只将已登记备份恢复到新的独立副本并回读核验，不覆盖正在使用的正式账本，也不接受任意恢复路径。

## 菜鸟与外部验收边界

菜鸟按实际账户和业务时间下载官方交易、计费及费用原件，保存原 ZIP 和原工作簿成员及 SHA。月份范围不限于固定的示例月份；多月下载需先验证一个历史月份的完整下载。当月要求明确 `cutoff` 或 `cutoffs[month]`，不得晚于北京时间昨天，并保存截止范围。当前月仅允许更新可证同源的未结记录，保留 ID、递增 version 和旧附件历史；不能缩小已登记覆盖范围，也不能凭账单编号猜测覆盖历史记录。提交不明确时先找已存在平台任务，不盲目重复发起。

本轮菜鸟测试使用 **FakeBrowser 模拟外部平台**，但 ZIP/XLSX 生成解析、归档 SHA、本地签名 HTTP、中央审批、正式领域入账、附件取回及回执幂等均实际执行。**本轮未使用真实菜鸟账号进行浏览器平台验收**，登录态、平台页面变动和真实下载仍是外部验收边界。测试名称中的“真实 ZIP/XLSX”指真实文件格式，不代表真实平台账号操作。

`sales.skill` 返回随销售台发布的指引原文；merchant 和 sf 自动采集仍返回 `available:false`。手工运费登记渠道与外部采集支持是不同能力，不能把占位状态表述为已支持这两个平台自动下载。汇率测试模拟官方 CBR 网络响应，实际验证 XML 解析、预演、审批及数据库保存，不代表本轮访问过真实 CBR 网络。

实现及验证范围是销售台业务接口和必要中央主机桥接；**75 项能力不表示修改或验收了 desktop/启动器/安装包**。所有测试使用 `os.tmpdir()` 隔离数据与动态端口，不在正式账本做写入，不据此宣称已完成生产部署、安装或真实平台验收。

## 后台任务完成语义（代码待统一测试）

主机适配器按持久任务 ID 查询云仓后台任务，默认最多等待 45 秒，支持 AbortSignal 取消等待；处理未结束、登录/人工接管、暂停、取消、未知提交或回读失败均返回 blocking issue 和真实状态、查询能力及任务 ID。重复启动前先查已有同范围任务，未完成任务不会自动重新启动；完成记录按来源文件 ID、验证标记核对，并通过安全原件能力将产物登记到中央任务。平台返回“已开始”或单独的 completed 字样均不视为产物完成。停止只表示原任务停止，不表示原下载/入账目标完成。后续测试遵循总控代码冻结后的统一执行安排。

## 2026-10-29 最终访问决策（替代旧角色门控说明）

所有真实登录人员均可使用全部业务功能并查看全部业务数据，不再按老板／员工、admin/editor/viewer 或模块成员配置限制业务能力。签名协议中的旧 role/modules/canRunTasks 字段仅保留兼容结构，领域业务不据此授权。销售已登录界面使用统一 member 身份，不再弹出独立老板／员工选择；未签名旧本机接口仍保留原兼容安全边界，不可作为 Agent 身份。

总览归档交接不再要求额外模块授权；仍须真实登录、本任务实际持有的来源产物、runtime 来源标记、人员／任务／SHA 一致。人员目录与销售领域映射只用于归属、防重名和分派，不改变访问权限。真实登录、请求签名、本人身份确认、中央结果页复核、UI确认通道、版本／月锁、幂等、防跨任务原件及Beta维护窗口均保留。没有新增权限管理页面或成员授权接口。

本次访问调整是单独增量提交；新增及更新的测试仅编写，尚未统一执行。不得将旧角色门禁测试的历史通过记录当作新策略验收。
