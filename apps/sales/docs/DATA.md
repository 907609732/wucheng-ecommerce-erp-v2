## 金额与日期口径

| 数据来源 | 日期依据 | 金额含义 |
| --- | --- | --- |
| 正式运营报表 | 来源定义的支付日期 / 统计区间 | 支付金额、支付订单、退款、广告及流量指标 |
| 拼多多货款账务明细 | 官方发生时间 | 货款账户收入、退款、费用、提现和转账等动账 |
| 淘宝交易货款 CSV | 官方「账期」字段 | 交易货款入账和逆向退款，保留打款及确认收货时间 |
| 结算账单 | 结算记录日期 | 平台净结算与调整 |
| 实际收款记录 | 收款来源记载日期 | 支付宝、微信、银行、PingPong 等实际到账 |
| 线下与代发登记 | 业务登记日期 | 销售应收、退款和收款关联 |

人民币金额以**整数分**保存和计算，避免直接用浮点数累计。原币支持 CNY、RUB、USD、EUR；经营人民币参考折算与实际换汇收款分别保留。

### 提现、费用和利润

- **提现 / 内部转账**：自己账户之间转移，不是新增收入或经营费用；在平台账户对账中仍保留对应流出。
- **退款**：单列逆向流水，避免和收入记录混淆。不能在读取已扣退款的净额后再次扣同笔退款。
- **充值和保证金**：分别归类，不能一律视为当期费用。
- **平台已扣费用**：与另外支付的单店费用分开，避免重复扣除。
- **采购、工资、共用物流等**：需要实际用途和成本依据；当前不提供完整商品成本、库存或共用费用核算。

当前总览的「账单支出」「账单净变动」仍用于已取得账单的收支展示，可能包含提现。它们**不是经营费用或利润指标**。

### 缺失、零与覆盖

缺失数据显示空缺；只有有依据的零才能作为零。年度金额是已取得数据的合计，不能由「出现了几个月的金额」推断全年完整。

拼多多按已确认店铺各批次的声明时间范围求并集，判断自然月覆盖；平台截图单独保存作对照。截图数字不会变成流水，余额标明参考日期和来源。

淘宝单月文件名和账期可确定声明月份，但无法单凭文件存在证明与官方月汇总完全一致，导入后仍需核对。

月访客不累加日访客，年度访客也不直接累加月份。转化率、客单价和广告投产比仅在分子分母及归因窗口满足要求时计算。

## 原件、批次与去重

每批导入保存原件、文件 SHA-256、店铺、来源及预览信息。预览版本改变后不能沿用旧版本提交。

| 导入类型 | 记录识别重点 |
| --- | --- |
| 拼多多 | 同店铺订单号、发生时间、业务代码、币种、金额及相同行出现次数；无订单号记录补充备注依据 |
| 淘宝交易货款 | 业务流水号、主订单、子订单、退款单号、账期、收支方向及出现次数；已有身份但数值变化时阻止冲突 |
| 通用资金流水 | 同店铺、同类型的业务编号 |
| 通用运营报表 | 同店铺、日期区间和币种 |

不同店铺不互相去重。同一订单的不同子单、退款和费用不应被当成一笔。重复导入同一原件或同一业务记录不会再次增加对应金额；出现冲突需回到原件核对。

拼多多来源待确认批次进入独立待归属区，排除正式汇总及正式去重。确认归属时检查目标店铺重复、现有匹配和锁定月份，保留审计；不要直接修改数据库绕过检查。

## 运费台账

`freight_records` 保存独立运费记录，`freight_attachments` 保存凭证及移除历史，`freight_requests` 保存成功写入的请求编号和结果。费用以整数分存储，界面与 Excel 以元展示。运费不写入原有 `ledger`，不自动从经营结余或资金对账再次扣费。

云仓固定为共用，商家寄件必须有店铺，顺丰可为单店或共用。月汇总归属所填月份，日汇总与单笔归属所填日期；日统计不包含月汇总。件数只有在筛选范围内所有记录均填写时才汇总，平均快递运费只用纯运费除以已完整填写且大于零的件数。

请求编号阻止网络重试重复入账；同类型、同归属的相同单号、月汇总重叠或同日同金额会要求人工核对。确认依据与冲突记录编号写入审计，不自动推测是否为同一笔业务。编辑有版本检查，作废只改变状态并保留原因。

凭证位于 `originals/freight-*`，作废及移除后的原件仍保留并参与备份和校验。备份恢复包含有效、已作废记录及其历史附件。此迁移只新增表与触发器；升级正式账本前先创建并校验备份，禁止用演示库覆盖真实库。

## 月份锁定

锁定保存当时的月份快照。后续读取锁定月份的报表使用保存的数据，避免其他月份变化影响已确认结果。

流水、运营数据、匹配、汇率、覆盖、归属调整、运费和运费附件均有相应锁定检查。运费也参与预览修订校验与锁定快照；旧快照没有运费字段时显示“当时未记录运费”，不改写旧快照或补零。修订时通过页面明确解锁并填写原因，旧快照及历史继续保留。

## 本机数据目录

| 路径 | 内容 |
| --- | --- |
| `data/sales.sqlite` | 账本、店铺、批次、匹配、审计及月份快照 |
| `data/originals/` | CSV、ZIP、XLSX 原件及平台参考截图 |
| `data/reports/` | 生成的报告和导出结果 |
| `data/backups/` | SQLite 快照、被引用原件、截图与报告、校验清单 |
| `data/recovered/` | 应用恢复出的独立副本 |
| `data/server.port` | Windows 启动脚本上次使用的端口 |
| `data/server.pid`、`*.log` | 本机进程与运行日志 |

Git 忽略 `data/`、`.env*`、日志、`node_modules/`、`test-output/` 和生成的任务 XML。**Git 忽略不能清除过去已经提交的文件，也不是数据备份。** 不要提交账单、数据库、截图、账号密码、验证码或令牌。

## 备份恢复与迁移

### 创建和校验

在「任务与备份」创建备份并执行校验。服务端还会在主要导入提交、归属调整、批次撤销以及锁定 / 解锁等操作前按对应流程备份。

每份备份有 `manifest.json`，记录文件 SHA-256；校验同时检查文件哈希和 SQLite 完整性。应另行保留离线或受控位置的副本，避免本机磁盘故障同时影响账本与备份。

### 恢复成副本

1. 在页面选择备份，先完成校验。
2. 使用「恢复为独立副本」，获得 `data/recovered/…` 下的新目录；现有账本不会被覆盖。
3. 停止应用进程，确认没有仍使用旧数据库的服务。
4. 通过新的终端指定副本目录启动：

```powershell
$env:SALES_DATA_DIR = 'D:\SalesDesk-Recovered\verified-copy'
$env:SALES_PORT = '17869'
node server.mjs
```

示例目录需替换为实际恢复目录，端口需空闲。此命令只对当前 PowerShell 会话设置环境变量；验证完成后保留原账本，决定长期入口再切换。

> `scripts/start-app.ps1` 的端口与日志管理以项目 `data/` 为基础。验证恢复副本时应按上方方式直接运行 `node server.mjs`，不要同时启动桌面入口。

### 迁移到另一台电脑

安装同版本源码与依赖，将**已校验的完整备份**转移至目标电脑的受控目录，按恢复副本方式启动并检查月份、原件下载和金额。不要只复制一个正在写入的 `.sqlite` 文件；SQLite 运行时可能使用 WAL 辅助文件。

## 定时与访问边界

内部任务名 `Wucheng-SalesDesk-Monthly` 保留兼容。计划使用北京时间每月 15 日 20:00，处理上月，XML 固定 `+08:00`；默认停用，运行层也受 `schedulerEnabled=false` 保护。

手工生成月报仅使用已保存数据，不执行尚未验证的后台采集。不要把任务存在、报表生成或本地测试通过当成自动登录、验证码处理及官方导出已经完成。

默认服务只监听 `127.0.0.1`，校验 Host，写操作需当前会话令牌并检查 Origin。老板与员工按服务端人员会话分工；本机按启动时直接点选身份，人员会话不是公网密码登录系统。通过工作台私网访问时，人员选择不能提升原 Tailscale 账号的权限。

员工月度交接记录保存在 `sales_staff_handoffs`，包含月份、提交人、提交时间和资料版本，随数据库备份保留。资料提交与资金核对、月份锁定分别记录，互不替代。
