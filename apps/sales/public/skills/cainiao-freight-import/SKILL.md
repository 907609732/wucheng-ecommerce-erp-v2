# 云仓运费导入销售台

把官方云仓账单按业务月份登记到正式销售台「运费」，保留下载原件、费用分类、附件和审计记录。用户要求执行导入时，完成核对后继续执行授权范围内的导入，不因常规步骤重复索要确认。

## 执行前

- 使用用户已登录的本地浏览器，优先 ego-browser；先读取其已安装 Skill 并运行 `ego-browser skill`。复用本次任务空间，不接管无关标签页。登录、验证码或设备授权交给用户处理，不索取账号密码或请求头。
- 找到当前正式销售台：读取当前用户 Documents 下 `LingtuWorkbench/registry.json` 的 `sales` 配置及必要的位置标记，核实服务健康、端口和 dataDir。不要硬编码用户名、开发端口、历史安装目录或 TaskSpace ID。不要创建空库替代原账本。
- 先明确本次范围。默认补齐当前可查询的缺失月份并更新未结月；已完整导入且金额、分类、覆盖截止日相同的月份跳过。若用户只指定一个月，仅处理该月。
- 读取 [references/browser.md](references/browser.md) 操作云仓；读取 [references/import.md](references/import.md) 进行分类、查重、备份、导入与验收。

## 工作顺序

1. **确定可查询范围**：观察日期控件允许的最早、最晚日期，不把过去一次可查询范围当永久规则。当前月只导出实际允许的截止日，并标为未结月。更早月份无法查询时如实报告。
2. **按月下载原件**：时间维度选「业务时间」，不限定店铺、服务产品或费用项。每月导出交易账单、货品信息、计费明细。保存原始 ZIP 和里面的 Excel，不修改源文件。
3. **核对与预览**：按整数分统计，核实币种、业务日期、交易账单合计、费用明细合计和页面金额。分类金额必须相加等于月度净额；赔付负数保留。包裹件数不由交易行数推算。
4. **查重与决定动作**：对照正式台账，列出新增、跳过、更新、待处理。已知同源未结月需要更新时修改原记录并保留旧附件历史，不能再新增一条覆盖同月的月汇总。归属不明、未知费用项、多人改动或锁定月份只暂停相关月份，不自动确认重叠或解锁。
5. **备份后写入**：使用当前销售台运费 API，带原件附件和稳定提交编号。使用员工可操作的费用入口；不借用其他人的会话或权限。正式账本保存在现有 dataDir，禁止直接 SQL 改业务记录。
6. **验收**：逐月回读记录、金额、分类与附件；核对重复数、更新版本和旧附件留存。检查数据库完整性与外键，确认原有流水、匹配、月锁和其他模块没有被修改；在实际界面检查至少一个赔付月份和本次最新月份。
7. **交付**：报告实际范围、成功/更新/跳过/待处理数量、月度净额合计、当前月截止日、原件和备份位置。整理浏览器任务空间，保留有用结果页。没有实际回读和原件校验，不宣称导入成功。

## 业务口径

- `channel=warehouse`、`entry_mode=month`、`period=YYYY-MM`、`shop_id=shared`（服务保存为 NULL）。所有云仓费用归「多店共用」，不自动分摊到店铺。
- 运费台账独立统计，不将它再写入资金流水或重复从资金对账扣除。费用净额包含赔付抵扣，纯快递费用仍单独列示。
- 仅本地保留原件、预览、备份、回执。Skill、提示词和公开文件不得包含登录信息、临时签名下载地址、访问令牌、客户订单明细或真实账本副本。
- 此 Skill 是让具备本地浏览器、文件和代码执行能力的 AI 完成操作的说明，不表示软件已内置 AI 执行器。不能访问所需环境时明确说明缺少的能力，不假装已执行。
