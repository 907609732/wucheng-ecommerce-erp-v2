# 原件核对和正式销售台导入

## 环境和文件读取

Node 24 的 `node:sqlite` 可只读检查现有账本、使用原生在线 backup 获取一致备份。ExcelJS、JSZip 是销售台现有依赖；从注册表 `sales.root` 发现对应依赖，不安装另一套业务服务。也可使用已有表格技能支持的只读工具。部分官方 XLSX 的 dimension 错报为 A1；使用 openpyxl 只读模式时需 `reset_dimensions()` 后再遍历，不能据 max_row=1 判断文件没有数据。

同一个月通常有三类原件，文件名包含 `YYYYMMDD_YYYYMMDD`：

| 文件角色 | 主要列 | 用途 |
| --- | --- | --- |
| 交易账单 | 交易单号、ERP单号、物流履约单号、运单号、单据类型、计费金额合计(CNY) | 独立核对月合计和行数 |
| 计费明细 | 费用项、计费金额、计费币种、业务时间、账单类型 | 分类计费，保留赔付符号 |
| 货品信息 | 物流履约单号、货品ID、货品件数等 | 原件凭证，不再次累加费用 |

核实所有分卷均已下载。ZIP 与其解压文件按原文件哈希识别同一份文件，不能重复统计。不要按相同金额或相同履约单号简单删掉计费行，同一单可能有多个正常费用项目。

日期以业务时间为准，须落在文件声明区间和所选月份；币种必须 CNY。金额逐行转整数分再汇总，拒绝缺失、非数字或无法解释的精度。交易账单月合计、计费明细月合计与页面金额应一致；有差异先查清。行数不是包裹数，不知道发货件数时留空。

## 已验证的费用映射

| 计费明细费用项 | 销售台字段 |
| --- | --- |
| 正向配送费、逆向配送费、正向配送费_春节不打烊 | shipping 快递运费 |
| 防护包装费、多品防护包装费 | packing 打包费 |
| 包装物料费、防护耗材-气枕费 | materials 耗材费 |
| 仓储费 | storage 仓储费 |
| 订单处理费、订单处理费_春节不打烊、拦截费、非销售出库费、退货入仓费、货物装卸费、代贴条码费 | other 其他费用 |
| 货值赔付、服务赔付 | other，保留负号抵扣 |

`other_note` 写出原分类金额，包括正数服务费和负数赔付；`other` 为这些项目的净额。不能将赔付抹零或混入纯快递运费。其他费用净额可能为负。销售台从 0.4.4 起支持此口径，shipping/packing/materials/storage 仍不接受负数。发现新费用项、其他字段出现负数或旧版不支持时，保留原件并报告该月待处理，不自行修改程序或猜测映射。

例：快递费 1000、耗材 20、其他服务 50、赔付 -100，保存 shipping=1000、materials=20、other=-50，净额 970；说明中保留其他服务 50 和赔付 -100。

## 查询、去重、更新

从当前正式台账读取 `freight_records`、有效附件、月份锁及当前版本，或使用下面的查询 API。

- 同月同源、同分类金额、同覆盖截止日已经存在：跳过。重新导出造成 ZIP 元数据或文件哈希变化，不能单独据此再新增。
- 已知云仓同源月汇总的业务标识使用 `bill_no=CAINIAO-BIZ-YYYY-MM`。历史记录还要核实原件名称、来源和区间，不能只凭账单号覆盖。
- 更新未结月：保留 record ID 和 bill_no，用 PUT 携带最新 `version`、新金额、新附件及新的截止日说明。通过 `remove_attachments` 移除被替换的有效附件，服务会保留原件与附件历史。范围扩大但金额未变时也应更新区间说明和凭证。
- 已结月金额变化、同月多条月汇总、未知来源或重叠记录需要先解释差异。409 `FREIGHT_REVIEW` 不能自动回填 review_token；423 锁定不能自行解锁；STALE_RECORD 必须重新读取。
- 对每月列出新增、更新、跳过、待处理及原因，核对总额再继续已授权写入。存在歧义的月份单独留待处理，其他已核实月份可以继续。

## 使用现有 API

服务地址从 registry 读取并验证 `/api/health`：应用必须是销售台，`demo=false`，dataDir 保持原目录。下面路径针对直接本机销售台端口；使用工作台代理时需遵循其当前会话及路径前缀，不绕过权限。

1. GET `/api/bootstrap` 取得当前防跨站 token，只在内存中使用。POST 请求使用 `x-sales-token` 和实际本机 Origin，不记录 token。
2. 需要本机人员会话时，POST `/api/personnel/session`，JSON `{ "role": "employee" }`；仅在本次调用内保留返回 Cookie。云仓费用登记属于员工可操作范围。不要为此选择老板或申请管理员权限。
3. GET `/api/freight/records?grain=year&period=YYYY&page_size=100`；检查分页和各年份，GET `/api/freight/records/:id` 读取最新版本和附件。
4. 新增 POST `/api/freight/records`；更新 PUT `/api/freight/records/:id`；均为 multipart FormData。

提交字段：

```text
request_id: 不超过80字符，按本次来源、月份、动作、版本、内容和原件哈希确定的稳定编号
channel: warehouse
entry_mode: month
period: YYYY-MM
shop_id: shared
shipping / packing / materials / storage / other: 元金额字符串，最多两位小数
other_note: 原项目金额及赔付抵扣说明，不超过500字符
bill_no: CAINIAO-BIZ-YYYY-MM
note: 菜鸟官方账单、业务时间、起止区间；未结月注明截止日及下次应更新原记录
pieces: 未知时不提交
files: 官方Excel原件，以同名files字段逐个附加
version: 仅更新时填当前版本
remove_attachments: 仅更新时填待替换的有效附件ID的JSON数组
```

每笔最多 5 个附件，单文件 25 MB，总计 50 MB。ZIP 不直接作为附件，保存在本地原件目录；附上里面的官方 Excel。超过附件限制不能悄悄丢掉分卷或拆成重复月汇总，应保留原件并报告处理方案。错误时记录已完成月份及可恢复的提交编号；只对同一内容重用 request_id。

## 备份、审计与验收

在第一次写入前，对当前销售台 SQLite 做一致备份，保存原附件/原件和本次来源清单。使用现有备份功能或 Node 原生在线 backup，不直接复制正在写入的单个 SQLite 文件来冒充完整备份。

记录写入前的关键表摘要、月锁、旧审计和附件摘要。操作通过运费 API 留审计；不用直接 SQL 插入/修改业务记录，不改服务端口、注册表、程序版本或其他模块。

写入后逐月 GET 回读，核对 record ID、version、全部分类整数分、净额、shared 归属、截止日及附件哈希；新增或更新的附件均实际 GET 下载并校验大小和 SHA-256。更新后检查旧附件仍在历史中。

检查 `PRAGMA integrity_check` 和 `PRAGMA foreign_key_check`，原流水 ledger、operations、matches、coverage、shops、月锁及其他无关表保持原样，旧审计保持不变，只允许本次 freight 写入带来的记录、附件、请求、审计和业务修订号变化。遇到其他人同时改账，报告并重新建立基线，不回滚别人的数据。

在软件「运费」切换到本次月份，核实净额和凭证数量；有负数其他费用时打开记录检查负号与合计，关闭而不额外保存。汇报当前可查询范围与限制，不把部分月份或未结月宣称为全部历史或已结清。
