# 灵兔电商销售台

**把多家店铺的账单放在一起看，让每个数字都能追溯到原件。**

本机运行的电商资金与销售数据工作台，支持淘宝、拼多多官方货款账单导入、经营资金总览、逐笔核对、Excel 导出，以及线下供货和代发记账。

`Node.js ≥ 24` · `SQLite` · `Chart.js` · `Tabulator` · `Windows 桌面启动`

> 当前为 **0.1.0 本机单人版本**。账单收入不等于支付销售额，货款净额不等于利润。官方账单可手工导入；平台后台无人值守采集尚未完成，定时任务默认停用。

[快速开始](#快速开始) · [功能与接入状态](#功能与接入状态) · [使用指南](docs/USAGE.md) · [数据口径与备份](docs/DATA.md) · [接口参考](docs/API.md)

## 能做什么

- **经营资金总览**：按日、月、年和店铺查看已取得账单，展示收支趋势、店铺对比、退款及费用构成。
- **运费看板**：登记云仓、各店商家寄件及顺丰费用，支持月／日汇总和单笔寄件、凭证留存、编辑作废及 Excel 导出；共用费用单独统计，暂不参与资金对账扣费。
- **拼多多月度对账**：收入、支出、笔数、账户净变动、日期覆盖及平台截图参考分别展示。
- **逐笔追溯**：按订单号、日期、收支、分类和来源文件筛选；查看完整备注、主子订单、原件行号并下载原文件。
- **完整结果导出**：Excel 包含全部符合筛选条件的记录，不局限于当前页；订单号保持文本格式。
- **可审计的导入**：指定店铺、预览后提交、跳过重复、阻止冲突；待归属批次排除正式汇总。
- **本地数据保护**：保留原件、操作审计、月份锁定快照与备份；恢复操作先生成独立副本。

## 功能与接入状态

| 渠道 / 能力 | 当前支持 | 尚未包含 |
| --- | --- | --- |
| 拼多多 | 官方货款账务 ZIP、尾部金额与笔数校验、多文件覆盖合并、月表与明细 | 自动登录和后台定期采集、完整利润核算 |
| 淘宝 | 官方单月交易货款 CSV、货款与退款分开记录、主子订单追溯 | 从货款账单推算支付销售额、全部平台费用或银行到账 |
| 其他平台 | CSV、TSV、XLSX 列映射导入；保留原币及来源定义 | 京东、抖店、Ozon 等平台的完整自动采集验收 |
| 线下 / 供货代发 | 销售、退款、分次收款及应收关联 | 商品库存与完整成本管理 |
| 月报与备份 | 已保存数据生成月报草稿、核对后锁定、备份校验与副本恢复 | 无人值守补齐缺失账单 |

**有数据不代表范围完整。** 未取得的数据保持空缺；文件名声明、文件日期覆盖与平台汇总核对是不同的证据。

## 快速开始

### 1. 获取代码与依赖

需要 Node.js 24 或更高版本、npm；以下命令面向 Windows PowerShell。私有仓库需先具备访问权限。

```powershell
git clone https://github.com/907609732/lingtu-ecommerce-sales-desk.git
cd lingtu-ecommerce-sales-desk
npm.cmd ci
```

首次建立空账本前，可检查 [店铺初始配置](lib/config.mjs)。配置包含项目预设店铺，不表示对应平台已接入；已有账本不要随意更改店铺 ID。

### 2. 启动

Windows 用户可直接双击根目录的 **[启动销售台.bat](启动销售台.bat)**，服务就绪后会自动打开浏览器。已经运行时复用现有服务，无需重复启动；启动失败会保留窗口显示错误。

也可以从终端启动：

```powershell
npm.cmd start
```

默认访问 **http://127.0.0.1:17869**，服务只监听本机。终端启动保持窗口运行，按 `Ctrl+C` 停止。

Windows 也可使用带端口检查的启动脚本：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/start-app.ps1
```

脚本优先复用 `data/server.port` 记录的端口；不可用时在 `17869–17889` 中选择端口，并输出实际地址。

### 3. 创建桌面入口（可选）

```powershell
npm.cmd run install:desktop
```

创建「灵兔电商销售台」快捷方式。首次安装还会登记**停用**的月度任务；已有任务保持原状态，安装不代表自动采集已可用。

### 4. 导入第一份账单

进入 **任务中心**，选择月份，展开 **按店铺导入本月账单**，从真实店铺的入口读取文件、核对预览后提交。再按任务逐店核对资金，点击金额查看逐笔来源。设置中的账单导入入口也继续保留。

- 拼多多：官方货款账务明细 `.zip`。
- 淘宝：保留官方文件名 `交易货款_YYYYMM_YYYYMM.csv`。
- 其他报表：使用通用列映射入口，明确月份、数据类型与指标定义。

详见 [使用指南](docs/USAGE.md)。

## 三种金额，不混着算

| 口径 | 回答的问题 | 不能替代什么 |
| --- | --- | --- |
| 支付销售额 | 买家在支付日期买了多少？ | 确认收货后的货款入账 |
| 货款 / 平台账单 | 平台在账期内记了哪些收支？ | 银行卡实际到账、全部经营成本 |
| 收款与资金转移 | 钱实际去了哪个账户？ | 新增销售收入或利润 |

提现到自己的银行卡属于资金转移：平台对账可以保留提现支出，经营费用不能再扣一次。采购、工资、快递和云仓等实际用途需另有记录；目前不提供完整利润计算。详见 [数据口径](docs/DATA.md#金额与日期口径)。

## 数据保存与隐私

运行数据默认保存在项目的 `data/`，不随源码提交到 GitHub。数据库、原件、报表和备份均需自行妥善保管；本机访问不等于磁盘加密或多用户权限管理。

- 不需要把平台密码、验证码、浏览器凭据或账单传到仓库。
- 迁移账本时，应使用应用生成并验证的备份，保留原件和历史。
- 不要在服务运行时覆盖 SQLite 文件。
- 项目没有经过多用户服务或公网部署验收，不应直接暴露财务接口。

恢复与迁移步骤见 [数据与备份](docs/DATA.md#备份恢复与迁移)。

## 当前限制

- 后台自动采集尚未完成；月度任务默认停用。计划时间为**每月 15 日 20:00（北京时间）**，处理上月数据，尚不等于能自动登录并导出。
- 缺少订单、运营、采购成本和共用费用时，不生成假定销量、访客、广告投产比或完整利润。
- 平台截图仅作对照，不生成流水；截图余额不冒充由流水验证的余额。
- `scripts/correct-pdd-attribution.mjs` 是特定历史账本的修复脚本，**不是通用初始化步骤**，新环境不要直接运行。
