# 历史实现与兼容说明

本页保留旧版本细节用于排查和兼容；当前安装和日常操作以主 README、手机使用说明为准。版本号表示功能引入时间，不表示独立发布包。

## 日常使用

1. **采购看板**：选择年份、平台和归月方式，查看月度采购金额、订单数、供应商及平台占比。点柱状图月份进入订单。展开“每月金额明细与导出”可导出 CSV。
2. **表格导入**：选择平台及账号，上传 XLSX 或 CSV，核对字段、订单数与实付金额后确认。源表不修改，原文件复制到本机。支持 1688 合并单元格格式；淘宝、拼多多提供字段别名与手动映射入口，实际新文件仍需核对。
3. **AI 识别采购单**：统一采购单录入入口，从导入中心打开。“上传 / 粘贴识别”支持 PNG / JPG / WebP、PDF 和文字。可一次多选、拖入多图，或 Ctrl+C 复制图片后在窗口 Ctrl+V 连续粘贴；查看缩略图、移除或清空后，点击“识别全部”将同一笔订单的多份截图合并识别。附件每单最多 20 个文件，单文件 50 MB、合计 200 MB；识别最多 20 张图片 / PDF 页，超限时弹窗说明；不同订单应分批识别。文字框最小高度 300px，可继续拖高。确认入账后保存全部原件，多份附件以 ZIP 下载；“直接填写”用于微信、线下采购及临时补货，无需上传文件。切换方式保留当前表单；直接新建自动生成订单号，默认下单日期为当天，请按实际情况修改。采购平台可选择“微信”；微信采购支持直接填写、文字 / 图片识别、通用表格导入，并可按平台筛选、统计和导出。支持多项商品、退款、运费、备注和收货物流。识别使用 Tesseract 本地模型；提取后缺失字段保持为空，复杂表格和手写单的商品行需要人工整理。核对日期、金额及实际状态后确认入账，原始附件和修改历史保留。
4. **数据备份**（设置页）：创建完整 ZIP 备份，包含数据库、原始文件、附件、已缓存图片和修改历史。备份同时保存在 `data/backups`。
5. **全部订单**：默认每页 100 笔，可选 50 / 200 / 全部；支持表头排序、Shift 多列排序、列宽调整、显示列、显示图片和收起导航。按平台、状态、月份、供应商、账号、日期、金额、备注和运单信息组合筛选；搜索涵盖商品、收货人、手机、地址、物流与备注。导出使用当前筛选和排序，包含全部匹配订单。
6. **备注与收货物流**：点击表格“添加备注”或已有备注即可修改；详情和编辑页可以查看、修改收货人、地址、手机、物流公司和运单号。每次修改保留记录。旧订单首次升级时从保留的原始行补回收货物流字段，原始文件不变。源表未提供的字段显示为空，不推测补齐。
7. **商品单价、数量和单位**：订单表新增三列，与商品逐项对应。多商品订单默认显示首项，点击商品下方“展开其余”查看该单全部商品，再点击“收起”恢复紧凑显示。详情、编辑、表格字段映射、导入模板、文字识别和 CSV 导出均支持单位；多商品导出的三列按相同序号对应，订单实付仍只记一次。旧订单从保留的原始商品行补回单位，原表空白单位显示“—”或“未提供”。
8. **自动识别采购账号**：1688 表格优先读取“买家会员名”，也支持“采购账号”“买家账号”等明确账号列。卖家会员名和发票银行账号不会自动用作采购账号。表内账号优先，未提供时使用导入窗口的备用账号；预览逐单显示识别结果。旧 1688 订单中“默认账号”从原表补回，已有自定义账号保留。补回记录可在订单详情的修改历史查看。去重仍按平台、采购账号、订单编号组合判断。

## 功能补齐（1.3.3）

- 左侧管理入口统一为“设置”。数据备份、使用教程、导出任务和检查更新都在此页；“执行日志 / 订单日志”默认折叠。旧的备份与日志链接仍可访问，支持刷新和浏览器前进后退。
- 全部订单勾选后可批量修改供应商、采购账号、状态、支出统计与采购类别。提交前显示数量和目标值；版本、月份锁定或账号下订单号冲突会阻止整批保存。成功批次可在设置中的订单日志查找并整批撤销。
- “设置 → 供应商列表”从订单实时汇总，按“平台＋供应商名称”分别展示。可按名称、平台筛选，查看采购账号、订单数、最近日期与整单金额，并打开相关订单和商品。
- 录入、编辑与识别核对页可粘贴整段地址，预览后点击“应用识别结果”，也可从统一地址库选择。地址库支持编辑、删除、搜索和多标签筛选；供应商关联可选。订单保存地址快照，地址库后续修改不影响历史订单。
- 每条商品可添加多个运单号及物流公司，不同商品可共用运单。常见前缀在本地识别，人工填写的公司保留。历史整单运单仍显示，不自动分配到商品；搜索、筛选、导出及日志保留商品对应关系。
- AI 录入界面左上角统一添加图片、PDF 和其他附件；编辑订单保留附件区。每单最多 20 个，单文件最多 50 MB、合计最多 200 MB。上传中不能保存；关闭窗口会清理未保存上传。保存订单与绑定附件同时成功或回滚，撤销修改可恢复附件引用，已保存原件不会删除。
- 地址识别使用固定版本 `address-parse@1.2.19`，离线运行；许可证保留在 `licenses/address-parse-MIT.txt`。后台能力不足时页面会提示重启，不会静默丢弃新字段。

## 订单日志与撤销（1.3.2）

“设置”页的“订单日志”入口统一查看已有和新生成的修改记录。可按订单号、供应商、修改内容、日志编号、批次、修改类型和北京时间日期查询；默认每页 50 条，默认显示修改，切换类型可查看首次入账。订单详情的“修改记录”中也可进入该订单的日志。

每条日志保存时间、订单、操作类型、修改前后值和批次，覆盖金额、状态、备注、收货物流、商品、采购分类及是否计入支出。点击“查看变更”核对差异，再选择“撤销本次修改”或“撤销整个批次”，预览此次实际恢复的字段，可填写原因后确认。只撤销选定操作改动的字段，保留后续对其他字段的修改；相关字段当前值不符、版本过期、金额与分类不一致、编号重复或涉及锁定月份时整批不保存。锁定月份需先取消确认。首次入账与系统初始化记录只供查询，不通过日志删除订单。

撤销生成新日志并关联原日志，原记录、原件、图片及后续历史保留；撤销记录本身也可再次撤销。日志随完整备份保存，不提供清空或删除入口。升级直接读取已有历史，只新增撤销关联字段和查询索引，不改动旧日志或订单。

## 批量修改属性（1.3.1）

勾选订单后点击“批量修改属性”，可修改订单状态，或独立选择“不计入采购支出 / 恢复正常计入”；保持不变的属性不会修改。不属于公司的订单建议使用“不计入”，保留真实交易状态。恢复正常计入后，仍按订单状态统计：已完成、待发货、待收货才计入。列表新增“支出统计”列、“不计入”快捷筛选及更多筛选中的统计条件，详情和单笔编辑也能查看、设置。

表头仅选择当前页可编辑订单，“选择全部筛选结果”可跨页选择；改变筛选条件会清空选择。右键已选订单作用于所选记录，右键未选订单仅作用于该单。确认窗口显示数量、实付合计、计入采购净支出的变化。批量操作检查全部版本和月份锁定，任何一笔失败整批回滚，保留同批次的前后修改记录。已确认的月份必须先取消确认，锁定订单不显示编辑入口。

手动排除同步影响看板、有效采购、分类统计与月度报表；原订单、商品、金额、凭证及历史仍保留。订单导出和分类明细导出增加“支出统计设置”和“计入采购净支出”，便于区分原始金额与实际统计金额。排除标记不参与原文件去重，重复导入不会覆盖人工选择；升级旧订单默认按原状态正常统计。

## 订单图片（1.3）

全部订单的“显示图片”开关替代原“舒适行高”。开启后显示图片列及缩略图，关闭后恢复紧凑行高，浏览器会记住选择。按滚动位置加载当前可见订单，每单最多展示三张缩略图并注明图片数量；点击图片打开订单详情查看全部。无图片显示“暂无图片”，叠图提示待核对。切换保留当前筛选、排序、分页和勾选。

打开订单详情，会按保留的原始文件、工作表、商品行读取 XLSX 内嵌图片，以及 XLSX / CSV 明确图片列中的 HTTP / HTTPS 图片链接。补充原件同样支持，旧订单无需重新导入。使用 JSZip / Saxes 读取 OOXML 关系，并用 Sharp 校验格式和生成缩略图；兼容命名空间前缀和扩展名为 `.bin` 的实际图片。

- 网络图片首次查看时缓存到 `data/images`，以后优先使用本机副本；图片地址失效或网络异常会显示失败原因，可点“重试图片”。不登录电商平台、不访问商品详情链接搜图。
- 图片可点击放大，支持上一张、下一张和方向键；Esc 只关闭大图。原件未提供图片时明确提示，不生成替代图片。
- 同一来源行存在多张浮动图片时全部读取、按图片内容去重，标注“来自原表，待核对”，保留原表名称、工作表与行号。商品编辑后不能明确对应的图片显示为“原表图片”。
- 只增加独立的图片关联与缓存，不修改订单、金额、来源指纹或月度确认；锁定订单也可查看图片。无图片上传、替换或删除入口。
- 只接受公网 HTTP / HTTPS 图片地址，逐次验证域名及跳转，限制下载大小、时长和像素。单张图片最多 10 MB、4,000 万像素；不支持的格式提示失败。

## 拼多多表格导入

选择“拼多多”后上传订单表，已适配“订单ID、商品名、价格、实付、店名、用户名、收货人名、收货电话”等字段。价格按商品单价保留，采购金额只取整单实付，不按数量重复相乘。状态为“拼过几次”的记录，仅当同表明确为“已签收”且有不早于下单日期的有效收货时间时归为已完成，判断依据写入备注。退款成功、取消订单按关闭单列，不推算退款金额；缺少付款日期时按下单日期统计。使用表格导入，无浏览器采集模块。

## 闲鱼订单导入

闲鱼订单可在导入窗口选择“闲鱼”后上传，读取表内登录账号昵称、卖家、商品、时间及实付款。明确的合并收货信息自动拆分为姓名、手机和地址，原表缺少单价时保留为空。实付款已含运费，统计不重复加计；完整表格及内嵌图片保留在原件中。使用 ExcelJS 读取，遇到带 XML 命名空间前缀的兼容格式时由 [SheetJS](https://docs.sheetjs.com/docs/getting-started/installation/nodejs/) 读取。

## 补充淘宝原始数据

淘宝数据库导出表可以按订单号和采购账号与现有记录核对，验证日期、店铺、金额、状态及商品明细一致后，只补齐空缺的账号、付款日期和收货物流。原有订单编号、商品、金额、备注、首次导入原件均保留。订单详情中的“补充原始数据”可展开每条商品的完整原始字段、下载补充原件；导入记录会显示“补充 N 笔”。执行前创建完整备份，不因补充表缺单而删除系统订单。

维护命令：`node scripts/supplement-taobao.mjs <淘宝数据库导出.xlsx>` 只核对；添加 `--commit` 才备份并提交。出现账号归属不明或字段差异时停止提交，重复同一原件不重复补充。

## 金额口径

### 采购分类（第一期，1.1）

采购类别固定为 **商品采购**（`goods`）、**固定资产采购**（`fixed_asset`）、**日常支出**（`expense`）。采购平台表示购买来源，与类别分别保存。新订单默认商品采购；历史订单首次升级也统一初始化为商品采购，再手工修改例外。固定资产由使用者判断，不按商品名、金额或识别结果自动确认。耗材、软件服务、外包、员工福利等用途先写在备注。归属统一为公司共用，暂不显示归属编辑。

- 在全部订单中直接点击“采购类别”修改；也可右键快捷分类。勾选订单后批量修改，确认窗口显示数量和目标类别；混合订单会逐笔列出即将被替换的实付、退款分配。
- 表头复选框只选择当前页；“选择全部筛选结果，共 N 笔”才跨页全选。修改筛选会清空选择。右键已选订单操作全部已选记录，右键未选订单只操作该笔，菜单显示范围。任一版本冲突会整批回滚，刷新后重新选择。
- 一单多种用途时选择“拆分分类金额”。保留原订单、商品和金额，每类最多一行，填写两类或三类正数实付金额，合计必须等于整单实付。运费已含在实付中，不再加一次。也可在新增或编辑订单时选择“混合（拆分分类金额）”。
- 单一类别的退款自动跟随该类；混合订单退款手工分配，不能超过对应类别实付或整单退款。未分配部分单独提示，仍扣减总支出。改变实付或减少退款后，原拆分不符合规则则不能保存。
- 看板展示三类实付、已分配退款、净支出和待分配退款。核对关系：**三类净支出之和 − 待分配退款 = 整单实付之和 − 整单退款之和**。筛选某类别仅统计该类分配；待分配退款不能擅自扣到某个类别。订单行仍显示整单金额，并注明该类实付。
- “导出订单”保持一单一行，追加采购类别、分配内容和待分配退款；“导出分类明细”按分配输出，未筛选类别时另输出待分配退款的负净额调整行，便于汇总核对。订单页导出包含筛选内所有状态，明细有“计入看板”列；看板导出只含有效订单。CSV 的退款调整是可计算的负数。
- AI 识别采购单（图片、文字、直接填写）共享类别选择。识别不会覆盖手工选择的类别。改分类不改变导入去重指纹；相同原文件重新导入仍识别重复。旧版编辑请求未提交分类时保留原分类。
- 分类变更保留前后数据、时间、批次与订单版本。升级只新增分类列及审计批次，已有原件、订单金额、商品、历史均保留；重复启动不会重复初始化。上线前先用“数据与备份”创建完整 ZIP。

接口：`PATCH /api/orders/:id/classification` 提交 `{updatedAt, classification}`；`POST /api/orders/classification/batch` 提交 `{category, orders:[{id,updatedAt}]}`。单类结构为 `{mode:"single",category:"goods",owner:"company"}`；混合结构为 `{mode:"split",owner:"company",parts:[{category:"goods",amountCents:70000,refundCents:0},{category:"expense",amountCents:30000,refundCents:0}]}`，金额均为整数分。列表、详情、看板及导出支持 `category` 条件；`GET /api/classification-export` 导出分类明细。

### 后续实施顺序

1. **第二期：人力支出登记**。登记外部已经算好的工资、奖金／年终奖、社保等，按员工记录所属期间、支付日期、应付与已付金额；区分公司承担费用、员工个人代扣，避免公司成本重复计算。
2. **第三期：费用与报销**。补齐软件服务、项目外包、额外物流、打车餐饮等。员工垫付采购的报销单关联原采购；福利实物保留采购，人力汇总引用原记录。公司付款、报销、人力展示通过业务关联汇总，不能重复确认支出。
3. **第四期：库存、销售与利润**。同时提供资金结余与经营利润：商品付款计资金流水，利润只扣已售商品成本；未售部分留库存。固定资产购置记录付款，折旧规则另与会计确认。ERP 年费等保存服务期间，按期间归集。店铺佣金、店铺快递等直接归店铺；共用 ERP、云仓等暂留公司扣一次，不强制分摊。顺丰、云仓运单后续匹配销售订单和店铺，无法可靠匹配的留在公司。进货运费与销售发货费分开，可归属于商品采购的运输费用进入对应采购成本。项目外包为服务采购，按月／工时劳务单独登记，可在人力汇总展示并保留业务性质。

当前报表表示采购支出，不据此计算经营利润。人力归集、资产及跨期核算在后续接入时与会计核对。

- 有效采购：已完成、待发货、待收货。已关闭、待付款、待核对单列保留。
- 净采购 = 实付 − 已记录退款；运费已包含在实付中，不再次相加。
- 按付款月份统计时，没有付款日期的订单使用下单日期，看板提示数量。
- 源表没有退款金额时，0 表示尚无退款金额记录，不能推断从未退款。关闭订单不自动视为全额退款。
- “整单实付金额”模式，同一订单的多条商品行只记一次金额。“逐行金额”模式才逐行相加。
- 去重键是平台、账号、订单号。内容变化列为冲突，不静默覆盖。打开现有订单核对后编辑。
- 内部金额以整数分保存。订单编号保持文本，异常金额、日期、超长数值订单号会阻止导入。

## 数据位置与恢复

业务数据在 `data/purchases.sqlite`，原文件在 `data/originals`，采购单附件在 `data/attachments`，已缓存图片及缩略图在 `data/images`。本地识别模型存放在 Windows 用户级共享目录 `%LOCALAPPDATA%/PurchaseDesk/ocr-models`，不需要网络服务或 API 密钥。运行环境已使用系统 Node.js 24。

恢复完整备份前关闭服务：在任务管理器中结束对应灵兔采购台的 Node.js 进程（可根据 `logs/server.pid` 找到）；先另存整个 data 文件夹，再把备份 ZIP 内的 purchases.sqlite、originals、attachments 和 images（如有）放到一个空的 data 文件夹。不要在服务运行时覆盖数据库或把旧的 WAL/SHM 文件和恢复库混用。随后双击启动入口。

采购数据库和原件保存在这台电脑，桌面服务仅监听 127.0.0.1。1.4.0 新增可选的私有手机录入入口，通过 Tailscale Serve 连接；手机入口默认关闭，只有本机配对后的浏览器可以录入和查询。它不提供公网网站、云账本或离线同步，不自动登录电商平台。加密中继只转发密文。每次大批量导入后建议把备份另存到其他磁盘。

## 月度确认与管理员验证（1.2.3）

1. 在「数据与备份」设置管理员密码（8–128 位，无默认密码）。以后更改密码需要当前密码。
2. 打开「月度确认」，选择月份，按采购平台点击「核对订单」。月份固定按付款日期，缺失时使用下单日期，不受看板日期口径影响。
3. **每个月最早在次月 15 日 00:00（北京时间）才能确认锁定**，例如 2026 年 10 月须等到 2026 年 11 月 15 日。当月、未来月份以及尚未到次月 15 日的月份不能确认，空月份也遵守相同规则。页面显示可确认日期，未到时间时禁用「确认完成」；后台按本机服务器时间再次校验，客户端传入的日期或密码不能提前确认。跨过日期后可点击「刷新状态」。到期且核对完成后，检查笔数和实付／退款金额，勾选确认再锁定。覆盖该平台全部账号、全部分类和全部订单状态；确认预览过期时须重新打开核对。
4. 已确认数据只读，可继续查看、导出和备份。列表使用供应商名称旁的小锁图标标识，悬停可查看确认月份及取消确认说明，不额外增加一行文字或撑高行高。订单行和详情隐藏编辑、备注编辑及拆分入口，分类不能直接修改，右键不提供修改操作，批量选择只包含未锁定订单。
5. 需要修改时，先在「月度确认」找到对应月份与平台，点击「取消确认」，验证管理员密码后解除该范围锁定。返回订单页后恢复编辑。完成修改后重新核对并「确认完成」，系统不会自动重新确认。重新确认同样须等到次月 15 日；旧版已提前确认的记录继续保留锁定，取消时会提示最早重新确认日期。

取消操作或密码错误时保留锁定；过期的取消确认请求不能解除后来重新确认的月份。直接向订单编辑接口提交密码也不能绕过锁定。移动订单的付款月份、下单月份或平台时，同时检查原归属和新归属；涉及已确认范围须先取消确认。批量修改遇到版本冲突或锁定订单时整批回滚。导入仍先预览去重，原文件和人工分类不会因确认而被覆盖。原表补充脚本和数据库写入边界也受月锁约束。

「查看记录」保留确认、取消确认和重新确认的快照；订单详情保留具体改动前后值。旧版的单次授权修改记录继续保留，但不再提供单次授权修改。升级保留原有确认状态和管理员密码，不自动确认或取消任何月份。

表格导入会按付款月（缺失时按下单月）检查月锁。已确认平台月份的新订单在预览中显示订单号、归属月份和未导入原因，不能勾选；重复、冲突和无效订单也不会入库。其他未锁定月份可单独勾选并确认入库，完成后显示完整未导入清单（含未勾选订单及无法识别的源行），可从「导入中心 → 导入记录 → 查看清单」回查。锁定只针对已确认的平台月份，其他未确认的历史月份仍可导入。如果预览之后月份被锁定，或所选订单已由另一批导入，本批次整批不保存，页面更新预览并提示重新核对；不会悄悄改成部分入库。数据库事务失败时订单、导入记录和原文件一并回退。

密码通过 Node.js `scrypt` 加盐派生后保存；不存明文，不缓存在页面或本地浏览器存储。连续五次验证失败后暂停一分钟，重启不清除等待状态。完整备份同时包含月度确认、授权记录和密码哈希，恢复后使用备份时的密码。此功能是本机业务防误改，不替代操作系统的文件权限和用户管理。

确认列表和预览返回 `canConfirm`、`availableOn`、`availableAt` 及 `timeZone`。提前确认返回 `403 MONTH_CONFIRMATION_TOO_EARLY`，不会写入确认或审计记录。日期来自运行灵兔采购台的电脑，请保持系统时间正确。

接口：`GET /api/month-confirmations?month=YYYY-MM`、`GET /api/month-confirmations/preview?month=YYYY-MM&platform=平台`、`POST /api/month-confirmations`（月份、平台、预览版本）、`GET /api/month-confirmations/history`。取消确认使用 `POST /api/month-confirmations/cancel`，提交 `{month, platform, version, password}`，其中 `version` 取当前确认记录；版本冲突返回 `409 MONTH_CONFIRMATION_CHANGED`。`POST /api/admin/password` 用于设置／更改密码。受锁定写入统一返回 `423 MONTH_LOCKED`，旧的 `X-Purchase-Admin` 请求头不再提供修改授权。

### 一键解锁月度确认

在“设置 → 月度确认”勾选月份后点击“一键解锁”，核对需要解锁的平台，输入一次管理员密码即可批量取消确认。默认勾选所选月份的已锁定平台，提交前可取消无关项目。整批校验确认版本，任何一项失效或写入失败均不解锁；各项保留取消记录、原确认快照与统一批次编号。修改完成后重新确认对应月份。

### 勾选月份一键锁定与解锁

月度确认页顶部可切换年份、勾选多个月份，并使用“全选本年”或“清空选择”。所选范围可跨年保留。点击“一键锁定”后汇总月份、平台、订单数、金额和待核对数量，勾选确认后整批锁定；已锁定或未到确认时间的平台会明确提示跳过。点击“一键解锁”只列出所选月份中已锁定的平台，验证一次管理员密码后整批解锁。两种操作均保留统一批次和逐项历史，失败全部回滚。原来的单月逐平台确认功能继续保留。

### 上传日期与排序

订单的“上传日期”使用首次录入本机账本的创建时间，精确到秒，以北京时间显示，与下单日期、付款日期分开；后续编辑不会刷新此时间。历史记录直接使用已保存的创建时间，不推测原始文件最早上传时间。全部订单的排序下拉框支持上传日期最新或最早在前，也可点击上传日期列头切换排序；导出保留上传日期和当前排序。手机查询其他采购也提供上传日期排序，详情中可查看该时间。

物流公司填写与筛选使用固定下拉选项：申通、圆通、中通、百世、韵达、顺丰快递、京东快递和其他。旧名称打开编辑时映射为标准选项；极兔、德邦、邮政等选择其他。查询按规范类别匹配旧物流名称，历史原件和已锁定订单不批量改写。
