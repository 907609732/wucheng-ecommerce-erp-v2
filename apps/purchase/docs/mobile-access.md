# 手机私有访问

## 首次配置

1. 手机和电脑安装并登录 Tailscale，由本人启用多因素认证、设备审批和最小访问规则。
2. 启动灵兔采购台，电脑打开左侧“手机管理”（本机 `/phone`），检查连接状态。客户端窗口关闭不等于后台断开。
3. 运行 `tailscale serve --bg http://127.0.0.1:17869`，把输出的私有 HTTPS 根地址保存到管理页并开启。示例：`https://computer.example-tailnet.ts.net`。不要开启 Funnel。
4. 生成一次性二维码，手机连接 Tailscale 后用相机扫码，在系统浏览器自动配对；无法扫码时使用八位一次性配对码。
5. 可添加到手机主屏幕。电脑及采购服务必须在线；没有离线队列、云暂存和云账本。

二维码五分钟有效、仅可使用一次。重新生成、保存配置、关闭入口或重启后台使旧码作废。二维码与手输码互相替代；不要截图或转发。

## 日常使用

- 顶部单行入口：录入、查询、识别、字段、退出。
- 先选平台，再选供应商/店铺；多个联系地址可切换，与电脑共用资料。
- 必填项、地址和备注默认显示；其他字段按需开启，隐藏不会清除已有值。
- 商品一行一项，可横向滑动；物流和多个运单归属对应商品。
- 拍照、相册、PDF 或文字识别后人工核对，收到“已保存到电脑”才完成入账。
- 查询共用 PC 的筛选排序，25 个业务字段可全文或单独搜索；横向表格点击订单编号查看详情。
- “查询 → 上传历史”支持文件名、订单号、供应商、日期与类型筛选，查看已保存原单、导入文件、订单附件和本功能上线后接受的手机未入账上传。

点击顶部“查询”默认显示手机上传并保存的采购摘要列表，最近上传排在前面，每次30条，可加载更多。每条显示供应商、金额、商品摘要、上传日期与“详情 / 编辑”按钮，点击后才展示完整信息。没有手机上传记录时显示空列表，不混入电脑订单；电脑记录可在“查询其他采购”中查找。编辑旧单不会改变最近上传顺序。“查询其他采购”保留全部字段筛选。详情“编辑”带回原表单，已有附件保留，可追加新附件；取消编辑不提交，保存修改后返回该订单详情。

录入页面备注下方常驻“附件图片 / 文件”，支持拍照、相册与文件选择，可移除待保存文件，无需识别。确认保存时上传并随订单绑定；订单详情和上传历史可下载原件。每单最多20个附件，单个50MB、总计200MB。

上传与入账是不同状态。识别任务未入账原件暂存在内存，任务过期或后台重启后需重新上传。普通附件上传到本机临时区，只允许原手机会话绑定；未绑定文件沿用24小时孤立附件清理规则。只有订单事务成功后才显示保存成功，重试不重复入账。手机支持单笔采购编辑，沿用桌面订单校验、月度锁定、版本冲突检查与审计历史；不提供批量管理、备份和系统设置权限。

## 安全和撤销

桌面服务只监听 `127.0.0.1:17868`，独立手机服务监听 `127.0.0.1:17869`；Serve 只代理手机服务，不要公开桌面端口。自建 DERP 是可选项，不应存放采购账本、附件、网页代码或终端私钥。

独立手机会话使用 Secure / HttpOnly / SameSite=Strict Cookie，接口校验来源与 CSRF。二维码的 256 位随机临时凭据放在 URL fragment；页面先移除地址栏 fragment，再通过 HTTPS POST 兑换会话，服务器只保存临时凭据哈希。fragment 不随页面 HTTP 请求路径发送，也不是长期登录链接。五次错误配对暂停十分钟。

浏览器授权有效三十天。电脑可撤销单个授权；关闭入口撤销全部手机会话。手机丢失时还应在 Tailscale 控制台撤销设备。Tailnet Lock 由本人按官方指引启用并离线保管恢复材料，不存入仓库。

业务接口和原件下载需验证手机会话且禁止缓存，不注册离线 Service Worker。请求编号和订单同事务写入，断网重试不会重复入账。终端或账户本身被控制时，中继加密不能保证账本安全。

## 排查与验收

| 问题 | 处理 |
| --- | --- |
| 忘记打开 Tailscale | 电脑手机管理检测后台状态；按钮打开固定路径客户端，再从托盘登录或连接 |
| 已连接但网页打不开 | 检查 Serve、私有域名、设备访问规则、电脑睡眠与服务状态 |
| 配对失败 | 重新生成，核对有效期、是否使用及错误次数限制 |
| 上传慢或中断 | 保持页面打开，使用少量清晰图片；中继速度受带宽限制 |
| 保存结果不明确 | 保留原表单重试，以成功响应为准 |

管理页可见时每十五秒检测，主界面侧边栏每三十秒更新。断连时，手机不能通过电脑本机按钮远程启动软件。

配置在 `data/mobile-config.json`，缺失时默认关闭。会话、去重和上传元数据存于本机 SQLite，均不上传源码仓库。

升级前完整备份。真实手机分别验收同 Wi-Fi、移动网络、强制中继，完成拍照、识别、核对、保存、电脑查询与原件核对，并验证过期码、撤销会话、越权和离线重试。仓库不包含生产设备地址或替代这些操作的验收结论。

手机录入和编辑保存时，收货人、联系电话、收货地址及每个商品至少一条完整运单（运单号、物流公司）均为必填。收货与物流默认展开，字段设置不能将其隐藏；界面和手机后端均校验。历史数据不自动补写，编辑时需要补齐后保存。供应商联系地址保持选填。

## 录入人与数据来源

手机打开后先选择“五成”“陈奇”或“自定义”姓名，再进入采购表。顶部姓名按钮可以切换录入人；姓名是业务标记，访问权限仍由手机配对会话控制。每笔新采购保存当时的录入人，后续切换不会改写旧记录。

电脑列表、订单详情及 CSV 导出显示数据来源和录入人。来源区分表格导入（保留文件名）、电脑人工录入 / 上传、手机上传（有原单时显示文件名）。历史手机订单依据原提交记录识别；未记录的历史姓名显示“历史记录未设置”。原来源信息不随订单编辑改变。
