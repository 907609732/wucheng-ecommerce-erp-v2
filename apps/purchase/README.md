# 灵兔采购台

把 1688、淘宝、闲鱼、拼多多、微信和线下采购记在同一本本地账本中。支持电脑管理、手机私有录入、本地 OCR、供应商档案、月度核对与审计。

> 当前源码版本：1.8.0。业务数据保存在运行程序的电脑；GitHub 仓库只用于源码与文档同步，不是云账本，也不是手机网页托管入口。

## 安装与启动

推荐 Windows 10/11、Node.js 24 或更新版本。需要 PowerShell；中文 OCR 测试还需要 Windows 中文字体。Node.js、Git、Tailscale 等通用工具请按需安装到系统，依赖包通过项目锁文件安装。

```powershell
git clone https://github.com/907609732/lingtu-purchase-desk.git
cd lingtu-purchase-desk
npm.cmd ci
Copy-Item config.example.json config.json
```

私有仓库需要先在 GitHub 登录并取得访问权限。首次安装中文/英文识别模型，双击 `安装识别模型.cmd`，或运行：

```powershell
node scripts/install-models.mjs
```

随后双击 **启动灵兔采购台.cmd**，打开 <http://127.0.0.1:17868>。旧名称启动入口继续兼容。关闭网页不会停止后台或删除数据；电脑仍须保持开机和服务运行。

更新源码前先保存表单并在“设置”生成完整备份。更新后双击 **重启灵兔采购台.cmd**，再刷新页面。不要直接覆盖运行中的数据库。

## 日常操作

| 要做什么 | 入口与行为 |
| --- | --- |
| 看采购支出 | 采购支出看板：按平台、月份和类别汇总；实付包含运费，不重复相加 |
| 导入平台订单 | 任务中心 → 常用工具：选择平台、上传 XLSX/CSV、映射字段、预览核对后入账 |
| 录入采购单 | 任务中心 → 单据识别 / 直接填写：本地识别图片/PDF/文字，也可直接填写 |
| 查询订单 | 全部订单：组合筛选、排序、列设置、详情与按筛选结果导出 |
| 维护供应商 | 设置 → 供应商管理：产品、多个地址、多平台店铺、联系信息和资料历史 |
| 核对后防误改 | 月度确认：到期后核对、锁定；修改前验证管理员密码并取消确认 |
| 手机操作 | 左侧手机管理：检查 Tailscale、生成一次性二维码、管理授权浏览器 |
| 恢复误操作 | 订单日志：查看前后差异并按允许范围撤销；保留历史记录 |
| 完整备份 | 设置 → 数据备份：数据库、原件、附件、图片缓存与审计一起打包 |

录入默认显示采购平台、供应商、订单编号、下单日期、实付金额，以及收货与供应商地址、备注；其他字段可通过“显示字段 / 字段”开启。隐藏不会清除已有值。

商品逐行记录名称、规格、SKU、数量、单位、单价和多个运单；整单实付只记一次。供应商选择先按平台筛选，多个联系地址可在录入时切换。订单保存联系信息快照，后续修改供应商档案不会追改原订单。

## 数据规则

- 同一平台、采购账号和订单号去重。重复文件不会重复入账；内容变化进入核对，不覆盖人工修改。
- 默认只有已完成、待发货、待收货且未手动排除的订单计入有效支出；净支出为实付减已记录退款。
- 付款日期缺失时按下单日期归月，不根据订单状态推算退款金额。
- 月度确认按付款月和平台覆盖全部账号与类别，从次月 15 日北京时间 00:00 起允许确认。已锁定数据必须先取消确认。
- OCR 只是辅助填写。请核对供应商、商品、日期、状态和金额，看到“已保存”才算入账。
- 每单最多 20 个附件、单个 50 MB、合计 200 MB；识别最多 20 张图片/PDF 页。建议使用少量清晰原件。

## 手机访问

手机与电脑安装并登录 Tailscale。电脑“手机管理”配置 Serve 私有 HTTPS 地址；扫码可自动配对，二维码五分钟有效、仅能使用一次，重新生成即作废旧码。也可使用八位一次性配对码。

手机提供单行录入、字段设置、全字段查询、横向表格、上传历史和原件下载。查询默认展示最近一次手机保存的采购，支持单笔编辑，保留版本校验、月度锁定和审计历史。手机不提供批量管理、备份或系统设置权限。电脑离线时不可用，不提供离线提交或云端暂存。

无需自建中继也可先使用 Tailscale 默认直连/中继。不要开启 Funnel，不要把电脑端口直接公开到互联网。更多说明见[手机文档](docs/mobile-access.md)。

## 数据与备份位置

| 路径 | 用途 | 上传 GitHub |
| --- | --- | --- |
| `data/purchases.sqlite` | 订单、供应商档案、地址、审计与手机会话 | 否 |
| `data/originals/`、`data/attachments/` | 采购原件和订单附件 | 否 |
| `data/images/` | 本地图片缓存 | 否 |
| `data/backups/` | 完整备份 ZIP | 否 |
| `config.json` | 本机配置，参考 `config.example.json` | 否 |
| `logs/`、`.tmp/` | 运行日志与临时验证数据 | 否 |

识别模型位于系统用户的 `%LOCALAPPDATA%\PurchaseDesk\ocr-models`，不随源码上传。

恢复前先停止对应后台，并另存整个 `data` 目录。在空数据目录中解压备份里的 `purchases.sqlite`、`originals`、`attachments`、`images`；不要混入旧的 WAL/SHM 文件。恢复后的月度管理员密码和手机会话来自该备份，手机入口另行核对与配置。
