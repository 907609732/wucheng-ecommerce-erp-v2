## Delivered interfaces and package contract

- `createNativeBrowsers(config,{logger,signal})` returns `{start,stop,status}`. The `signal` is the supervisor's existing cancellation signal; cancellation interrupts browser acquisition and cleans partial launches. Internal `spawnProcess`, `probe` and timeout injection are used by isolated process-boundary tests.
- `nativeBrowserSpecs(config)` resolves the two fixed module IDs. Defaults: sales CDP 19222, VNC 19322, display 122; overview CDP 19223, VNC 19323, display 123. All network targets are literal `127.0.0.1`. Trusted configuration may set `native.browser.instances.{sales,overview}.{cdpPort,vncPort,display}` for isolated acceptance. Ports must be distinct integers 1024–65535, displays distinct 100–999; arbitrary host/URL/unknown instance properties are refused. Request input never selects an upstream.
- Package paths: `native.browser={enabled:true,runtimeRoot,chromiumPath,novncRoot}`, with `runtime/sysroot/usr/bin/{Xvfb,x11vnc,xauth}`, `runtime/chromium/chrome`, `runtime/novnc/vnc.html`. Private libraries are resolved from sysroot `usr/lib/x86_64-linux-gnu`, `lib/x86_64-linux-gnu`, `usr/lib`, `lib`. XKB data is `sysroot/usr/share/X11/xkb`; fonts are `sysroot/usr/share/fonts`, including `X11/misc`; optional font configuration comes from `sysroot/etc/fonts/conf.d`.
- The manager creates fresh 0700 generation scratch directories and Xauthority files, separate retained `<dataRoot>/browser-profiles/{sales,overview}`, authenticated Xvfb displays with TCP disabled, loopback CDP Chromium, and loopback-only IPv4 x11vnc. x11vnc uses LibVNCServer's native WebSocket support on its RFB port; there is no WebSocket-to-TCP or RFB implementation here. Clipboard remains enabled inside each private Xvfb for upstream noVNC password/OTP and Chinese paste workflows.
- Startup checks target conflicts, browser version, each child, display readiness, CDP `/json/version`, and actual x11vnc WebSocket upgrade within bounded waits. A missing payload, failed Chromium launch or unavailable sandbox fails startup; `--no-sandbox` is never supplied. No sandbox-bypass fallback is added.
- `status()` separates process readiness (`ready`, `state`, per-browser `ready`) from platform login (`unknown`, or `need-login` after safe profile separation). Logging out of Cainiao is not a startup failure. A newer imported profile, including a same-major patch version, is renamed to a retained sibling archive and a clean profile is opened; the newer profile is never downgraded in place. Unreadable/unparseable existing version metadata fails conservatively.
- Shutdown operates on direct child handles and, on Linux, only detached-session members carrying the private generation runtime directory. `/proc` start time and UID are rechecked before signaling members; no pidfile/process-name/broad `pkill` is used. Teardown is bounded and reports survivors rather than claiming success.
- Supervisor changes are limited to browser creation/cancellation and browser endpoint propagation. `startNativeCollector` now sets the selected trusted CDP endpoints before creating the actual adapters. Task 1 lifecycle/ownership/configuration locks were not changed.

## Gateway and UI

- Authenticated chooser: `/web/native-browser.html?module=sales|overview`; authenticated upstream assets: `/web/novnc/*`; authenticated upgrades: `/api/workbench/v1/native-browser/{sales,overview}/websockify`.
- The chooser embeds the package's upstream `vnc.html` and constructs the actual entry's public prefix, host, TLS setting and WebSocket path. It does not implement a VNC client. UI styling reuses the existing `--lt-*` tokens.
- New session feature metadata and the shell entry appear only when native browsers are enabled. Disabled configurations register no native browser resources or proxy routes. The shell tolerates an older cached DOM without the new optional navigation element.
- Each upgrade passes existing gateway identity/session resolution, requires a UI session and exactly one matching Origin, and accepts only the exact fixed path with no query or alternate destination. Gateway identity/session headers and cookies are not forwarded upstream.
- `@fastify/http-proxy` is pinned to 11.6.4 in root dependency/lock files and the release production whitelist. Inspected its installed official source and upstream documentation: its real upgrade listener dispatches Fastify's normal router/hooks, so authentication is enforced in `preHandler` before proxy upgrade. The FN Unix listener forwards the original upgrade request/socket/head after setting private WeakMap context and stripping the public prefix once. No private plugin symbol is fabricated and no caller-supplied transport header grants FN context.
- Both Cainiao adapters now point Linux users to the workbench's native login browsers instead of referring to a browser container.

Official sources checked: [Fastify HTTP proxy](https://github.com/fastify/fastify-http-proxy), [v11.6.4 release](https://github.com/fastify/fastify-http-proxy/releases/tag/v11.6.4), [LibVNCServer](https://github.com/LibVNC/libvncserver), [x11vnc options](https://github.com/LibVNC/x11vnc/blob/master/doc/OPTIONS.md).

## Remaining acceptance and integration concerns

- Tasks 3/4 must supply and execute real Linux payloads under the non-root package user, run the real Unix tests in Linux CI, verify sandbox effectiveness, actual CDP/Playwright navigation/snapshot/input/download, noVNC display/keyboard/Chinese clipboard, and clean process-tree shutdown. Local process tests use an injected spawn boundary and do not establish native GUI runtime correctness.
- x11vnc/LibVNCServer must be built with native WebSocket support; startup's real upgrade probe intentionally fails if it is missing. Package XKB/fonts and verify xkbcomp resolution: Debian Xvfb may use a compiled `/usr/bin/xkbcomp` path. This is a real-payload integration check, not fulfilled by a file-existence assertion.
- Imported credentials may need human login even when the profile is technically compatible. Controller research identifies old `jlesage/chromium` v26.10.1 Chromium `155.0.8059.84-r0`, with its browser profile at `/config/chromium`; all of `/config` may also contain NSS/keyrings and legacy Downloads. The controller must archive all `/config` before normalizing the profile into `browser-profiles`. Task 2 uses `--password-store=basic` and offers only best-effort compatible profile reuse; it cannot promise old-keyring decryption or retained Cainiao login. Newer profiles are retained intact with an explicit need-login status. Manual reauthentication, actual HOME/keyring and download mapping belong to Task 4 acceptance.
